> 性质：**只读审计**。未启动/停止服务，未调用 8080 / 8000，未修改任何代码；本文件是唯一产出。
> 范围：`backend/src/main/java/com/examprep/` 下 33 个控制器 / 210 个映射、`GlobalExceptionHandler`、`Result` / `ResultCode`、`SecurityConfig`、`TraceIdFilter`、3 个 Servlet 过滤器；对照 `docs/Agent阶段三接口契约.md` 与管理端 `static/admin/index.html`。

## 1. 结论（先看这段）

1. **`GET /api/me` 返回 500 的根因已定位**：`common/GlobalExceptionHandler.java:129-135` 的 `@ExceptionHandler(Exception.class)` 兜底把 `NoResourceFoundException`（Spring 6.1+ 资源处理器在"无映射/无静态资源"时抛出，本项目 Spring Boot 3.5.3）当成未预期异常，`setStatusIfHttpRange(resp, 500)` 写 500，并 `log.error` 打全栈。
2. **这不是单点 bug，而是一族**：`ExceptionHandlerExceptionResolver` 优先级最高，catch-all 会在 `ResponseStatusExceptionResolver` / `DefaultHandlerExceptionResolver` 之前截获**所有** Spring 内建 4xx 异常（404 / 405 / 406 …），全部变成 500。修 1 处即可覆盖最严重的 3 类。
3. **是否阻断框架验收：不阻断主线，阻断一条验收项**。RAG / Agent 主线与 `/me/stats`、`/me/mastery`、`/me/practice-trend` 均 200，210 个映射的正常路径不受影响；但"错误码收口"（执行记录 §8 第 5 条 / F-06）无法通过，且任何"无非预期 5xx"的冒烟门槛都会挂。
4. **证据缺口（必须先记一笔）**：任务输入的 `项目规划/第7周/evidence/smoke_nonmodel_20261107.json` **不存在**（该目录只有 `agent_smoke_20261107.json` 与启动日志）；`backend_start3_20261107.log` 中**搜不到** `NoResourceFound` / `/api/me`。即 500 目前只有执行记录表格里的口径，**无可复核的机器证据**。修复时请顺手补三条 curl 证据（见 §6）。

## 4. 修复建议（只写方案，不改代码）

### 4.1 P0 —— 一处改动覆盖 API-01 / 02 / 04

在 `GlobalExceptionHandler` 增加显式 handler（`@ExceptionHandler` 按"最具体类型"匹配，与书写顺序无关；**不要**在 catch-all 里 `instanceof` 判断，语义会含混）：

| 新增 handler | HTTP | body code | message | 日志级别 |
|---|---|---|---|---|
| `NoResourceFoundException` / `NoHandlerFoundException` | 404 | 404 | `"接口不存在：" + method + " " + path` | warn（不打全栈） |
| `HttpRequestMethodNotSupportedException` | 405 | 405（建议新增 `ResultCode.METHOD_NOT_ALLOWED(405,"请求方法不支持")`，并在响应头回填 `Allow`） | `"该接口不支持 " + method` | warn |
| `HttpMediaTypeNotAcceptableException` | 406 | 406（同上新增枚举） | `"不接受该 Accept 类型"` | warn |
| `ResponseStatusException` | 按其 `getStatusCode().value()` | 同值 | `getReason()` | warn |

实现要点：
- `NoResourceFoundException` 位于 `org.springframework.web.servlet.resource`，仅 Spring 6.1+/Boot 3.2+ 存在（本项目 3.5.3 可用）；不能改用 `ErrorResponseException` 一并覆盖——`ErrorResponse` 是接口、非 `Throwable`，`@ExceptionHandler` 只接受 `Throwable` 子类，必须按类逐个声明。
- 404 的 message **不要**复用"服务器内部错误"，否则客户端仍无法区分（这是本次 F-06 的验收点）。
- 与 `@ResponseStatus` 风格的 401/403 保持一致的写法即可，`setStatusIfHttpRange` 可继续复用（code 404/405/406 都在 400-599 区间会自动同步 HTTP）。

### 4.2 API-03 的统一映射（是否改 Security 规则）

- **推荐（A）**：不动 `SecurityConfig`，把规则写成文档："**鉴权先于路由**——未登录优先 401，登录后未匹配才 404"。理由：`/me/**` 属个人数据，移出 authenticated 会把 401 下沉到业务层，所有 `/me` 接口的 401 来源、限流、审计口径都会变，收益仅"匿名也看到 404"。
- **不推荐（B）**：把 `/me/**` 从 `AUTH_REQUIRED_GET` 拿掉、控制器内 `requireUserId()` 抛 401。改动面大、与既有测试（`AgentMemoryEndpointsTest.java:217` 期望 401）冲突。

### 4.3 API-05 二进制端点

`FileController` 的 404/403 分支改为抛 `BizException(ResultCode.NOT_FOUND, "…")` / `BizException(ResultCode.FORBIDDEN, "…")`，让它们回到统一契约；若因流式下载语义必须保留 `sendError`，则补一个最小 `ErrorController` 实现（读 `server.error.path`）返回 `Result.fail`。**这是唯一需要客户端配合的改动**：成功响应仍是二进制，错误响应变成 JSON，客户端需按 `Content-Type` 分支。

### 4.4 API-06 过滤器 JSON

`RateLimitFilter` 注入 `ObjectMapper`，用 `Result.fail(ResultCode.TOO_MANY_REQUESTS)` 序列化；`InternalTokenFilter` 同理（`Result.fail(ResultCode.FORBIDDEN, "内部接口未授权")`）。既得 traceId，又消除文案漂移。`InternalTokenFilterTest` 只断言状态码，不会冲突。

### 4.5 API-07 兼容策略（关键：**不要**一刀切）

- **不把 2001/3001 等业务码提为 HTTP 404**。硬依据：管理端 `static/admin/index.html:967-978` 的 `api()` 是 `401 特判 → resp.json() → json.code !== 200 判失败`，注释明确"调用方需要按 403/400 给不同文案时不必再猜 HTTP 状态"；App 侧同源。把业务码提为 HTTP 4xx 会让"业务提示文案"走 HTTP 错误分支，老客户端行为改变。
- 兼容做法：**维持两套语义但显式化**——HTTP 200 + 业务码 = 可预期业务结果；HTTP 4xx/5xx = 协议/鉴权/系统层错误。在 `docs/API.md` 增一节判读规则（含 2001/3001/4001/5xxx 的边界）。
- 收敛只在**新增接口**执行：新接口一律用 `ResultCode.NOT_FOUND(404)`，旧接口冻结不改。

### 4.6 API-08 `data` 键缺失（二选一，推荐 A）

- **A（零风险，推荐）**：文档对齐实现 —— `docs/API.md` 与 `Result` 类注释写明"null 字段不下发，错误响应为 `{code,message,traceId}`"。
- **B**：给 `Result.data` 加 `@JsonInclude(ALWAYS)`，错误体恒定含 `"data":null`。会改动全站 210 个映射的 JSON 形状（管理端不解析缺失键，风险低，但属框架冻结期的全局形状变更）。
- 本轮建议 A，B 记为"下一版本统一再改"。

### 4.7 P3 批量

415（API-09）改判并复用 `UNSUPPORTED_TYPE`；`DataIntegrityViolationException` 补 409 handler；API-11 在引入参数级约束时同批补 `HandlerMethodValidationException`；API-12 让 404/405/406 只 warn；API-13 二选一：`/me/practice-trend` 越界改 400（与 ops metrics 对齐），或文档显式写"clamp 到 1..90"。

## 5. 控制器响应体一致性抽查（3 个核心 + 2 个补充）
