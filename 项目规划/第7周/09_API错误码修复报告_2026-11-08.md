## 1. 修改点

| # | 异常 | HTTP | body `code` | message | 日志 |
|---|---|---|---|---|---|
| 1 | `NoResourceFoundException`（Spring 6.1+ 资源处理器，`GET /api/me` 落此） | **404** | 404 | `接口不存在：GET /api/me` | warn，无堆栈 |
| 2 | `NoHandlerFoundException` | 404 | 404 | `接口不存在：<method> <url>` | warn |
| 3 | `HttpRequestMethodNotSupportedException` | 405 | 405 | `该接口不支持 GET 请求`；响应头回填 `Allow` | warn |
| 4 | `HttpMediaTypeNotAcceptableException` | 406 | 406 | `不接受该 Accept 类型，请使用 application/json` | warn |
| 5 | `ResponseStatusException` | 按其 `getStatusCode()` | 同 status | `getReason()`（空则“请求处理失败”） | warn |
| 6 | `Exception` 兜底（**保留**） | 500 | 500 | `服务器内部错误` | **error + 完整堆栈** |

> 406 特殊处理：客户端在 Accept 层就拒绝 JSON，若直接返回 `Result`，错误体二次协商仍会失败导致 **body 为空**（实测已复现，`ExceptionHandlerExceptionResolver` 报 "No acceptable representation"）。故在该 handler 内 `resp.setContentType("application/json")` 预设 Content-Type，让统一错误体照常写出。实测后 body 为 `{code:406,message:…,traceId:…}`。

- `@ExceptionHandler` 按“最具体类型”匹配，新增 handler 自动优先于 `Exception` 兜底；未在兜底里做 `instanceof` 判断。
- 响应体结构不变：仍返回 `Result`，即 `{code, message, data, traceId}`（`data=null` 时因 `non_null` 策略省略，属既有口径 API-08，未改）。
- 404/405/406 复用既有 `setStatusIfHttpRange` 同步 HTTP 状态；`ResponseStatusException` 直接写入其自身 status。
- 405/406 的 body code 使用 `HttpStatus.METHOD_NOT_ALLOWED/NOT_ACCEPTABLE.value()`（未改 `ResultCode`，避免越界改动）。

## 4. 验收 curl 计划（主 agent 启动 8080 后执行）

前提：`Authorization: Bearer <有效令牌>`（404 用例需登录态；匿名 `GET /api/me` 仍由 Security 先判 401，属既有“鉴权先于路由”约定，本次不改）。

| 编号 | 命令 | 期望 HTTP / body.code | 断言要点 |
|---|---|---|---|
| 404 | `curl -i -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8080/api/me` | 404 / 404 | message 含“接口不存在”；`X-Trace-Id` == body `traceId` |
| 405 | `curl -i -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8080/api/practice/start` | 405 / 405 | 响应头含 `Allow: POST` |
| 406 | `curl -i -H "Accept: text/html" http://127.0.0.1:8080/api/ai/capability` | 406 / 406 | 公开接口，无需令牌；`Content-Type: application/json`；body.message 含“Accept 类型” |
| 500 | 见下注 | 500 / 500 | 仅此场景出现 ERROR 全栈 |

> 500 负向验证：在**不启动/不改代码**前提下无法用普通请求稳定触发。两种可选做法——
> (A) 等价证据：`mvn -B -Dtest=GlobalExceptionHandlerTest#unexpectedExceptionIs500 test`（已通过）；
> (B) 真机验证：临时停 MySQL 后 `curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8080/api/me/stats`，验完立即恢复；此时应 500/500 且日志仅此一条带堆栈。

补充回归（应保持原行为）：`GET /api/me/stats`、`/api/me/mastery` → 200/200；`GET /api/me/practice-trend?days=abc` → 400/400；`GET /api/questions/999999` → 200/2001（业务码口径不变）。
