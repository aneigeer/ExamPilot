### 2.1 代码改动（子 agent + 主 agent追加）

### 2.2 为什么追加 0.60

live 复测发现：Agent 工具已正确返回 0 页，但 Agent 最终走 Java 完整 RAG 兜底时，Wiki **热层**（阈值 0.55）仍把 0.572 的跨学科页（Prompting）当答案返回——「函数专题」被答成 Prompting。

实测标定（2026-11-08，`wiki-search` 七个查询）：

| 类型 | 页面分数 |
|---|---|
| 跨学科误命中 | Prompting **0.5720**、DeepSpeed **0.5624** |
| 相关页最低 | 进程/线程 **0.8400**、数据库索引 **0.6996**、数组/指针 **0.6984** |

0.60 落在空隙内，两处配置同步修改，`WikiQueryServiceTest` / `AiConfigConsistencyTest` / 新增用例共 **18/18** 通过。

### 2.3 live 复测（2026-11-08 18:03，8080 PID 28584 / 8000 PID 12400）

|---|---|

**F-10 关闭**：不再出现「refused=false 却回答未找到」或「跨学科页直接当答案」。

- `HybridRetrieverTest.refusalRateOnProductionPath` 是**在线守卫**：向量通道就绪才断言，离线自动跳过。AI 服务在线时它真跑，当前 **6/10**（低于 ≥9/10 断言）；离线时跳过。故 Java「350 全绿」是**离线口径**，与第7周既有测试纪律一致。
