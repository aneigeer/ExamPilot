## 0. 结论摘要

1. **0.58 是三档里唯一「零新增域外漏拒 + 域内误拒降到 10%」的点**（在唯一一条干净窗口上）。稳健收益是 s09（0.5932），边缘收益是 s14（0.5829，距新线仅 0.0029）。
2. **0.55 不建议**：它会先放行 r05（0.5606）、r10（0.5564），拒答准确率 81.8% → 63.6%；且 0.55 恰好等于 `min-vector-score`，会破坏 `τ > 接受线` 的护栏（`AiConfigConsistencyTest` 会失败）。
3. **最大的证据缺口不是阈值本身**：当前只有 30 条窗口是在 0.60 口径下测的；100 条（25.0%）与 214 条（31.0%）的误拒数字都是 **0.62 口径**。因此「0.60 下全量 203 条的误拒率」目前**没有实测值**，不能据 30 条直接外推到全量。
4. **阈值不是误拒的主因**。203 条里仍有 12.8%（26 条）的域内问题走 `FULLTEXT_OR`（向量 0 候选），语义闸门对它们根本不触发——降阈值救不了这些。真正的瓶颈仍是 query rewrite / embedding / 索引覆盖。

### 1.2 三个必须纠正/标注的点

**(1) 0.62→0.60 的 26.7%→16.7% 不能全部记在阈值头上。**
s26「前序中序后序遍历分别怎么走？」余弦 **0.5798**（`start3:2474`），低于 0.60，却在 0.60 下被正常回答（30 条报告 HIT rank 1），且 0.60 运行日志中**没有 s26 的语义拒答行**。这说明它是被「字面通道有证据则跳过语义拒答」那条新逻辑放行的，而不是被阈值放行的。
推论：如果只改阈值、不带 lexical bypass，0.60 拿不到 16.7%。任何阈值实验必须在**同一构建**（含 bypass）下对比，否则数字不可比。

**(2) 100 条 25.0% / 214 条 31.0% 是 0.62 口径，不能当作 0.60 的基线。**
时间线：`221419`（22:14:19）→ `221733`（22:17:33）→ build2（22:23:12）→ `start2` 运行打印 `top1 余弦 0.5932 < 0.62`（22:24）→ build3（22:26:13）→ `start3` 打印 `< 0.6`（22:26:43）→ `222659`（22:26:59）。
因此 22:26 之前的两个报告应视为 0.62 口径（除非存在未记录的重启）。**「0.60 下 203 条误拒降到多少」从未被测量过。**

**(3) 30 条窗口是被挑过的好窗口。**
`s01–s30` 全是 C 语言 / 数据结构，余弦集中在 0.52–0.88；`g` 类（国考行测）一条都没有。而 214 条里 26 条（12.8%）域内问题走 `FULLTEXT_OR`（向量 0 候选），语义闸门对其不生效。用 30 条选阈值，存在明显的样本偏差。

## 2. 闸门机制（决策前提）

一次检索链路上实际有 3 道拒答条件，语义线只是其中一道：

| 闸门 | 位置 | 触发条件 | 参数 | 受本次阈值影响 |
|---|---|---|---|---|
| 分数闸门 | `RetrievalService` | `best < reject-threshold` | 0.15 | 否 |
| 覆盖度闸门 | `RetrievalService` | `bestCoverage < min-content-coverage` | 0.45 | 否 |
| 越界词 | `RetrievalService` | 命中能力边界词 | 词表 | 否 |
| **语义闸门** | `HybridRetriever` | `applyGate ∧ vectorEnabled ∧ ¬lexicalEvidence ∧ vectorBest>0 ∧ vectorBest<τ` | **τ=0.60** | **是** |

两个关键行为（都已在代码中确认）：

1. ngram 侧拒答 **不会** 让最终结果拒答——只要向量通道有候选，`contexts` 仍会合并返回（`HybridRetriever.java:128-175`）。所以 s05 的 coverage 0.17、s09/s27 的 0.43 都只是「字面通道没证据」，并不额外阻塞。
2. 因此 s05/s09/s14/s23/s27 这 5 条**只受语义线约束**，降 τ 能直接放行，不受覆盖度影响。

## 4. 推荐阈值：**0.58（有条件采纳），默认回退 0.60**

### 4.1 理由

1. **在唯一干净窗口上严格占优**：域内误拒 16.7% → 10.0%（−6.7pp），拒答准确率不变（81.8%），无新增漏拒。
2. **离域外最高分还有 0.0194 的余量**：11 条负例全覆盖复核（A 级），r05 0.5606 < 0.58 仍被拒。这是三档中「唯一既改善域内、又不破坏现有拒答能力」的点。
3. **不与设计不变量冲突**：0.58 > `min-vector-score` 0.55，`AiConfigConsistencyTest` 仍可通过；0.55 则直接失败。
4. **可逆、成本极低**：纯配置项，回退一条配置即可。

### 4.2 必须承认的弱点

- 收益不厚：稳健收益只有 s09 一条；s14 距新线仅 0.0029，语料/模型任何微小漂移都会把它推回拒答。
- 余量变薄：域外安全余量从 0.0394 降到 0.0194。`application.yml` 已注明语料会扩容（11300 → 11999 → 12900），**每次扩语料都必须重标**，0.58 更经不起漂移。
- 对全量帮助有限：203 条误拒即便按乐观外推也只有 ~17%，离 ≤10% 的 F-02 目标仍有距离。阈值不是主瓶颈。

### 4.3 采纳/回退判定

```text
IF 214 条 0.60 基线已跑通（无降级、无 ERROR）
   AND 落盘 per-case 余弦后重放 0.58 满足：
       ① 203 条误拒 ≤ 10%（或至少 ≤ 0.60 基线 − 5pp）
       ② 11 条域外全部仍被拒（或 ≥ 9/11 且不新增漏拒）
       ③ 没有任何域外样本余弦 ≥ 0.58
   THEN 上线 0.58
ELSE 保持 0.60，并把「阈值已到边界，改 query rewrite / embedding」写回执行记录
```

任何一条不满足 → **保持 0.60**。不建议用 30 条窗口的 10.0% 直接上线。

## 6. 补测清单

### 6.1 工具/指标（不改业务代码）

1. `retrieval_eval.py` 的报告行补 4 个字段：`vector_best`（语义闸门实际用的过滤后 top1）、`lexical_best_score`、`content_coverage`、`refuse_reason`；`write_report` 的列清单同步加上（当前 HTML 只有 rank/mode，`gate_refused` 被丢掉了）。
2. 区分「raw 调用」与「gated 调用」两条记录分别落盘（现在同一 question 会打出两条拒答日志：ngram 侧 + 语义侧，极易误读——s05 的 cov 0.17 与 cos 0.5644 就是两条不同来源）。
3. 增加降级检测：统计日志中「向量通道不可用」与「语义闸门使用过滤后 top1」行数，非 0 则该轮不计入标定。
4. 输出按 subject / 题型 / 召回模式分组的误拒率，便于定位 g 类的 `FULLTEXT_OR` 群体。

### 6.2 样本

| 类别 | 现有 | 建议补 | 目的 |
|---|---|---|---|
| 域外负例 | 11 条 | +20 条，余弦目标带 0.50–0.62 | 压测 0.58 的 0.0194 余量；现有负例太"远"，区分力不足 |
| 近邻负例 | 0 | +10 条（学科相邻但语料没有：Python 爬虫、英语作文模板、考研院校分数线） | 检验"实体在语料但无答案"与"真域外"的边界 |
| 域内 hard case | 5 条（s05/s09/s14/s23/s27） | +20 条同 chunk 的口语化改写 | 量化"表述不像"型误拒，供 query rewrite 对比 |
| 模态缺口样本 | 26 条 `FULLTEXT_OR` | 逐条记录其向量余弦（若为 0 需查明是通道问题还是语料问题） | 区分"向量没召回"与"向量召回了但不像" |
| 标注复核 | — | r02、r09 人工终判 | r02 cov 0.75 + cos 0.8066，语料确有内容；r09 字面 0.67 |

### 6.3 指标

- 三档混淆矩阵：域内误拒 / 域外漏拒 / 正确放行 / 正确拒答。
- EOD（误拒率 = 漏拒率）交点，作为"可解释最优点"的备选证据（仅作参考，不替代业务约束）。
- 域内最低余弦（剔除 bypass 样本）与域外最高余弦，二者中点为理论上界。
- 引用支持：阈值放松后需复用第 6 周三级口径（存在 / 相关 / 支持），防止"答了但引用不支持"。

## 7. 全量 214 条重标的执行顺序与验收判据

### 7.1 顺序（严格按依赖执行）

| 步骤 | 动作 | 产出 | 门禁（不满足不进入下一步） |
|---|---|---|---|
| 0 | 冻结输入：语料块数、embedding 模型版本、Qdrant 快照、`golden_set.jsonl` 哈希 | 一页"标定基线快照" | 缺任一项 → 结果不可复现，停止 |
| 1 | 稳定性前置（F-01）：watchdog + 每 ≤100 次检索重启 8000；先跑 300 次探针 | 探针日志 | 出现崩溃或「向量通道不可用」→ 先修稳定性，不标定 |
| 2 | 评测脚本补字段（6.1 的 1–3） | 新版报告模板 | 报告必须含 `vector_best` / `refuse_reason` |
| 3 | **基线跑 0.60**（全 214，单次 raw+单次 gated，落盘每案余弦），连跑 2 遍 | 基线报告 ×2 | 两遍误拒数差 ≤1；0 条 ERROR；0 条降级 |
| 4 | **离线重放 0.58 / 0.55**（只改判定式，不重复调服务） | 三档混淆矩阵 | 判定式必须与 `HybridRetriever:160-173` 完全一致（含 `lexicalHasEvidence`） |
| 5 | 边界人工复核：取余弦落在 [0.55, 0.62] 的全部样本逐条判"该答/该拒" | 人工判读表 | 边界样本判读完成率 100% |
| 6 | 定档 → 改 `application.yml` + `AiProperties` 默认值 + 注释块（246–252 行） | 配置 diff | `mvn test -Dtest=AiConfigConsistencyTest` 通过 |
| 7 | 回归：30 条窗口 + 11 条负例（快速通道） | 回归报告 | 见 7.2 |
| 8 | 归档：报告、判定式、日志片段、决策结论写入第 7 周执行记录 | evidence | 结论里必须写明测量口径（τ、语料版本、用例数） |

> 注意：步骤 1 必须在步骤 3 之前。214 条 = 428 次检索，已超过 22:26 那次崩溃的规模（~300 次）；不先做分段重启，末段数据会混入 ngram 降级（现有 214 报告已注明"末段可能混入降级"）。

### 7.2 验收判据（建议直接作为 gate）

| # | 指标 | 判据 | 口径 |
|---|---|---|---|
| A1 | 域内误拒率 | ≤ 10%（203 条），且 ≤ 0.60 基线 − 5pp | 只统计语义闸门拒答 |
| A2 | 拒答准确率 | ≥ 9/11（81.8%），**不得低于 0.60 基线** | 新增漏拒 = 0 为硬线 |
| A3 | 域外安全余量 | `τ − max(域外余弦) ≥ 0.015` | 现 0.58 为 0.0194，勉强达标 |
| A4 | 域内边界余量 | 非 bypass 的域内最低余弦 `≥ τ − 0.005` | 即最多容忍 0.005 的边缘误杀 |
| A5 | 数据完整性 | 0 条 ERROR、0 条降级、embedding 版本与步骤 0 一致 | 否则整轮作废 |
| A6 | 可复现性 | 两遍独立运行误拒数差 ≤ 1，且边界样本判定一致 | 抖动 >1 说明服务不稳 |
| A7 | 配置一致性 | yml 生效值 = 代码默认值 > `min-vector-score` | 单测护栏 |
| A8 | 回归 | 30 条窗口误拒 ≤ 10%；11 条负例拒答 ≥ 9 | 快速通道，分钟级 |
| A9 | 归因可解释 | 每条被放行的样本都能给出「余弦 ≥ τ」或「lexical bypass」理由 | 报告需逐条列出 |

任一不满足 → 保持 0.60，并在执行记录里写明「阈值已到边际，转向 query rewrite / embedding / 索引覆盖」。
