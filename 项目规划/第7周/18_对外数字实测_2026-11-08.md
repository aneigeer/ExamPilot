## 2. C-01 后端接口数

**命令（运行时，优先口径）**

```powershell
$r = Invoke-WebRequest "http://127.0.0.1:8080/api/v3/api-docs" -UseBasicParsing
$j = $r.Content | ConvertFrom-Json
$j.paths.PSObject.Properties.Name.Count          # → 189
# 每个 path 内的 HTTP 方法计数（get/post/put/delete/patch）
```

**结果**

- HTTP 200，响应 254,633 字节。
- `paths` = **189**；按方法求和 = **210**：`get=110`、`post=74`、`put=15`、`delete=11`、`patch=0`。
- `paths` 中含 `internal`（`/internal/agent/**`、`/internal/wiki/**`、`/internal/jobs/**`）= **14** 条、14 个 operation。
- ⇒ **对外 196 个**（210 − 14），对外路径 **175 条**（189 − 14）。

**静态交叉验证（同一口径必须能对上）**

| 注解 | 数量 |
|---|---|
| `@GetMapping` | 110 |
| `@PostMapping` | 74 |
| `@PutMapping` | 15 |
| `@DeleteMapping` | 11 |
| `@PatchMapping` | 0 |
| **方法级合计** | **210** |
| `@RequestMapping`（类级前缀） | 17 |

- 方法与数量逐项与 api-docs 一致 ⇒ **210 是真实 operation 数，不是「注解下界」**（07 号报告的 210 也被证实，只是当时无法排除「一个注解多路径」的误差，实测已排除：210 = 210）。
- 189 < 210 的原因：**同一路径挂了多个方法**（如 `/questions` 同时有 GET 与 POST），路径数与接口数不是一回事。

**量法说明**：三个层次必须声明——类级前缀 17 处 / 路径 189 条 / 方法级 operation 210 个。对外说「接口数」应取**方法级**。

**推荐口径**：**对外 196 个**（并注明全量 210 含 14 个 internal；路径 189）。
作废：`197`（README §一）、`195`、`192`、`176`、`154`。其中 154 是 README §九「按控制器实测分布」表可见行之和，漏掉 `AiOpsController`(16)、`AgentInternalController`(11)、`Wiki*`(19)、`AiInterview`(4)、`Courseware`(3)、`Me`(12)、`AiAgent`(3) 等后加模块，属**表内自洽、全量失真**。

**仍待测**：196/210 是否还需再剔除 actuator、静态资源、`/v3/api-docs` 自身（当前 api-docs 未包含 actuator 端点，故此项影响≈0）；对外「196」是否要按「学生端可用 / 管理端可用」再分组。

## 7. C-06 题库总量

```sql

SELECT audit_status, is_deleted, COUNT(*) FROM question GROUP BY 1,2;
SELECT SUM(parent_id=0), SUM(parent_id<>0),
       SUM(parent_id=0 AND is_deleted=0),
       SUM(parent_id=0 AND is_deleted=0 AND audit_status='APPROVED') FROM question;
```

**结果**

| 口径 | 数量 | 含义 |
|---|---|---|
| 总行数 | **3,085** | 含 2 条软删（`is_deleted=1`） |
| 有效（未软删） | **3,083** | README「有效 3,083」的来源 |

| 已通过（`audit_status='APPROVED'`，且 `parent_id=0`） | **2,500** | 学生端 `/questions` 的 `total`（只查 APPROVED） |

- 状态分布：`APPROVED,0 = 2,500`；`PENDING,0 = 583`；`PENDING,1 = 2`。
- 差额拆解：`3,083 − 3,080 = 3` 是 **3 道子题**（`parent_id <> 0`）；`3,085 − 3,083 = 2` 是软删。
- 口径陷阱：题干说「按 status 字段」——`question` 表**没有 `status` 列**，审核状态列名为 **`audit_status`**（`PENDING/APPROVED/REJECTED/OFFLINE/APPEALING`）。

**推荐口径（两个维度必须分开说，但只有一个主数字）**：
对外 **「题库 3,080 道，其中已通过 2,500 道可作答」**；
需要技术口径时括注「表内 3,085 行（含 2 条软删 + 3 道子题），有效 3,083」。
作废：单独引用 `3,085`（未剔除软删/子题）、把 `2,500` 当「题库总量」、`3,092 chunk`（是块数不是题数）。

**仍待测**：3,080 是否应把 3 道子题并入母题计数（产品口径，非技术问题）；`REJECTED/OFFLINE` 当前为 0，若日后出现需再分层。
