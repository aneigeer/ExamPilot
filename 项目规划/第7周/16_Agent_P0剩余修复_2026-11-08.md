## 2. 修复点

### 2.1 T02 参数 Schema（`tools.py`）

新增 `ArgumentError` 与 `_validate_arguments(name, args)`：

- `search_knowledge` / `search_wiki`：`query` 必须是非空字符串；
- `get_wiki_page`：`pageId` 必须是正整数；
- `get_question`：`questionId` 必须是正整数；
- 可选数值参数（`topK`/`limit`）仍由 `_clamp_int` 显式 clamp：
  - `topK=99 → 10`
  - `limit=-1 → 1`

`ToolRegistry.execute` 在进入任何 Java 调用前先校验；非法参数返回
`ToolResult(ok=False, summary="参数错误：…")`，不拼路径、不泄漏 ValueError。

### 2.2 T03-A 单次工具超时（`harness.py`）

工具执行改为：

```python
result = await asyncio.wait_for(
    self.tools.execute(decision.tool, decision.arguments, ctx),
    timeout=max(0.01, self.settings.tool_timeout_seconds),
)
```

超时返回 `ok=False, summary="工具调用超时（>X s）"`；`tool_result` 仍照常发出，会话继续。

### 2.3 T03-B 会话级 deadline（`config.py` + `harness.py`）

- `AgentSettings` 新增 `session_timeout_seconds: float = 120.0`；
- `llm_timeout_seconds` 默认 30→**15**，使 `6 步 × 15s = 90s < Java SSE 120s`；
- `load_settings` 新增 `AGENT_SESSION_TIMEOUT_SECONDS`（默认 120）；
- `AgentHarness.run` 用 `asyncio.timeout(session_timeout_seconds - 0.05)` 包住单 Agent 循环；
  超时后发 `final`（`degraded=true`、`degradedReason="session deadline 截止"`）和 `done`；
- 50ms 余量用于吸收调度开销，保证外部观测总耗时不越过配置值。

> 测试适配：T03-B 用例构造 `AgentSettings(..., session_timeout_seconds=1.2)`，把 deadline 显式设为 1.2s；断言未改。

### 2.4 T05 重复调用去重（`harness.py`）

在 `_agent_loop` 内维护 `seen_tool_calls`：

```python
call_signature = json.dumps([decision.tool, decision.arguments], sort_keys=True, default=str)
if call_signature in seen_tool_calls:
    yield thought("重复调用已跳过：相同工具与参数不再执行、不重复扣预算")
    continue
```

第二次相同调用不执行、不扣预算、不访问 Java；第一次结果仍在 observations 中。

### 2.5 T06 审计日志（`harness.py`）

每次工具执行后记录：

```text
[AgentAudit] trace_id=... user_id=... step=... tool=... ok=... elapsed_ms=... error_code=... arg_keys=...
```

- 成功 `error_code=OK`；参数错误 `PARAM_ERROR`；超时 `TOOL_TIMEOUT`；其它 `TOOL_ERROR`；
- 只记 `arg_keys`，不记参数值/正文，避免泄漏敏感内容；
- 日志 logger 为 `app.agent.harness`，可被 `app.agent` 的 caplog 捕获。
