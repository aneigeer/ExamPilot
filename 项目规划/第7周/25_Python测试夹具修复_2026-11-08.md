# Python 测试夹具修复（W3b）

- 日期：2026-11-08
- 范围：`ai-service/tests/` 测试夹具，**未修改任何生产代码**（`harness.py` / `subagent.py` 等一字未动）
- 仓库：`d:\大学生多考试备考知识库与题库系统`

## 1. 根因

`ai-service/app/agent/harness.py` 的 T05 去重（原文件 L334-L350）：相同 `tool + arguments`
签名只执行一次，第二次起走 `continue`，**既不产生 tool_call/tool_result，也不扣工具预算**。

三个失败用例的规划器每一步都返回完全相同的参数：

- `tests/test_subagent.py`：`_TOOL_DECISION` 固定为
  `search_knowledge{query:"C语言 int", topK:5}`，且 `plan_script=[_TOOL_DECISION] * 20`；
- `tests/test_phase2_acceptance.py`：`_GreedyPlanner.plan()` 固定返回 `{"query": "x"}`。

因此第 2 步起被去重跳过，循环耗尽步数后只剩 1 次工具调用（子问题模式下每个子问题各
1 次，3 个子问题共 3 次）。断言本身正确（预算上限必须生效），失败原因是夹具未模拟
"每次调用参数不同"的真实场景。**不是生产逻辑违背设计意图**，故未改生产代码与断言。

## 2. 改动点（最小 diff）

### `ai-service/tests/test_subagent.py`

- L57-L70 新增 `_tool_decisions(count)`：生成 `count` 条互不相同的工具决策
  （`query` 带递增序号，如 `C语言 int 第1次` … `第20次`），注释说明去重与预算的关系。
- L236：`test_tool_budget_is_shared_across_sub_questions` 的
  `plan_script=[_TOOL_DECISION] * 20` → `plan_script=_tool_decisions(20)`。
- L369：`test_degrade_restores_full_tool_budget` 的
  `plan_script=[_TOOL_DECISION] * 20` → `plan_script=_tool_decisions(20)`。
- 其余用例（步数预算、硬上限、单次回退等）仍使用 `_TOOL_DECISION`，未改动；断言零改动。

### `ai-service/tests/test_phase2_acceptance.py`

- L295-L304：`_GreedyPlanner.plan()` 的 `arguments={"query": "x"}` →
  `arguments={"query": f"x-{len(observations)}"}`，仍保持"永远想调工具"的语义，
  且每步参数唯一。断言（`max_tool_calls=2` → 2 次 `tool_result` + `final`/`done`）零改动。

## 3. 语义逐条复核（真实事件证据）

用测试夹具直接跑一次并打印事件（非断言，仅取证）：

1. 预算共享（3 子问题 / 全局 4 次 / 6 步）：
   `tool_call=4`、`final.tool_calls=4`、`steps=4`，4 次 query 依次为
   `第1次…第4次`；thought 出现
   `[subagent] 预算已耗尽（工具 0 次 / 步数 2 步），跳过剩余 1 个子问题`。
   即前两个子问题各消耗 2 次、第三个被跳过，全局恰好 4 次。
2. 回退路径（拆解失败 `no key`）：`tool_call=4`、`final.tool_calls=4`、
   `degraded=True`、`degradedReason=拆解调用失败：no key`，4 次 query 均不同，
   证明回退后单 Agent 仍能用满 4 次工具预算。
3. 失控循环（`max_tool_calls=2`）：`tool_result=2`，query 为 `x-0`、`x-1`，
   thought 出现 `工具调用已达上限，直接进入最终回答`，事件尾部为 `final`、`done`。
