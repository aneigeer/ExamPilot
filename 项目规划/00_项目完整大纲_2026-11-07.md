## 1. 项目目标、范围与验收原则

### 1.1 产品目标

面向大学生的多学科备考平台，核心闭环：

- **题库练习**：题目、选项、答案、解析、错题、收藏、模考；
- **AI 答疑**：优先 RAG 检索增强，答案附可点击来源；无可靠证据时明确拒答；
- **知识库检索**：导入、切分、索引、检索、来源展示、版本更新、失败重试；
- **Agent**：工具白名单、Schema、超时、最大步数、执行日志；
- **管理端**：题库/知识库导入、审核、失败记录、调用监控、基础权限；
- **运维**：健康检查、日志、备份恢复、限流降级、发布回滚。

**交付定义**：可验证、可试点、可回滚。微调模型是可选优化项，不是首发阻塞项；未经评测的微调模型不进入默认生产路由。

### 1.2 系统组成

| 层 | 组件 | 职责 |
|---|---|---|
| 客户端 | Android 学生端 | 刷题、解析、AI 答疑、知识库、面试、学习计划 |
| 客户端 | Web 管理端 | 题库/知识库导入、审核、监控、权限 |
| 业务后端 | Spring Boot 3.5.3 / JDK 21 | 用户、权限、题库、学习记录、业务事务、客户端 API |
| AI 服务 | FastAPI + Uvicorn | RAG、Agent、OCR、模型路由、推理调用 |
| 数据 | MySQL 8 / Redis | 业务数据权威源 / 缓存、会话、限流 |
| 向量 | Qdrant / 本地文件模式 | 知识块向量检索 |
| 模型 | Ollama 本地 + 在线 API | 本地 Qwen 系列；在线 GLM 等；五层降级 |
| 网关 | Nginx | HTTP/HTTPS、反向代理、限流 |

### 1.3 两条工作线

| 工作线 | 周次 | 目标 | 当前状态 |
|---|---|---|---|
| 训练微调线 | 第1–6周 | 数据治理 → 训练稳定 → 正式训练 → 导出 → 公平评测 → 上线决策 | 第6周已结项（结论 No-Go） |
| 系统质量线 | 第7–10周 | RAG/Agent 质量 → 端到端联调 → 安全/性能/运维 → 试点发布 | 第7周进行中（框架线）；第8–10周未开始 |

> 注意：系统侧在 2026-10 已有大量工程资产（见 §4.3），但**没有按第 7–10 周计划做正式验收**，不能把“代码存在”等同于“本周完成”。

### 1.4 验收原则（本项目固定）

1. **数据先冻结**：任何重建都改 sha，必须停训练、后改数据、同步 `data_pins.txt`；
2. **同档比较**：基线与微调必须同量化档、同模板、同解码参数；
3. **独立验收**：执行者与验收者必须是不同 agent，PARTIAL 不得写成 PASS；
4. **证据落盘**：日志、JSON、SHA、样本清单缺一不可；
5. **GPU/Ollama 由主 agent 执行**：子 agent 只出方案与脚本，避免与训练抢资源；
6. **不达标不上线**：安全项不允许用软指标抵消。

#### 3.2.2 F2 根因

不是“选块 bug”，而是“没有可用语料”：

- `chunks[i % 9746]` 在 `i < 3044` 时恒等于 `chunks[i]`，题目与块各自打乱后按同序号随机挂接；
- `pick_definition` 命中率 **0/158**，全部落到 `clip(content,120)` + `…`；
- final 的 user 消息 **一条【资料】都没有**（0/158），却输出 `[1]。`，等于直接教模型“凭空引用”。

#### 3.2.3 F2 修复

- 改为材料驱动合成任务：user 给 `【资料】[1] 标题：正文`，assistant 出 `{"action":"final","answer":"…[1]。"}`；
- 第一次实现：资料截 120 字、答案用完整正文 200 字 → 答案比资料长的 200/250；
- 修复后：答案中位 94 / 资料中位 95，答案比资料长的 **0 条**；
- `answer ⊆ material`：子串口径 **250/250**；全集子串 **533/533**；去 `[1]。` 后逐字相等 525/533（8 条差 1–2 字）。
