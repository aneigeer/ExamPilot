# Agent 教学化改造记录（2026-11-13 夜）

> 目标：让站内 Agent 从「几十字的短结论」变成「能讲明白、能带学生做题」的助教。
> 约束：只用本地千问 3B（`qwen2.5-3b-instruct-q8_0-baseline`），不接在线模型。

---

## 1. 诊断：四个真实根因

改造前实测（同一批问题）：RAG 类问题只有 36 字、TCP 类 77 字，多数走抽取式降级。

| # | 根因 | 证据 |
|---|---|---|
| 1 | **定稿根本没重写**：`/internal/agent/answer` 在拿到 contexts 时，直接用规划器草稿 `draft` 做 L3 校验并返回，`generator` 固定写 `agent-llm` | `AgentInternalController.java:225` |
| 2 | **系统提示词禁止展开**：原文要求「每句必须标来源」「资料不足只输出「未找到相关资料」六个字」 | `AiProperties.Prompt.systemTemplate` |
| 3 | **提示词超上下文**：3B 窗口 4096 token，实测一次请求 8543 token → Ollama 400 拒绝 → 熔断降级抽取式 | 日志 `request (8543 tokens) exceeds the available context size (4096 tokens)` |
| 4 | **抽取式兜底倒原文**：把「题干：…解析：…标签：…」整段当答案，学生看到的是资料内字段 | RAG 问题输出 1628 字原文 |

---

## 2. 改动

### 2.1 定稿改为「基于资料重写」

`AgentInternalController.answer`：contexts 非空时先调 `aiQaService.answerWithContexts(question, contexts)`
（带引用约束的完整 RAG 生成 + L3 校验），生成失败或判为拒答才退回草稿。

- 收益：回答从「规划器一句话」变成「基于资料的教学式讲解」
- 代价：多一次 LLM 调用，实测总耗时 6–12 秒

### 2.2 系统提示词改成教学结构

```
1) 一句话结论
2) 分点讲解 2–4 点（先是什么，再为什么/怎么用）
3) 易错点或记忆提示
4) 最后一行「依据：[n]」
```
并附一条格式示例（数据库索引），3B 对示例的服从度明显高于纯规则。
同时把「资料不足就整体拒答」改为「先答覆盖部分，再写『资料未覆盖：X』」。

### 2.3 提示词预算（修 400 报错）

`PromptBuilder.userPrompt` 增加双层截断：单块 700 字、总预算 3600 字，按相关度降序取块，超出整体放弃并打日志。

### 2.4 抽取式兜底清洗

`ExtractiveAnswerClient.normalizeSentence / cleanFallback`：丢弃「题干/解析/标签/原文出处/参考答案」等字段行、Markdown 标题与纯链接，最多 240 字；全部被过滤时给「资料中没有可直接引用的答案，建议查看来源原文核对」，不再倒原文。

### 2.5 学习建议类问题给可执行答案

`harness._structured_answer`：计划/错题/薄弱点为空时，不再回「0 题 / 0 道」，改为具体动作
（如「先做 10 道题热身，约 15 分钟，做完我再根据错题安排下一步」）。

### 2.6 规划器提示词补两条

`planner.SYSTEM_PROMPT` 新增：
- 学习建议类必须先调 `get_weak_knowledge / get_wrong_book / get_study_plan`，禁止空话；
- 概念题检索结果明显无关时直接拒答，不用常识补答。

## 4. 仍然存在的限制（不粉饰）

1. **3B 的讲解深度有限**：能给结构、能把资料复述清楚，但抽象概括和例子质量明显弱于大模型。
2. **引用是「挂了号」不等于「有依据」**：L3 只校验编号在范围内、正文与资料有字面重合；像「四级阅读提分」这种资料覆盖弱的问题，模型会给通用建议并挂引用，需要人工抽查。
3. **多一次生成带来延迟**：概念题 6–12 秒；学习建议类仍走规则路径（2–3 秒），不额外调模型。
4. **超长资料仍会被截断**：单块 700 字、总 3600 字是硬上限，超长材料只能覆盖前几块。

## 7. 多轮与细节修复（23:20–23:40）

### 7.1 指代消解（真 bug）

**现象**：先问「什么是 RAG」，再问「它和微调有什么区别」，回答变成一篇《Harness Engineering》——完全跑题。

**根因**：检索用的是原始问题，「它」没有指向，命中了一篇无关 Wiki 页。

**修复**：`harness._resolve_arguments`：当问题含「它/这个/那题/继续」等指代词，
且 `search_knowledge / search_wiki` 时，用上一轮问题补全检索语句（只补检索词，不进最终答案）。
复测同一组对话：第二轮正确落在「RAG vs 微调」，`degraded=false`，10.9 秒。

### 7.2 空话清理

7B 会机械照抄提示词，在结尾输出「资料未覆盖：无」。
`AgentInternalController` 在返回前用正则删除「资料未覆盖：无/没有/暂无」这类空行，并压缩多余空行。

### 7.3 一个需要如实说明的发现

同一题「RAG 和微调的区别」：

- 线上第一次回答把 RAG 说成「训练时引入数据」（**事实错误**）；
- 用正确的两段资料直接测同一个模型，回答完全正确（RAG 不改参数、微调更新参数）。

结论：**错误来自检索到的语料质量，不是模型知识**。语料是抓取的面试笔记，存在少量表述不严谨的块；
L3 只能校验「有没有引用、引用编号是否越界」，无法校验「引用内容本身是否说错」。
要根治需要做语料清洗或换更强模型，不在本轮范围。
