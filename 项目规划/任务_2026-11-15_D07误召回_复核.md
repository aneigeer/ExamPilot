## 3. 判据③：「调高阈值会先误伤 Q1/Q4」—— **FAIL（量纲错位，结论方向对但依据不成立）**

### 3.1 报告的说法
`任务_2026-11-15_D07误召回根因分析.md:17、:108`：「真缺陷那 2 条 0.60–0.61，而神经网络 0.688、大熊猫 0.596 —— 调高阈值会先把域内题误伤」「`reject-threshold` 0.15 → 0.65：先误伤 Q1（0.688）、Q4（0.596 会被拒）」。

### 3.2 代码事实：0.688 与 0.65 不是同一个量
- `reject-threshold` 比的对象是 `best`，而 `best` **不是** `/v1/search` 返回的余弦：
  - `HybridRetriever.java:139` `double best = contexts.isEmpty() ? 0.0 : contexts.get(0).finalScore();`
  - `AiQaService.java:187-189` `double best = outcome.bestScore(); if (… || best < threshold || …)` → 比的确实是 `finalScore`
- `finalScore` 的构造：`VectorChunkMerger.java:128、142-146`
  - 向量块 `ftNorm = ctx.ftScore()`，而 `VectorChannel.java:229-230` 已把余弦归一化：`(score - floor) / (ceiling - floor)`，配置 `score-floor: -1.0`、`score-ceiling: 1.0`（`application.yml:375-376`）
  - ⇒ **`ftNorm = (cos + 1) / 2`**
  - `finalScore = ftNorm×1.0 + titleHit×0.30 + kpBoost×0.25 + fresh×0.15 + hotNorm×0.10`，双通道再 `+0.25`
  - ⇒ **`finalScore ≥ ftNorm` 恒成立**（其余因子非负）
- 换算后四条的实际 `best` 下界：
  | 题 | 报告用的余弦 | 真实 `ftNorm`=(cos+1)/2 | 下界是否 >0.65 |
  |---|---:|---:|---|
  | Q1 神经网络 | 0.6879 | **0.8440** | 是 |
  | Q2 量子力学 | 0.6115 | **0.8058** | 是 |
  | Q3 区块链 | 0.6010 | **0.8005** | 是 |
  | Q4 大熊猫 | 0.5960 | **0.7980** | 是 |

## 4. 判据④：「6/8 = 75%」的算术与口径 —— **PARTIAL**

- **算术**：`6/8 = 0.75` ✓；`10 − 2 = 8` ✓；`refused=6` 与 D07 的 `refusedCount=6`、行 i=1/3/4/5/6/10 ✓ 一致。
- **口径问题 1（不成立的部分）——剔除依据被数据证伪**：报告的剔除理由是「语料确有内容/答案 ⇒ 属域内正例」（`:58、:89`）。但同一把尺子用在被它自己判为「拒答正确」的题上会立刻崩：
  ```

                                              '%馒头%'    → 14
                                              '%护照%'    → 23
                                              '%天气%'    → 634
  ```

  红烧肉在语料里**确有内容**，却仍被报告算作「该拒且拒对了」。**⇒「语料里有答案」既不是域内的充分条件，也不是必要条件**，用它剔除 Q4 属于循环论证（行测材料包罗万象，这一点 `RetrievalService.java:222` 的注释自己都写着）。

- **口径问题 3（顺序自相矛盾）**：报告主张「**先**重标评测集」（`:18、:111`），但 §3 已经**先行执行了剔除**并给出 75% 的结论。要么重标是待批动作（那 75% 就只能写成"若剔除后"的推演），要么剔除已生效（那就不必再建议重标）。
- **唯一站得住的剔除是 Q1**：语料有成套**教学材料**（课件第 1/19 页 + 面试题 + 可调超参数段落），且 D07 的回答用语（优化算法/超参数/迭代）能在 9791 里找到依据 —— 这是「备考知识库确有此主题」，与「语料偶有一句提到」性质不同。
- **Q4 只能说「需要产品口径裁定」**，不能说「依据充分」：2608 是**言语理解填空题**，答案碰巧包含事实；它是否属于「备考知识库承诺范围」是产品范围问题（行测常识算不算），不是「语料有没有」的问题。**这一点必须在重标时用范围定义写死，否则同样的争议会在「红烧肉」「护照」上重演。**

- **「先重标评测集」——同意，但理由要换。** 成立的依据只有 Q1（语料有成套教学材料，D07 答得也有出处）；Q4 只能算「待产品范围裁定」。而真正让重标变紧急的，是 D07 这 10 条**混装了三种东西**：真域外（天气/火车/护照/菜谱/发面）、形式域外但语料有料的（大熊猫/神经网络）、语料只字面相近的（量子力学/区块链）。三条证据：语料里同时存在「红烧肉」「馒头」「护照」「天气」（计数 1/14/23/634）却都被正确拒 —— 说明**当前"该拒/该答"的分界靠的是关键词与覆盖度，不是范围定义**，这确实是评测集要先写死的东西。
- **「因此暂不调阈值」——不同意作为结论。** （a）报告支撑它的算数是错的（判据③，量纲错位）；（b）它把「阈值无效」当成了「没有代码问题」，而 `HybridRetriever.java:160-166` 的旁路是**实打实的缺陷**；（c）正确顺序是 **① 修 `lexicalHasEvidence` 旁路 + ② 重标评测集并写死范围定义 + ③ 固定条件重跑取真实基线 → ④ 再谈阈值**。修旁路不依赖重标，且成本低于重标。
