> 结论先行：**主线走「本地 8GB + max_length 640 + 7B QLoRA」**——1 epoch 约 **2.3 小时**（135 步 × 60 s，
> 区间 1.4–2.7 h），边际费用 0，训练数据不出本机，失败可原地续跑。

- 数据：`sft_train_behavior.jsonl` 2,156 条、4.35 MB、全部 ≤ 640 token（见第 2 周 02 报告）
- 已知实测：`max_length=640` → 显存 **7.8/8.2 GB**；`max_length=768` → OOM

## 1. 先对齐口径：步数到底是多少

`sft_train_behavior.jsonl` = 2,156 条，`per_device_train_batch_size=1`，因此

| `gradient_accumulation_steps` | 每 epoch 优化步数 | 每步覆盖样本 |
|---|---:|---:|
| 8（任务书口径） | **270** | 8 |
| 16（`train_qlora.py:145` 当前代码值） | **135** | 16 |

**这两个值不矛盾，但会让人把时间算错一倍**：单步耗时与 accum 成正比。
总时长应按下式算，而不是「步数 × 固定秒数」：

```
T_epoch ≈ N_samples × (s_step / accum) = 2156 × 单样本秒数
```

三种组合（60 s/step 为实测；36 s/step 取自 `full_train.log` 100 步均值，作乐观界）：

| 假设 | 135 步 × 60s（**当前代码**，accum=16） | 270 步 × 60s（accum=8，若单步耗时不变） | 135 步 × 36s（乐观界） |
|---|---:|---:|---:|
| 1 epoch 耗时 | **2 h 15 m** | 4 h 30 m | 1 h 21 m |

> **以 2 h 15 m 为准**：当前 `训练v3续跑.bat` 自己写着「50 步预计 50 分钟」，即 60 s/step 是
> **accum=16** 下测出来的，1 epoch = 135 步 × 60 s ≈ 2.25 h。
> 若把 accum 改成 8，步数翻倍到 270，但每步只跑 8 个 micro-batch、单步耗时约减半，**总时长仍 ≈2.25 h**。
> 规划区间取 **1.4–2.7 h**（36–60 s/step）；开跑后看前 10 步的实际 `s/step` 即可收敛。
> 另注：当前 `训练v3续跑.bat` 用 `--max-steps 50` 只跑 50 步（≈800 样本，**0.37 epoch**），
> 不是 1 epoch，**不要把它当成全量耗时**。

## 2. 三条路线对比

### 2.0 总表

| 维度 | ① 本地 8GB（7B @640） | ② 云 GPU（A10 24G / 4090 24G） | ③ 更小模型（3B / 1.5B） |
|---|---|---|---|
| **预计耗时（1 epoch）** | **1.4–2.7 h（典型 2.3 h）** | A10 **1.3–2.1 h**；4090 **0.8–1.6 h**（均含 0.4–0.8 h 装环境/下模型） | 3B @1024：**0.7–1.4 h**；1.5B @2048：**0.5–0.9 h** |
| **费用** | **¥0**（电费 ≈0.25 kWh ≈ ¥0.2） | **$0.6–1.1 / 次**（A10）；**$0.4–0.8 / 次**（4090），按 $0.5/h 假设 | ¥0（本地跑）；若上云约为 ② 的 1/2–1/3 |
| **可复现性** | 高：同机、同驱动、同 torch/CUDA，种子固定即逐字节可复现 | 中：镜像/CUDA/driver 版本漂移会改变数值；需固定 image digest | 中：换基座=换基线，**与 7B 的历史分数不可比** |
| **数据安全** | **最好**：数据不出本机 | 需上传 4.35 MB 训练集（可脱敏/加密）；权重只下载不外传；用完销毁实例 | 同 ①（本地） |
| **失败可恢复性** | 高：`save_steps=10` + `save_total_limit=2`，最多丢 10 步；可直接 `--resume` | 中：需把 checkpoint 挂到网络卷；竞价实例可能被抢占 | 高（同 ①），但**评测要全部重做** |

### 2.1 本地 8GB

- 显存余量只有 **0.4 GB**（7.8/8.2），**任何长度上调（768）都会 OOM**；这是硬约束，不是调参能绕过的。
- 期间机器基本被独占：CPU 侧还有 tokenize/DataLoader（`num_workers` 默认 0，影响小），但 GPU 占用 95%+，
  **不适合同时开浏览器/IDE 编译/视频会议**；夜里跑最合适。
- 失败模式主要是 WDDM 共享内存回退：不报 OOM，但步速会突然掉 5–10 倍（见 §3.1）。
- 可复现性最好，也最容易对照上一轮（同机同环境）。

### 2.2 云 GPU

| 项 | 估算 | 说明 |
|---|---|---|
| A10 24 GB | $0.3–0.6 /h（按 $0.5/h 假设） | 显存 3×，可开到 1024，token 吞吐约 4060 Laptop 的 2–2.5× |
| RTX 4090 24 GB | $0.4–0.7 /h | 吞吐约 3.5–4×，1 epoch 约 0.4–0.8 h |
| 数据传输 | 上行 **4.35 MB**（秒级）；下行 15 GB 模型权重（3–10 分钟，依带宽） | 权重不必上传，云上直接拉 |
| 一次性总价 | **$0.4–1.1 / 次**（含装环境 0.5 h） | 按月跑 4 次 ≈ $2–4 |
| 合规 | **需评估**：题库/课程资料若来自第三方，外传存在版权与数据合规风险 | 建议境内云 + 加密传输 + 用完销毁磁盘 |

> 云上真正的收益不是钱，是**时间**：把 4.5 h 压到 1 h，且 24 GB 显存可以不再被 640 卡脖子（可试 1024）。

### 2.3 更小模型（3B / 1.5B）

| 模型 | 8GB 上可行长度 | 1 epoch 估计 | 效果预期 | 重训/验证成本 |
|---|---|---|---|---|
| Qwen2.5-3B | 1024（QLoRA，约 6.5–7.5 GB） | 0.7–1.4 h | 行测准确率通常比 7B 低 5–10 pp；格式/引用/拒答这类「行为」任务损失较小 | 需重建 baseline、全部评测重跑，历史分数作废 |
| Qwen2.5-1.5B | 2048（约 6–7 GB） | 0.5–0.9 h | 能力缺口更大，复杂资料题明显掉分 | 同上，且要重新做能力下限评估 |

**判断**：小模型解决的是「长度」问题，不是「质量」问题；本项目当前瓶颈是**数据质量（F1/F2）与评测口径**，
不是上下文长度。换基座会让「v3 vs v4」所有对比失去基准，**本期不做**。

## 3. 推荐

**主线：① 本地 640，夜里跑 1 epoch（约 2.3 h），全程挂看门狗（§4）。**

理由（按权重排序）：
1. **零成本、零外传**：数据合规风险为 0，费用可忽略；
2. **已知可行**：640 已实测 7.8/8.2 GB 跑通，不需要重新调参；
3. **可复现**：同机同环境，和上一轮数字可比；
4. 2.3 h 属于「睡前启动、半夜就能收」的量级，不构成瓶颈。

**触发切换的条件**（满足任一条再考虑 ②/③）：

| 条件 | 切换动作 |
|---|---|
| 需要在 1.5 h 内拿到结果，且本地排队 | 用 ② A10 跑一次（约 $1），固定镜像 digest、挂网络卷 |
| 连续两次本地 OOM 或步速掉到 >120 s/step | 用 ② 4090（24 GB 可试 1024），并把 640 的结论作为对照 |
| 本地显存必须降到 <7 GB（要同时做别的事） | 用 ③ 3B，但必须**同时重建 baseline 并重跑全部评测** |
| 训练目标是长文档（>1024 token） | 只能 ② 或 ③；① 的 640 会截掉答案（见第 2 周报告：512 档 323 条答案整段丢失） |

## 4. 停止条件（可由脚本判断）

> 统一原则：**任何一条触发即停止并保留 checkpoint**；先停再查，不要「再等几步看看」。

| # | 指标 | 阈值 | 检测方式（可脚本化） | 处置动作 |
|---|---|---|---|---|
| 1 | 显存占用 | dedicated ≥ **98%** 连续 3 次（90 s） | `nvidia-smi --query-gpu=memory.used,memory.total --format=csv,noheader,nounits` 每 30 s | 立即停；降 `max_length`（不降 accum）或换 ② |
| 2 | 显存余量 | `free < 256 MB` 连续 3 次 | `torch.cuda.mem_get_info()` 在训练回调里打印（或 `nvidia-smi` 差值） | 同上 |
| 3 | OOM | 日志出现 `CUDA out of memory` / `OutOfMemoryError` | 日志 grep（大小写不敏感） | 立即停；记录 `max_memory_allocated` |
| 4 | 共享内存回退（Windows/WDDM） | 步速 > 基线 **5×** 且显存 ≥ 95% | `Get-Counter '\GPU Adapter Memory(*)\Shared Usage'`（Win10 1803+）；或步速突增 + dedicated 打满 | 视为隐式 OOM：停，重启并释放显存（关掉占卡进程） |
| 5 | 步速 | 连续 **5 步**均值 > **120 s**（基线 60 s 的 2×），或单步 > **300 s** | 解析日志 `it/s` / `s/it`，或 `step_end` 时间戳差分 | 停；检查是否共享内存回退、是否被其他进程抢卡 |
| 6 | loss NaN/Inf | 出现即停 | `logging_steps=5` 的 loss 字段，`math.isnan/isinf` | 立即停；降 lr（3e-4 → 1e-4）后重启，检查数据是否有空答案 |
| 7 | loss 平台 | 连续 **30 步**最低 loss 无改善，且末 10 步均值比最低点高 **>5%** | 滑动窗口 | 停并保存；判定过拟合/发散，回退到最佳 checkpoint |
| 8 | 数据加载 | `len(train_dataset) == 0`；或 DataLoader 抛异常 | 训练前断言 + 日志 grep `Traceback` | 立即停；校验 pins（`training/verify_pins.py`） |
| 9 | token 超限比例 | > **5%** 样本被截断 | 训练前用第 2 周脚本统计 `n_tokens > max_length` 的占比（当前 **0%**） | 停；先压缩数据或抬 `max_length`，不要带截断训练 |
| 10 | 进程存活 | PID 消失且未生成 `adapter_model.safetensors` / 日志无 `train_runtime` | `tasklist /FI "PID eq <pid>"` + 检查产物文件 | 判为失败；按最后 checkpoint 续跑 |
| 11 | 日志停滞 | PID 存在但日志 **15 分钟**无新增 | 日志 mtime | 判为挂起；`py-spy dump --pid <pid>` 采样后停止 |

### 4.1 Windows 下的“共享内存回退”怎么判断（重点）

WDDM 驱动在显存不足时**不会抛 OOM**，而是把溢出部分放进「共享 GPU 内存」（系统内存），表现为：

- `nvidia-smi` 的 dedicated 显示接近上限（如 7.9/8.2 GB），但**步速突然变成原来的 5–10 倍**；
- 任务管理器「性能 → GPU」里 `Shared GPU memory` 明显非 0（>0.5 GB 即可疑）；
- 此时继续跑不报错，但一轮训练可能从 4.5 h 变成 20 h+。

判定脚本（PowerShell，只读）：

```powershell
# 每 30s 采样一次，连续 3 次 dedicated ≥98% 或 shared >0.5GB 就报警
while ($true) {
  $gpu = nvidia-smi --query-gpu=memory.used,memory.total --format=csv,noheader,nounits
  $used, $total = $gpu -split ','
  $pct = [math]::Round(100 * [int]$used / [int]$total, 1)
  $shared = (Get-Counter '\GPU Adapter Memory(*)\Shared Usage' -ErrorAction SilentlyContinue).CounterSamples |
            Measure-Object -Property CookedValue -Sum
  Write-Output ("{0}  used={1}MB ({2}%)  shared={3}MB" -f (Get-Date -Format HH:mm:ss), $used, $pct, [math]::Round($shared.Sum/1MB,0))
  if ($pct -ge 98) { Write-Output "STOP: dedicated >=98%"; break }
  if ($shared.Sum/1MB -gt 512) { Write-Output "STOP: WDDM shared memory fallback"; break }
  Start-Sleep -Seconds 30
}
```

### 4.2 步速看门狗（读日志，不干扰训练）

```powershell
# 训练日志里 HF Trainer 会写 " 12/135 [02:15<23:04,  9.02s/it]"；连续 5 步 >120s 即停
$log = "training\output\qwen2.5-7b-exam-lora-v3b\trainer_log.txt"
$slow = 0
Get-Content $log -Wait -Tail 0 | ForEach-Object {
  if ($_ -match '([\d.]+)s/it') {
    $s = [double]$Matches[1]
    if ($s -gt 120) { $slow++ } else { $slow = 0 }
    if ($slow -ge 5) { Write-Output "STOP: 连续 5 步 >120s/step"; break }
  }
}
```

> 注意：Windows 下训练通常用 `>> log 2>&1` 重定向，`-Wait -Tail 0` 可实时跟；若日志被 buffered，
> 用 `python -u` 关闭缓冲。

## 5. 每次训练的执行清单

**开跑前**
1. `training/verify_pins.py` 必须全绿（数据 sha 与 pins 一致）；
2. 跑第 2 周的长度脚本确认 `n_tokens > max_length` 占比 = 0%；
3. 确认没有别的进程占卡：`nvidia-smi` dedicated < 1 GB；
4. `--save-steps 10`、`--max-steps` 设为本轮预算（全量为 135 步）。

**运行中**（§4 的 1/5/6/10 四条必须先挂）
- 30 s 采样显存、5 步窗口看步速、每 5 步看 loss、15 min 看日志 mtime。

**结束后**
- 产物三件套：`adapter_model.safetensors`、`adapter_config.json`、`train_metrics.json`（steps 与 mtime 必须对得上）；
- 记录：实际 `s/step`、`max_memory_allocated`、总时长、是否有共享内存回退。

## 6. 限制与待确认

- 云价格按 **$0.5/h** 统一假设（A10/4090 公开区间大致 $0.3–0.7/h），实际以下单时报价为准；
  跨境数据传输另有合规成本，未计入。
- 吞吐倍率（A10 2–2.5×、4090 3.5–4×）是按显存带宽与算力推算，**未实测**；上云前建议先跑 10 步标定。
- 3B/1.5B 的「效果预期损失 5–10 pp」是经验值，非本项目实测，切换前必须做小样本对照。
- `gradient_accumulation_steps` 代码是 16、任务书写 8，**开跑前请确认用哪个**（影响步数与日志对账，
  但不影响总时长，见 §1）。
