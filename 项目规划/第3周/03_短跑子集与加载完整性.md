## 2. 训练加载路径（代码确认）

`training/train_qlora.py`：

1. `render()`：`tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=False)` → 存入 `text` 字段（与 build/compress 同一模板，无 generation prompt）。
2. `SFTTrainer` + `SFTConfig(dataset_text_field="text", max_length=640)`（启动脚本 `训练v3续跑.bat` 传 `--max-length 640`）。
3. TRL **1.17.1** 的 `_collate_language_modeling`（site-packages/trl/trainer/sft_trainer.py:379-391）对 text 分支调用：

```python
self.processor(text=texts, padding=True, padding_side="right",
               truncation=self.max_length is not None,
               max_length=self.max_length,
               add_special_tokens=False)
```

即：**同一 chat template + `add_special_tokens=False` + 右侧截断到 640**，不会额外加 BOS/EOS；`SFTConfig.packing` 默认 `False`，训练脚本未开启，不存在跨样本拼接后再截断的情况。压缩脚本 `compress_for_training.py` 用的也是 `apply_chat_template(tokenize=False) → tokenizer(text, add_special_tokens=False)`，两条路径完全同源。

## 3. 实测：build 侧 vs 训练侧

子集 200 条逐条对比：

| 指标 | 结果 |
|---|---|
| `build_len`（apply_chat_template tokenize=True）与 `train_len`（tokenizer(text, add_special_tokens=False)）不一致 | **0/200** |
| 子集 max（两侧） | **638** |
| 子集 >640 | **0** |
| 全量 2,156 条训练侧 max | **640** |
| 全量 >640 | **0** |
| 全量恰为 640 | **7** |

结论：训练侧与 build 侧 token 数**逐条相等**，没有「模板/特殊 token 多算几个」的问题。

### 3 条边界样本明细（子集内最接近 640）

| i | kind | build_len | train_len | 距 640 | 640 截断后是否与原文一致 | assistant 尾部 |
|---|---|---:|---:|---:|---|---|
| 110 | refusal | 638 | 638 | **2** | 是（`truncated_is_same=true`） | `未找到相关资料`（拒答样本，本身无 `[1]`） |
| 128 | grounded | 636 | 636 | 4 | 是 | `……即体现了价值原则[1]。` 完整 |
| 190 | injection | 636 | 636 | 4 | 是 | `……购买全价票与九折票的人数一样多[1]。` 完整 |

补充：全量中 7 条恰好 640 的样本（i=504/786/1096/1160/1292/1704/1996）在 `ids[:640]` 后逐字比对原文，assistant 尾部 `[1]。` **全部保留**（截断是「保留前 640」，恰好等于全文，不会切掉尾部）。

## 4. 结论

**不存在二次截断。**
- 训练侧与 build 侧 token 数 0 差异；子集 max 638（留 2 token 余量），全量 max 640（0 条超限）。
- 即使 `max_length=640` 等于最大值，TRL 的截断是 `input_ids[:, :640]`，恰好等于完整序列，assistant 的 `[1]。` 不会丢。
- 最接近上限的 3 条与 7 条 640 样本已逐条验证尾部完整。

## 5. 建议

1. **不需要改 `max_length`，也不需要改数据压缩预算**；640 与数据上限一致，当前 0 风险。
2. 若想留冗余，可把训练 `--max-length` 设为 **648**（8 token 余量，显存影响可忽略），但这不是必需项；**不建议降低到 640 以下**（会真正截掉尾部）。
3. 建议在 `rebuild_all.py`/pins 里加一条断言：`max(token_len) <= 640`，并在训练启动日志打印「max_len=640 / over=0」，避免未来换 tokenizer 或模板后静默回归。
4. 子集固定使用 `short_run_200.jsonl`（sha `3f6528ef…`），不要用 `--limit 200` 让训练脚本自行抽样——两者抽样逻辑/种子不同，会破坏可复现性。
