## 3. 实测细节

### 3.1 登录过期（401）

| 场景 | 请求 | 结果 |
|---|---|---|
| 无 token | `GET /api/me/stats` | 401 |
| 伪造 token（`bad.token`） | `GET /api/me/stats` | 401，`{"code":401,"message":"未登录或登录已过期","traceId":"57acd349d0f3da17"}` |
| 结构合法但签名/过期无效（手工构造 JWT） | `GET /api/me/stats` | 401 |
| 正常 token | `GET /api/home` | 200 |

客户端侧（代码核对）：`ApiClient.auth()` 在响应码 401 且本地存在 token 时，`TokenStore.clear()` + 以 `NEW_TASK|CLEAR_TASK` 启动 `LoginActivity`；Retrofit 实例统一挂载该拦截器，覆盖所有业务接口。JWT `expiresIn=604800`（7 天），无 refresh token 机制，第 8 天起必然 401。

### 3.2 重复点击（幂等）

新建练习：`POST /api/practice/start` → `practiceId=24`，`totalCount=2`，题 49/48（均为 `SHORT_ANSWER`）。

| 步骤 | 响应 | answeredCount | correctCount |
|---|---|---|---|
| 首次提交题 49 | 200 `traceId=016810072038d4b5` | 1 | 0 |
| 再次串行提交题 49 | 200 `traceId=4a3d61a3672a3ccd` | **1（未累加）** | 0 |
| 并发两次提交题 48 | 两次 200（`39b2f10fee08207a` / `11aba4b53193c2dc`） | **2（仅 +1）** | 0 |
| 答题卡复核 | 200 `traceId=85ce6cc86854be5d` | 2 / 2 | 0 |

结论：串行与并发重复提交均幂等；前端另有 `btnAction.setEnabled(false)`、`finishing` 标志、自评按钮禁用等防抖，后端为最终防线。

### 3.3 契约一致性（关键风险）

- `student-app/app/build.gradle:28`：debug/模拟器 `http://10.0.2.2:8080/api/`
- `student-app/app/build.gradle:54`：release 真机 `https://10.200.83.194/api/`（APK dex 已确认写死）
- 当前环境：本机 IP `10.200.14.149`；仅 8080 监听；`10.200.83.194` ICMP/80/443 全部不可达
- `res/xml/network_security_config.xml:16-30`：`cleartextTrafficPermitted="false"`，仅信任 `@raw/server_cert` 与系统 CA
- `res/raw/server_cert.pem` 与 `nginx/certs/server.crt` SHA256 完全一致（`B5280E48…0FF335`），证书 SAN = `localhost / 127.0.0.1 / 10.200.83.194`

**影响**：release APK 在当前网络下登录、首页、刷题等**全部网络请求必然失败**（DNS/连接超时，或即使改回明文也会被 network security config 拦截，改 IP 又会触发证书 SAN 不匹配的 `SSLHandshakeException`）。W8 真机验收无法用该包完成。

**建议**：
1. 首选：将服务器地址改为运行时配置（首启输入/扫码/设置页切换），避免每次换网重打包；
2. 次选：用局域网固定域名 + 内网 DNS，证书 SAN 写域名，不再绑 IP；
3. 构建期由 CI 注入 `BASE_URL`，并自动重签证书（SAN 含目标地址），杜绝“改 IP 忘重签”；
4. 验收包暂时使用 debug 包（`10.0.2.2:8080` 模拟器可用），或先部署 `nginx-https.conf`（443）。

## 4. 缺陷台账

| 编号 | 严重级 | 标题 | 复现步骤 | 影响 |
|---|---|---|---|---|
| D1 | **严重（P1）** | release 包基址/证书/端口三处与实际环境不一致 | 安装 v1.9.1 真机包 → 启动 → 登录；或直接访问 `https://10.200.83.194/api/` | 真机包全功能不可用；证书 SAN 不含当前 IP，单纯改 IP 仍会 TLS 失败；W8 真机验收受阻 |
| D2 | 中（P2） | 401 跳转在后台可能失效，且无 onResume 兜底 | App 切后台期间 token 过期 → 回前台操作 | Android 10+ 后台启动 Activity 受限，跳转可能被静默拦截；用户回到前台仍停在失效页面，只见“加载失败”，需手动重进；并发 401 还可能重复拉起登录页 |
| D3 | 中（P2） | 练习页无状态保存，主观题自评入口可能在重建后丢失 | 提交主观题 → 未自评即旋转屏幕/被系统回收 → 重新进入练习 | `onCreate` 直接重新取下一题；后端 `next` 只返回 `user_answer IS NULL` 的题，已提交未自评的题无法再进入，该题永远不计分（`PracticeService.java:219-247`） |
| D4 | 低（P3） | 主框架忽略 `savedInstanceState`，Tab 每次切换重建 Fragment | 在题库 tab 滚动/筛选 → 旋转屏幕或切 tab | 重建后强制回首页 tab；列表滚动位置与筛选条件丢失（`MainActivity.java:27-53`） |
| D5 | 低（P3） | 弱网无缓存/无退避重试，POST 可能被 OkHttp 静默重发 | 弱网下提交答案/自评 | 用户仅见 Toast，无法重试或离线草稿（主观题草稿仅本地 SharedPreferences）；POST 重发依赖后端幂等兜底，新增非幂等接口时会重复写入 |
| D6 | 低（P3） | 401 静默跳登录，无“登录已过期”提示 | token 过期后任意操作 | 用户操作被打断但不知原因，易误判为网络故障 |

## 5. 结论

- **实测通过**：登录过期 401（服务端行为）、重复点击幂等（串行 + 并发，`practiceId=24`）、契约一致性探测（明确不通过）。
- **仅代码核对**：切后台状态保存（不通过）、弱网超时/重试（不完整）、请求重试（依赖后端幂等）、页面恢复（部分不通过）。
- **受阻**：关键机型安装/启动/截图——**无可用设备**（无真机；AVD `lux_test` 缺 `android-34/google_apis/x86_64` 系统镜像，启动 FATAL 退出）。未产生任何截图，未判定为通过。
- **最重要结论**：D1（严重）使 release 真机包在当前环境完全不可用，是 W8 客户端验收的唯一硬阻断；建议先修 D1，再补 D2/D3 的状态恢复与 401 兜底。
