### ③-1 A-01 为何保留 HTTP 200（不改 503）

`/v1/ask` 的既有契约是「永不 5xx」：Java 侧 `AiQaService` 依赖 `degraded` / `degrade_reason` / `layers_hit` 决定是否走 ngram/抽取式兜底。若把未预期异常改成 503，会触发 Java 侧「AI 服务不可用」分支，与「能力降级」语义混淆，且需联调验证。故本轮**保留 200**，但通过 `logger.exception`（完整堆栈）+ `UNEXPECTED_ERROR` 层标记 + `degrade_reason` 透出异常类型与消息，使「编程错误」不再被静默掩盖。**这不是「已修好」，是「已可观测、可归因」**；彻底区分需 Java 侧配合，登记为后续。

### ③-2 A-03 鉴权选择：`require_internal_token_if_configured` 而非 fail-closed（**风险必须明示**）

| 项 | 说明 |
|---|---|
| 选择 | `dependencies=[Depends(require_internal_token_if_configured)]`（`ocr.py:88`） |
| 理由 1 | `agent.py:146-149` 明文规定：fail-closed 作用域**只有** `/v1/agent/run|stream`，`/v1/route`、`/v1/embed|search|ocr|llm|wiki|interview` 维持「未配置令牌时放行 + WARNING」，否则一次配置遗漏会把整条降级链路打挂。`route.py:104` 已是同一先例 |
| 理由 2 | `tests/conftest.py:35-75` 的 `_isolated_env` 明确 `delenv("AI_INTERNAL_TOKEN")` 并注释「测试默认按未配置令牌运行」；若用 fail-closed，`tests/test_ocr.py` 33 例全部 401，破坏 373 passed。`ai-service/tests/` 不在本轮可改范围 |
| **风险（明示）** | **默认部署若未配置 `AI_INTERNAL_TOKEN`，`/v1/ocr` 仍等于无鉴权**（只打一条 WARNING）。但 **A-03 的核心风险「任意本地文件被读取并回传」已由根目录白名单默认拦住**（默认根 = 系统临时目录 + 工作区根，越界 `ParamError`）；未配令牌时仍可调用 OCR，但只能读白名单内文件 |
| 缓解建议 | 生产部署必须配置 `AI_INTERNAL_TOKEN`（与 Java 同值），并把 `OCR_ALLOWED_ROOTS` 收紧到上传目录；建议在 F4/部署文档与「已知限制清单」登记该前提 |

### ③-3 A-02 的已知限制

锁内包含 `_grade`（可能调用大模型，数秒级）与「懒生成下一题」，因此**不同 `session_id` 的 `/v1/interview/answer` 会被串行化**。正确性优先于吞吐；per-session 细粒度锁属架构级优化，登记为后续。`interview_start` 未包锁：其操作对象尚未写入 `_SESSIONS`（未共享），`_save_session` 自身有字典锁，无竞态。
