## 2,106 vs 2,110：哪个对、从哪来

**冻结文件是 2,110。** 证据：
- 脚本按「非空行」计数为 2,110；`data_pins.txt` 写 2,110；sha256 一致。
- 文件末尾无换行，`wc -l` 会显示 **2,109**（少计最后一行）——对账时不要用 `wc -l` 直接下结论，本报告统一用「非空行 + json.loads」口径。
- 三文件各自 kind 求和均等于行数，不存在「分类合计 2,106」的合法切分。

**2,106 的算术来源已定位**：`docs/交付大纲-全系统与微调-2026-11-03.md:170-178` 的「冻结集条数」表：

| 行号 | kind | 文档值 | 冻结实测 | 差 |
|---|---|---|---|---|
| 172 | mcq | 197 | 197 | 0 |
| 173 | grounded | **203** | **210** | **+7** |
| 174 | injection | 599 | 599 | 0 |
| 175 | refusal | 600 | 600 | 0 |
| 176 | planner | 419 | 419 | 0 |
| 177 | wiki | **45** | **43** | **−2** |
| 178 | citation | **43** | **42** | **−1** |
| — | 合计 | **2,106** | **2,110** | **+4** |

- 197+203+599+600+419+45+43 = **2,106**，与评审文档 D-01 的「分类条数合计为 2,106」完全吻合。
- 表中 203/45/43 是 23:32 中间版本的 grounded/wiki/citation（该版总数为 2,101），而 419/197 是 23:39 冻结版的 planner/mcq —— 表格由两次快照拼成，所以总和既不是 2,101 也不是 2,110。
- 同一文档 19、237、365 行都写 2,110，说明正文与表格不同步；2,106 不是任何一次落盘文件的行数（历史落盘为 2,101 → 2,110）。

**grep 结果**：字符串 `2,106`/`2106` 仅出现在两个规划 docx：
- `项目规划/01_项目大纲评审与修改建议.docx`（D-01 一条）
- `项目规划/03_第1周计划_2026-11-03_2026-11-09.docx`（P0 任务与验收标准各一条）

`training/reports/*.md`、`docs/*.md` 无该字符串；`docs/交付大纲` 只以表格形式隐含 2,106。

**结论**：2,110 为准；2,106 是交付大纲表格的过期行相加，不是真实样本数，也不是「2,110 去掉 4 条空 gold」的统计（虽然数值相同，但该表逐行相加已精确复现 2,106，且评审文档的措辞是「分类条数合计」）。

## 1,691 分流统计：两个数字各是什么、分母该是多少

脚本 `system_split` 输出（行为集 2,110 条，`unknown=0`）：

| 分组 | 条数 | system 特征 | 组成 |
|---|---|---|---|
| 无资料版（bare） | **197** | 含「如果没有【资料】」且不含「严格遵守」 | mcq 197 |
| 资料约束版（strict） | **1,494** | 含「严格遵守」+「未找到相关资料」 | grounded 210 + refusal 600 + injection 599 + citation 42 + wiki 43 |
| Agent 规划版（planner） | **419** | 含「严格遵守」+「未找到相关资料」+ JSON 协议 | planner 419 |
| 合计 | **2,110** | — | 三类互斥、无 unknown |

- **197 与 1,494 都是「条数」，不是比例**；二者相加 = 1,691。
- **1,691 的定义 = 2,110 − 419 planner = 回答类样本总数**（`non_planner_denominator`），也是「无资料版 + 资料约束版」两类 prompt 的覆盖总数。
- **分母该用哪个**：
  - 说「两版回答 system 的分流」→ 分母 **1,691**，覆盖率 1,691/1,691 = 100%；
  - 说「全量训练集 system 覆盖」→ 分母 **2,110**，必须写成三分：197 / 1,494 / 419，两版回答 prompt 合计覆盖 **80.14%**（1,691/2,110），planner 占 19.86%。
- 评审文档 D-02 指出「1,691 与 2,110 不同且未解释」，现在解释为：**1,691 是排除 planner 后的子集分母，不是全量**；原表述「其余用资料约束版」也不严谨，因为 planner 的 `PLANNER_SYSTEM` 是第三套（首句「你是一个大学生备考助教 Agent」，且要求 JSON 输出）。

**建议统一表述**（可直接替换到交付文档）：

> 2,110 条行为优先训练集按 system prompt 分三类：mcq 197 条用无资料版；grounded/refusal/injection/citation/wiki 共 1,494 条用资料约束版；planner 419 条用 Agent 规划版（JSON 协议）。回答类样本合计 1,691 条（占 80.14%），planner 占 19.86%，三类合计 2,110。

## 附：脚本字段说明

- `dup_user_full`：NFKC + 去空白/标点后的 user 全文哈希重复；`rows` 为多余行数（重复行数 − 组数）。
- `dup_stem`：题干段（mcq 为【题目】–【选项】之间，其余为【问题】之后）归一化后重复，**同题干不同选项也计**，用于暴露「同问法堆叠」，不等同于冗余。
- `missing_meta_qid`：`meta.qid` 缺失或为空；planner 与 chunk 样本天然无 qid。
- `empty_gold`：`answer_text` 为空且 kind 属 mcq/grounded/injection；行为集 4 条（injection 2 + grounded 2）。
