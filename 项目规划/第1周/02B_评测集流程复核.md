## 3. 「1,222 候选却丢弃 1,236」到底怎么回事

### 3.1 两个数字不同单位

| 数字 | 实际含义 | 单位 |
|---|---|---|
| 1,222 | 未参与训练的**题目**数 | 题 |
| 1,236 | 被三级判重剔除的**候选样本**数 | 条 |

它们之间没有「候选 − 丢弃 = 结果」的等式关系，因为生成样本会**放大**：一道题同时进 mcq、grounded、
injection 三条构造路径（refusal 复用题干、另配一门不相关学科的 chunk），所以候选条数 ≈ 1.3 × 题数。
用现盘数据可以正面验证：

- 1,232 题 → 1,600 条候选（1.30 条/题）
- 1,600 条候选 → 剔除 1,238 条 → 200 条
- 若不看单位，就会得到「1,232 题里丢了 1,238 条」这种看似不可能的结论

更直接的证据来自**最终留出集本身**：`eval_holdout.jsonl` 200 条只覆盖 **57 个唯一 qid**
（43 道题各出现 4 次、8 道题 2 次、3 道题 3 次、3 道题 1 次）。也就是说「条数」天然是「题数」的
3.5 倍左右，用题数去减条数必然对不上。

### 3.2 为什么现盘是 1,232 / 1,238，而不是 1,222 / 1,236

训练集在数据冻结前重建过两次。规划里的 1,222 对应旧训练快照：

- 旧：训练已用 qid = **1,822** → 3,044 − 1,822 = **1,222** 题
- 新（冻结版）：训练已用 qid = **1,812** → 3,044 − 1,812 = **1,232** 题

题库未变（3,044），训练侧少了 10 个 qid（数据清洗剔重后），因此可用题 +10、被剔样本 +2
（1,236 → 1,238）。这解释了 1,222→1,232、1,236→1,238 两组偏移，且偏移方向一致。

> 注：规划文档把 1,222 与 1,236 都标成「条」，把不同单位的两个数放在同一个减法链条里，
> 才产生了「不可能成立」的观感。**建议改成**：「未参与训练的题目 1,222 道（现盘 1,232 道），
> 生成的候选样本中有 1,236 条（现盘 1,238 条）因同题变体被剔除，最终保留 200 条」。

## 5. 留出集实际构成

### 5.1 `eval_holdout.jsonl`（200 条）

| kind | 条数 | 唯一 qid | 说明 |
|---|---:|---:|---|
| mcq | 50 | 50 | 全部带 `meta.qid`、`meta.answer`、`meta.answer_text` |
| grounded | 50 | 50 | 同上，带【资料】+ `[1]` 引用 |
| injection | 50 | 50 | 同 grounded，附攻击句 |
| refusal | 50 | 50 | 挂跨学科无关 chunk |
| 合计 | **200** | **57** | 同一道题被多类复用：43 题×4 类、3 题×3 类、8 题×2 类、3 题×1 类 |

- `meta` 缺失：0 条；`meta.qid` 缺失：0 条（**100% 可追溯**）。
- user 文本去重后仍是 200 条 → 条级无重复。
- 题级重复：mcq∩grounded = 46、mcq∩injection = 46、mcq∩refusal = 47（各 50 条）。
- 来源：全部来自 `build_eval.py`（题库新题），不含 `sft_val.jsonl`。

### 5.2 `eval_planner.jsonl`（50 条）

| kind | 条数 | meta |
|---|---:|---|
| planner | 50 | **50 条全部没有 meta**（无 qid、无 tool 标记） |

- 无法按 qid 追溯、无法做 qid 级去重，只能靠题干指纹判重（已在 eval_v2 中这样处理）。
- 这 50 条与 holdout 的 57 个 qid 无交集（planner 用 seed=99 单独抽样）。

### 5.3 统计口径建议（重要）

200 条**不是 200 个独立样本**，因为同一道题会在多个 kind 里各出现一次：

1. **有效样本量按题算 ≈ 57**。报告的 n 建议写成「200 条 / 57 题」，不要写「n=200」。
   若算置信区间或做组间比较，用**按 qid 的 cluster bootstrap**（重采样题号、带出该题所有行），
   否则区间会被系统性低估。
2. **跨 kind 比较要用配对检验**。同一批题同时出现在 mcq / grounded / injection（46 题）、
   refusal（47 题），四类指标高度相关；直接对两个比例做两样本检验会高估显著性。
   应改用 McNemar（同一题的成对通过/失败）或 paired bootstrap。
3. **口径提醒（分母按来源）**：默认口径（只用 holdout）时，`mcq_acc` 覆盖 mcq + grounded
   共 **100 行 / 54 个唯一 qid**（两类交集 46 题）；`cite_rate` **只覆盖 grounded 的 50 行 / 50 题**（holdout 里没有
   citation / wiki）。只有在 `--val` 追加 `sft_val.jsonl` 时，`cite_rate` 才包含
   citation 2 行、wiki 4 行，而这两类样本量不足以出结论，不应写进正文比例。
   两组分母不同且题有重叠，百分比不能直接相加或相减。

## 6. 复核中发现的风险（建议登记）

1. **规划文档口径混用**（本次要解释的问题本身）：同一段里「题」与「条」混写，建议全篇统一标注单位。
2. **留出集题级样本量远小于条数**：200 条只覆盖 57 题，`mcq_acc` / `cite_rate` / `injection_ok`
   在同一题上重复测量（详见 5.3 统计口径建议：按 qid 做 cluster / paired bootstrap，n 写 57 题）。
3. **`eval_planner.jsonl` 无 meta**：planner 指标无法题级追溯；且 `planner_ok` 只验 JSON 协议，
   测不出「格式对、内容错」（对应审计 F2）。
4. **题干级判重是启发式**：依赖 6-gram 倒排 + `ratio ≥ 0.9`，对改写较重的同题可能漏判；
   建议保留人工抽检（本次已由 eval_v2 用题干键二次复检，零剔除）。
5. **漏斗数字会随题库/训练集变动**：1,222/1,236 属于旧快照，文档若引用需带版本号或 sha。
