  select type, count(*) from question group by type;

  -d '{"model":"exam-prep-7b","messages":[{"role":"user","content":"你好"}],"max_tokens":30}'

## 5. 汇总

| 判定 | 数量 | 说明 |
|---|---|---|
| **通过** | 8 | 全部来自「Ollama 层 + MySQL 数据层」替代验证 |
| **失败** | 1 | Q4 解析缺失 1 条正式题（D-02）；另有 2 条 P2 观察项（D-01、D-04）不计入失败 |
| **阻塞** | 12 | 后端/AI 服务/Redis/Docker 未运行，接口层 8 类用例中 6 类无法执行 |

**核心结论：**

1. **接口层冒烟只完成了 1/8 类（Ollama 层）**，后端与 AI 服务全部未部署，Android 端未覆盖 —— 本轮**不构成"核心业务冒烟通过"**，只能算"环境探活 + 数据层就绪度验证 + AI 模型层冒烟"。
2. **数据层是全链路里最健康的一环**：2,473 道已审单选题的选项与正确答案 100% 完整，判分所需数据无缺口。题库不是瓶颈。
3. 真正的瓶颈是**环境未部署**（Docker/Redis 未启动、后端与 AI 服务无实例），且这不是"服务崩了"，而是"没拉起"。要完成规划要求的"至少一轮核心业务冒烟"，必须先有可运行环境。
4. 一旦环境就绪，Q1–Q4、E1、K1、G1、M1 可立即执行，用例与预期值已在本表固化，无需重新设计。

**下一轮冒烟的前置条件（按依赖顺序）：**

1. 启动 Docker daemon → `docker compose -f docker-compose.ai.yml up -d`（Qdrant）
2. 启动 Redis（6379）
3. 启动 FastAPI：`cd ai-service && run.bat`，验收 `GET /v1/health` 返回 200 且 `body.ready` 各项符合预期
4. 启动 Spring Boot：`启动后端.bat`（默认 profile 需指向 `application-local.yml`），验收 `GET /actuator/health` = 200
5. 上述 4 步全绿后，按本文 §2 表逐条执行 A1–M1
