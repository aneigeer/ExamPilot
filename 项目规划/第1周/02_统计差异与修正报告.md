## 1. 矛盾 1：训练集 2,106 与 2,110

### 结论
**2,110 正确**，2,106 是错误值，来源是`docs/交付大纲-全系统与微调-2026-11-03.md` 第 170–178 行的 kind 表逐行相加：
`197 + 203 + 599 + 600 + 419 + 45 + 43 = 2,106`

这张表混了两个时点的快照：
- `grounded=203`、`wiki=45`、`citation=43` 来自 **23:32 中间版**；
- `planner=419`、`mcq=197` 来自 **23:39 冻结版**。

冻结版实测：`grounded=210`、`wiki=43`、`citation=42`，合计 **2,110**。

### 证据
```
refusal 600 | injection 599 | planner 419 | grounded 210 | mcq 197 | wiki 43 | citation 42
合计 2110 | 非 planner 1691
```
（脚本：`count_train_data.py`，逐行 `json.loads` 统计，非 `wc -l`）

### 处置
- 已修正交付大纲表格，并校验合计 = 2,110；文档内 "2,106" 出现次数归零；
- 同文档第 19/237/365 行原本就写 2,110，属自相矛盾，现已一致；
- 附带修正：`wiki/citation` 的 P2 目标行由「45/43」改为「43/42」。

## 2. 矛盾 2：1,691 的分母

### 结论
1,691 = **2,110 − 419（planner）**，是「非 planner 子集」，不是全量。

三套 system prompt 的真实分布：

| 分组 | 条数 | system 类型 | 覆盖 |
|---|---|---|---|
| `mcq` | 197 | 无资料版 | 197/2,110 = 9.3% |
| 回答类（grounded/refusal/injection/citation/wiki） | **1,494** | 资料约束版 | 1,494/2,110 = 70.8% |
| `planner` | **419** | 规划专用（JSON 协议） | 419/2,110 = 19.9% |
| 合计 | **2,110** | — | 100% |

- 原表述「mcq 用无资料版、**其余**用资料约束版」不准确——它把 planner 算进了回答类；
- 正确的说法是**三分**：`197 / 1,494 / 419`，互斥且完备；
- 回答类内部覆盖率是 1,494/1,494 = 100%，但对全量只有 70.8%。

### 处置
交付大纲 §5.2 已改为三分表格，并注明旧表述错在哪。

## 3. 矛盾 3：1,222 候选 vs 1,236 丢弃

### 结论
**两个数都对，但单位不同**：1,222 计的是「题」，1,236 计的是「生成的样本条」。同一道题会派生 3–4 条样本（mcq / grounded / injection / refusal），所以丢弃条数完全可以大于题数。

### 实测漏斗（holdout，冻结版重跑）

| 阶段 | 数量 | 单位 |
|---|---|---|
| 题库总题 | 3,083 | 题 |
| 有效题 | 3,044 | 题 |
| 训练已用 qid | 1,812 | 题 |
| 未参与训练 | **1,232** | 题 |
| 生成候选 | **1,600** | 条（四类各 400） |
| 判重剔除 | **1,238** | 条（全文近似 598 + 题干 640；qid 0） |
| 剩余 | 362 | 条 |
| 配额截断 | 156 | 条 |
| 前缀重复 | 6 | 条 |
| 最终 | **200** | 条（四类各 50） |

最直接的反证：**剔除 1,238 条 > 可选 1,232 题**——同单位不可能出现。

planner 侧独立漏斗：未用题 1,232 → 候选 600 → 检查前 144 条（凑满 50 即停）→ 题干命中 90 + 前缀 4 → **50 条**。

### 处置
规划文档里把两者都写成「条」是问题根源，建议改写为：
> 从 1,232 道未参与训练的题中生成 1,600 条候选样本，判重剔除 1,238 条，配额截断 162 条，最终保留 200 条。

## 4. 矛盾 4：checkpoint-10 保留 vs 输出目录为空

### 结论
两个说法指的是**不同路径**，都成立：

| 路径 | 状态 |
|---|---|
| `training/output/qwen2.5-7b-exam-lora-v3/checkpoint-10` | **存在**（22:40:45 落盘，adapter 392 张量 / 40.2M 参数，sha `7b12ddc6`）|
| `training/output/qwen2.5-7b-exam-lora-v3/`（顶层） | 无 adapter、无 `train_metrics.json` |
| `training/output/qwen2.5-7b-exam-lora-v3b/` | **空**（23:57 创建，0 文件 0 字节）|

### 关键补充：checkpoint-10 不可续训
- `optimizer.pt` 仅 **286,720 B**（正常约 82 MB）；
- 缺 `trainer_state.json`、scheduler、rng_state；
- 步数只能由目录名推断，**没有 `train_metrics.json` 佐证**。

**判定：可读不可续**。`--resume` 会失败或退化为从头训练。

## 5. 数字漂移：1,222 与 1,232

规划文档写的 1,222 对应**旧训练快照**（当时训练用 qid 1,822）；冻结版训练集变化后，未用题变为 **1,232**，差 10 题。方向自洽：训练集扩了 10 个 qid，可选池少 10 题。

**这不是错误，是版本漂移**。凡引用此类派生数字，必须同时注明「基于哪份训练集 sha」。
