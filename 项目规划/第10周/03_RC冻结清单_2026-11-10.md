### 4.1 不可用原因（三条，逐条给证据）

1. **IP 不一致**：包内指向 `10.200.83.194`；本机本轮实测局域网 IPv4 为 **`10.200.86.72`**（`ipconfig \| grep -a IPv4`，另有 WSL/虚拟网卡 `198.18.0.1`）。二者不在同一网段，装到手机上必然连不上。
   > 与任务书给出的对照值 `10.200.1.56` 不同——本轮实测取到的是 `10.200.86.72`，说明**该机器 IP 本身发生过变化**（DHCP 或换网络），这也印证了「APK 内置固定 IP」方案在多轮演练中天然不可靠。
2. **证书 SAN 不匹配**：APK 走 HTTPS 且 `network_security_config.xml` 只白名单 `10.200.83.194`，把 BASE_URL 改到 `10.200.86.72` 后自签证书 SAN 不覆盖新 IP，会触发 `SSLHandshakeException`。
3. **本轮不可重建**：重打包需改 `build.gradle` 并执行 Gradle 构建，属于「改代码 + 构建」，超出本轮只读约束。

### 4.2 本轮 Android 端的替代路径（试点可用）

- **推荐**：直接用**学生端网页版** `http://10.200.86.72:8080/api/student/index.html`（SHA256 见 §3）在手机浏览器跑试点，功能面与 App 高度重合，零构建、零证书风险。

> 结论：网络层收口**只完成了一半**（账户层已收、监听层未生效）。这一项必须在发布前重启 MySQL 服务并复验 `bind_address=127.0.0.1`，否则 `04_发布前检查表` 的安全维度不能判 PASS。

### 7.1 语料聚合哈希（算法写清，可复现）

**算法**：按 `id` 升序取出每行 `(id, content_hash)`，以 `<id>:<content_hash>` 形式用 `\n` 连接（末行带换行），对整段字节流做 SHA256。

```bash
mysql -N -B -e "SELECT id, content_hash FROM exam_prep.ai_chunk ORDER BY id;" \
  | tr '\t' ':' | sha256sum
```

**结果**：`bec213616e9717167ffdb8360b61e2871b8d9b958c8c3aff58b4a028e13de9db`

**算法特性与局限（诚实声明）**：
- **只覆盖 `id + content_hash`，不覆盖 `content` 原文**。因此该哈希能检出「切片增删（id 集合变化）」与「任一文本内容变化（content_hash 变化）」，但**检不出 `title` / `status` / `vector_synced` / `content_hash` 之外的字段改动**。
- **不覆盖向量库**：Qdrant collection `exam_chunks` 的向量本身未做指纹（Qdrant 本地模式，无导出哈希）。若只重建了向量而未改文本，本哈希不变——这是已知盲区，向量一致性需靠 `ai_chunk.vector_synced` 计数另行核对。
- 该哈希对全表 13,307 行一次性计算，耗时 < 2 秒，可安全重复执行。
