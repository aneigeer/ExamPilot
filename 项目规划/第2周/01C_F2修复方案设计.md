## 0. 结论先行

**F2 不是一个「取块取错了」的 bug，而是「三个缺陷叠加 + 数据侧根本没有对应语料」。**

1. 选块与题目零关联（`chunks[i % len]`，实测 `i % 9746 == i`，等价于随机配同一序号）；
2. `pick_definition` 在真实语料上 100% 不命中，全部落到 `clip(content,120)` → **158/158 条 final 答案带省略号**；
3. final 样本的 user 里**没有任何【资料】**，答案却以 `[1]。` 结尾 → 直接教模型「凭空引用」；
4. 更关键的：**行测题（subject 190）在 `ai_chunk` 里没有任何「干净且能解释该题」的语料**（去污染后只剩 4 个知识点桩，内容就是题目列表）。

因此 **方案 A 在当前数据下可产出 0 条合格样本**；建议走 **方案 C（final 改为「基于给定资料作答」，200–300 条）**。

## 1. 现状：`build_planner()` final 分支

### 1.1 伪代码（`training/build_dataset.py:359-388`）

```text
pool   = 3,044 道题，random.shuffle(seed=42)         # 与 chunks 各自独立打乱
chunks = 9,746 个干净块，random.shuffle(seed=42)     # is_clean_chunk 过滤后
for i, row in enumerate(pool):
    stem = clip(row.stem, 160)                       # 只截题干，不取 subject / knowledge_id
    if i % 3 == 0: assistant = tool(search_knowledge, query=stem[:40], topK=5)
    elif i % 3 == 1: assistant = tool(search_wiki, query=stem[:30])
    else:                                            # ← final 分支
        chunk      = chunks[i % max(1, len(chunks))] # i < 3,044 < 9,746 ⇒ 实际就是 chunks[i]
        definition = pick_definition(chunk.content, chunk.title) or clip(chunk.content, 120)
        assistant  = {"thought":"资料已足够，直接作答","action":"final","answer": cite(definition)}
        #   cite(x) = x 去掉尾部句号 + "[1]。"
    out.append(Sample("planner", chat(stem, assistant, PLANNER_SYSTEM)))   # user 只有题干，无【资料】
```

### 1.2 四个缺陷（逐条对应实测）

| # | 缺陷 | 实测证据 |
|---|---|---|
| D1 | **选块与题目无关**：题池和块池各自打乱后按同一序号配对；`i % 9746 == i` 恒成立，等于「第 i 题配随机第 i 块」 | 答案里出现 MoA/MCP/Prometheus/《专题九--公司落地篇》，而题目是「观众：电视：新闻」「2014 年现代服务业…」 |
| D2 | **截断而非取句**：`pick_definition` 用 `DEF_SENT`（含「是指/指的是/称为/定义为/是一种」）在块内找定义句，真实语料几乎不命中 | **158/158 条 final 答案以 `…[1]。` 结尾**（`pick_definition` 命中率 0/158），全部走 `clip(content,120)` 兜底 |
| D3 | **引用无源**：user 只有题干，assistant 却输出 `…[1]。` | **158/158** 条答案以 `[1]。` 结尾；user 含「【资料】」的条数 = **0** |
| D4 | **无溯源元信息**：`Sample("planner", ...)` 不带 `meta` | 419 条样本无 qid/无 chunk id，本次只能靠题干反查（261 条因 160 字截断撞键，取首条） |

## 2. 数据侧：「题干 ↔ 知识块」到底有没有真实关联

### 2.1 表结构与关联路径（实查 `SHOW CREATE TABLE`）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `ai_chunk` | `source_type`（QUESTION / COURSEWARE / KNOWLEDGE / RESOURCE）、`source_id`、`subject_id`、**`knowledge_id`**、`title`、`content`、`ref_type`/`ref_id` | 检索语料块；`knowledge_id` 是指向 `knowledge_point` 的外键 |
| `question` | `subject_id`、`stem`、`material`、`analysis`、`type` | **没有** `knowledge_id` 字段，也没有指向 chunk 的字段 |
| `question_knowledge` | (`question_id`,`knowledge_id`) 主键 | 题目↔知识点关联表，3,056 行，**每题恰好 1 个知识点** |
| `knowledge_point` | `id`、`subject_id`、`name`、`level` | 30 行；subject 190 有 6 个（25 政治理论 / 26 常识判断 / 27 言语理解与表达 / 28 数量关系 / 29 判断推理 / 30 资料分析） |

→ **唯一可用的题目↔语料关联是 `question → question_knowledge → ai_chunk.knowledge_id`**；`subject_id` 太粗（subject 190 一个科目就有 3,027 块 / 158 题，无区分度）。

### 2.2 语料构成：干净块几乎全在「没有题」的科目里

| 口径 | 数量 | 分布 |
|---|---|---|
| `ai_chunk` 全量 | 13,306 | QUESTION 2,398 / COURSEWARE 10,214 / KNOWLEDGE 30 / RESOURCE 5 |
| 长度 120–1200（构建脚本的候选池） | 12,997 | — |
| 再过 `is_clean_chunk`（去题库原文污染 + 标题 3–30 字） | **9,746** | COURSEWARE **9,742** + KNOWLEDGE **4** |
| 干净块按科目 | — | 212: 5,159 · 211: 2,401 · 213: 1,765 · 214: 417 · **190: 4** |

- subject 190（行测，即 3,044 道题所在的科目）的 3,027 个块**全部**是 `source_type='QUESTION'` 的「题干：… 解析：… 标签：…」拼装文本，被 `is_clean_chunk` 全数过滤；
- 剩下 4 个干净块（id 3087/3089/3090/3091）内容是「知识点：政治理论 相关题目：<题干原文> 相关题目：…」，**0 条定义句**，本质是题目列表，不可当资料；
- 干净块的主体（9,742 条 COURSEWARE）属于 subject 211/212/213/214（AI 大模型面试、大厂架构、操作系统），而这些科目**在 `question` 表里一道题都没有**。

### 2.3 匹配率实测（对 158 条 final 样本的题目逐条计算）

| 判定方式 | 匹配率 | 说明 |
|---|---|---|
| `subject_id` 相同且有 ≥1 干净块 | **158/158（100%）** | 假阳性：同科目候选块 3,027 个，但全是题目拼装文本，没有区分度 |
| `question_knowledge.knowledge_id` = `ai_chunk.knowledge_id`，**不限干净度** | **158/158（100%）** | 每题的 6 个知识点下都有 116–939 个块，但块内容是**别人的题干+解析** |
| 同上，**只算 `is_clean_chunk` 通过的块** | **106/158（67.1%）** | 缺的 52 条 = 常识判断 21 + 资料分析 31（这两个知识点的 KNOWLEDGE 桩也被污染过滤掉了）；命中的也只是那 4 个无内容的知识点桩 |
| 文本相似度（题干 vs 全库块首 120 字，字二元 Jaccard） | max **0.121** / median **0.046** / p90 0.073 | 全库最相似块都只有 0.12，说明「语料里不存在与题干高度重合的正文」 |
| 文本相似度（题干 vs **知识点精确配对**的块） | median **0.009** / max 0.977 | 真正同知识点的块（另一道题）相似度中位仅 0.009 —— **说明本题库场景下「字面重合」不能用来判相关** |

**可行性判定**：`question_knowledge` 能把题目精确映射到知识点（100% 覆盖），但**知识点下的语料是题目本身**；真正可读的正文语料全在 4 个无题目的科目里。→ **「题干 ↔ 知识块」在现有数据里不存在可用关联。**

## 3. 三种方案对比

| 维度 | **A. 用真实命中 chunk 首段（不相关则不生成）** | **B. 不生成 final，只留 tool** | **C. final 改为「基于给定资料作答」** |
|---|---|---|---|
| 数据来源 | 该题 knowledge_id → ai_chunk | — | COURSEWARE 语料块（9,742 中可用的 1,024 个） |
| 预计条数 | **严格口径 0 条**；宽松口径（允许 QUESTION 块）158 条 | **261 条**（419 → 261，−37.7%） | **200–300 条**（可用组合 951 个，按标题去重后 343 个标题） |
| 可验证性 | 中：能校验「有没有引用」，无法校验「资料是否回答该问题」 | **最高**：JSON schema + 工具名 + query 非空即可判定 | **高**：引用编号对应资料、答案含资料实词、无 `…`、JSON 可解析 |
| 对「学会 final 收尾」的影响 | 若宽松实施：教模型「把题库原文当依据」→ 比现状更糟 | **负向**：final 正样本归零，模型会无限调工具 | **正向**：正是 `资料已在上下文 → 立刻 final + 标注 [1]` 的动作 |
| 对训练集的副作用 | 与 `grounded` 语义冲突（grounded 的资料是解析） | planner 占比从 19.9% 降到 12.4%，tool 类过采样 | 与 `citation`（42 条）同类但多一层 JSON 协议，互补 |
| 实施成本 | 需要先补行测语料（当前 0） | 改 1 行（删 final 分支） | 改 20 行左右 + 一段筛选逻辑 |

### 方案 A 的致命点（为什么严格口径是 0）
1. 干净块里与行测相关的只有 4 个知识点桩，桩内是「相关题目：…」列表，无解释性语句 → `clip_sentences` 能切句但没有可用内容；
2. 放宽到 QUESTION 块（题干+解析）后，资料就是**另一道题的完整题干与解析**，模型会学到「用别人的题目当依据回答本题」，且解析里常直接含答案，等于变相泄漏；
3. 加上「不得含题干：/解析：/相关题目：」这条内容过滤（必须加）→ 候选数直接归零。

> 补充：A 有一个域内变体 **A′**——把「该题自身的 `analysis`」当【资料】（158 题的解析中位数 310 字，150/158 ≥120 字，可用）。它与 `grounded` 类同源，但外层是 planner JSON，能干净地教 final。若不愿引入跨域语料，A′ 比 A 可行得多，代价是与 grounded 重复。

## 4. 推荐方案与阈值

### 4.1 推荐：C 为主（≈250 条），B 的「不造假」原则保留

- **样本形态**（单轮，仍满足 planner 协议）：
  - user：`【资料】\n[1] <chunk.title>：<clip_sentences(chunk.content, 180)>\n\n【问题】\n请依据资料说明「<chunk.title>」的要点。`
  - assistant：`{"thought":"资料已覆盖问题，直接作答","action":"final","answer":"<资料首句改写/摘录>[1]。"}`
- **筛选规则**：`source_type='COURSEWARE'` + `is_clean_chunk` + `pick_definition` 命中（去掉 `BAD_PREFIX` 开头句）+ 句子 ≥40 字 + 标题在样本内去重（每标题最多 2 条）
- **容量**：满足条件的块 **1,024 个**，涉及 **343 个不同标题**、**951 个（标题, 句子前 30 字）组合**，按科目 212: 444 / 213: 288 / 211: 274 / 214: 18；定义句长度中位 47 字，≥60 字的有 298 条 → 取 250 条完全够，且不会过度重复。
- **备选（域内）A′**：若必须保持行测域，则用该题 `analysis` 当资料，产出 158 条（≥120 字的 150 条），代价是与 grounded 重复。

### 4.2 若坚持方案 A：判定「相关」的四道闸门（全部满足才生成）

| 闸门 | 规则 | 理由 |
|---|---|---|
| G1 结构关联 | `question_knowledge.knowledge_id == ai_chunk.knowledge_id` | 唯一可靠信号；subject_id 无区分度（3,027 块/158 题） |
| G2 内容纯净 | 排除 `source_type='QUESTION'`；content 不含「题干：/解析：/参考答案/相关题目：」 | 防止把题库原文当资料（这是当前 3,027 块的全部内容） |
| G3 文本重合 | 题干与 chunk 首段 **2-gram 交集 ≥3 且 Jaccard ≥0.15** | 实测：全库最相似 max 0.121、p90 0.073、精确关联对 median 0.009 → **0.15 会把当前 158 条全部挡掉**，正是「宁缺毋滥」的目的；阈值不要往下调，调到 0.05 只能捞回 69 条噪声 |
| G4 可切句 | `clip_sentences(content, 180)` 非空（至少一个完整句） | 从根上消灭 `…` 截断型答案 |

**建议阈值**：G3 = 2-gram 交集 ≥3 **且** Jaccard ≥0.15。
**依据**：本题库的题干都是长句选择题，字面重合天然偏低（真正相关的跨题块也只有 0.009），所以 0.15 不是「宽松筛选」而是「几乎只放行近乎同文的块」；这会让 A 在补语料前稳定产出 0 条，避免又造出「看似修好、实则仍是噪声」的样本。

### 4.3 无论选哪个方案，都必须先修 D3（引用无源）

final 样本的 user 必须携带【资料】（方案 C 天然满足；A/A′ 需显式注入），否则「`[1]。`」永远是凭空的。这是 F2 的根因，与数据关联无关。

## 5. 风险与配套动作

| 风险 | 影响 | 缓解 |
|---|---|---|
| C 的资料域偏移（AI/大模型面试语料 vs 行测题库） | 模型可能学成「只有技术类问题才 final」 | 问题模板用中性表述（「请依据资料说明…」）；`citation` 类（42 条）本就用同一批语料，保持一致；评测集里把 planner 拆成 `planner_tool / planner_final_grounded` 两个子类分别看命中率 |
| B 单独实施 | 模型不会收尾，线上 agent 4 次工具后失败率上升 | 只作为 C 失败后的兜底，且需同时把 `PLANNER_SYSTEM` 的「最多 4 次工具」改成硬约束 |
| A 在补语料前强行实施 | 0 条或噪声 158 条，训练集进一步失真 | 先补行测语料（KNOWLEDGE 块的 content 目前只有「相关题目」列表，需要灌入真正的知识点正文）再启用 A |
| 评测集未同步 | `eval_planner.jsonl` 的 16 条 final 与训练数据同源同病，改了训练集若不改评测集，测的是旧分布 | 修 F2 时同步重建 `eval_planner.jsonl`（数据侧已有 50 条，其中 final 16 条） |
| 无溯源元信息（D4） | 事后无法按 qid 去重/回溯 | vs data-audit 的建议一致：planner 样本补 `meta {"qid":..., "chunk":...}` |

## 6. 一句话给决策层

F2 的修法不是「换一个更合适的块」，而是**承认行测题在 `ai_chunk` 里没有可用资料**：要么把 final 改成「资料已在上下文」的合成任务（C，推荐），要么干脆只训 tool（B，会丢能力），要么先补语料再做 A（当前 0 条）。任何「保留 final + 继续从现有池里挑块」的方案，都会把 F2 换个样子留下来。
