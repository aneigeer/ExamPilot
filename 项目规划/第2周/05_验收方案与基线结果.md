## 1. 通过标准（先定标准，再看数据）

## 2. 阈值标定（不是拍脑袋）

### 2.1 题干覆盖率阈值 = 0.15

用同一指标在**已知正常样本**上标定（`sft_train_behavior.jsonl` 的 gold assistant 输出）：

| kind | n | 题干 bigram 覆盖率 中位 | 25 分位 | ≥0.15 占比 |
|---|---|---|---|---|
| mcq | 197 | 0.400 | 0.256 | ~88% |
| grounded | 210 | 0.282 | 0.159 | ~72% |
| injection | 599 | 0.255 | 0.143 | ~68% |
| refusal | 600 | 0.000 | 0.000 | 0%（拒答样本本就没有答案内容，不适用） |

而**当前 planner final 污染样本**的覆盖率：中位 **0.000**、最大 **0.081**。

→ 任取 (0.081, 0.143) 之间的阈值都能完美分离。取 **0.15**：既高于污染样本最大值 1.85 倍，又贴近正常样本的 25 分位，属于"宽松下限"——它抓的是"完全无关"，不是"答得好不好"。因此 F2 PASS 只代表**不再污染**，不代表答案质量达标。

### 2.2 全文近似阈值 = 0.90

沿用团队既有口径（`eval_v2.py` 的 `FUZZY_RATIO`），保证与评测侧一致。6-gram 倒排只做**候选召回**（每条评测样本最多取 30 个候选），最终判定仍用 `SequenceMatcher.ratio ≥ 0.9`，避免短文本误杀。

### 2.3 资料保真度 = 0.80

修复后 final 样本将改为「基于给定资料作答」。此时答案 bigram 应有 ≥80% 能在【资料】里找到——低于此值说明模型在资料之外编内容。**当前数据无一条 final 带【资料】，故该项恒为 N/A（0 条违规）**，属于"新格式上线后才生效"的判据。

F4 在 1400/640/512 下都是 0 截断，因为当前 assistant 输出最长只有 508 字。为证明该检查不是摆设，压到 400：


即：**只要数据真的超长，F4 会立刻 FAIL**。真正的长度风险不在"改写范围"，而在训练脚本的 tokenizer 截断（`--max-length` 若按 token 计，中文 500 字 ≈ 700+ tokens），这一点需在训练侧确认口径。

## 4. 已知局限（不影响本轮结论，但必须写清）

1. **`eval_planner.jsonl` 的 50 条样本没有 `meta.qid`**（qid 覆盖 0/50），因此 F3 的 qid 维度对它**无法生效**，只能靠题干与全文近似兜底。建议新留出集补 `meta.qid`，否则"同题不同 id"这类污染永远测不出来。
2. **F2 的污染标记表是人工维护的**（8 个词）。它能抓到本轮已知污染，但换一批无关 chunk 会漏。因此 F2 的主判据是"题干覆盖率"，标记表只作为**快速定位辅助**，不作为唯一依据。
3. **F2 无法判断"答案是否正确"**。final 样本没有 gold 答案，覆盖率只回答"切不切题"。答案正确性仍需靠评测集（holdout mcq/grounded）间接看。
4. **F4 目前模拟的是字符截断**。若训练按 token 截断，需把 `--max-length` 换成 token 数并接 tokenizer；当前实现是本脚本的已知简化。

### 7.2 新问题：答案长度超出给定资料，78% 的答案含资料外内容

| 指标（`sft_train_behavior.jsonl` 250 条 final） | 实测 |
|---|---|
| 答案长度 中位 / 最大 | 166 / 203 字 |
| 资料长度 中位 / 最大 | **114 / 148 字** |
| 答案比资料长的条数 | **200 / 250（80%）**，长度差中位 54 字 |
| 资料保真度 ≥0.9（答案几乎全部来自资料） | 仅 **50 条（20%）** |
| 资料保真度 <0.8（含明显资料外内容） | **195 条（78%）**，中位 0.626 |

**这不是阈值苛刻，是构造口径不一致**：资料只放了 chunk 的前 ~120 字，而答案用的是同一 chunk 的后 ~200 字。
两条典型证据：

| 给定资料（截断处） | 答案（同一条样本） |
|---|---|
| 「…但在获取云端数据、调用在线 API 等方面，SSE 类型表现出色，能够为你提供丰富的外部信息支持。」（70 字，到此为止） | 「…**2.3 MCP本地服务测试** 现在我们来演示一下，如何在添加服务器时使用 STDIO 类型进行配置…」—— 这段在资料里**没有** |
| 「…本节简要概述了不同的共享策略如何工作。」（107 字，到此为止） | 「…**请注意，它只适用于CPU张量 - CUDA张量将始终使用CUDA API**…4.1 介绍一下文件描述符…」—— 同样不在资料里 |

**训练含义**：模型被教成"给定 120 字资料，可以合理输出 200 字"，而多出来的 80 字**输入里根本没有**。
这与站内"只依据资料作答、资料没有就拒答"的规则直接冲突——极可能就是本轮评测中**拒答合规 -40pp、引用 -52pp** 的训练侧成因。

**修复建议（一句话）**：让资料与答案用同一个 clip 长度（答案 ≤ 资料），或把答案也按资料边界重切；改完只需重跑本脚本，F2 的保真度项会直接反映。

### 8.2 两项独立抽检（主理人指定，不采信自报）

### 8.3 一个新观察（不阻断，但建议产品侧确认）

修好之后，final 答案的形态是**「资料原文去掉标题 + 末尾补 `[1]。`」的逐字复读**：

| 资料 | 答案 |
