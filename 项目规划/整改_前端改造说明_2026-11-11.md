## 1. 学生网页端 · 新增交互逐条说明

### 1.1 练习配置区（原「开始一组练习」卡片内）

1. **「考试类别（题库）」下拉**：`v-model="practiceExamCode"`，选项来自 `GET /questions/exam-categories` 动态加载（`loadExamCategories()`，组件 `mounted` 与登录成功后各触发一次），含 `:value="null"` 的「全部类别」项。**保留**原有的 `/exams` → `/subjects` 级联「考试类别 / 科目」下拉不动（它是选科目用的，与 examCode 是不同维度），新下拉标签加「（题库）」以区分。
2. **「真题年份」下拉改为动态**：删除原 `yearOptions` 的 IIFE 硬编码（`for (y=2026; y>=2016; y--)`），改为 `yearOptions: []` + `loadYears()` 从 `GET /questions/years` 填充 `[{year,count}]`；含 `:value="null"` 的「全部年份」项。练习与模考两个年份下拉共用这一份动态数据。
3. **提交时带上类别/年份**：`startPractice()` 在既有 `subjectId / mode / count / questionType / year` 之外，新增 `if (this.practiceExamCode) reqBody.examCode = this.practiceExamCode;`（其余参数名一字未改）。
4. **「全库随机练习」一键入口**：练习卡片顶部醒目横幅，`startRandomAll()` 只提交 `{ mode:'RANDOM', count }`，**不传** `subjectId / examCode / year`（按任务契约）。与 `startPractice()` 相互独立，未改动原有练习方法。
5. **题库总览统计**：按钮同区展示 `GET /questions/stats` 的 `total` 与 `byExamCode` / `byYear` 分布（chips）。`qStatsByExamCode` / `qStatsByYear` 由 `distRows()` 归一化，兼容「对象 map」与「数组」两种返回形态。
6. **loading / 空态 / 错误提示**：类别、年份、统计三者各有独立 `xxxLoading / xxxError` 与「加载中…」「暂无数据」「加载失败+重试按钮」；`startRandomAll` 失败写 `setupError`，不白屏。

### 1.3 新增「模拟面试」tab（第 6 个 tab）

## 5. 仍需后端配合的点 / 存在的缺口

1. **契约新接口尚未落地**：`GET /questions/years`、`/questions/exam-categories`、`/questions/stats`、`/admin/data/import-stats`，以及 `GET /questions` 新增 `year/examCode/keyword`、`POST /practice/start` 与 `POST /exams/mock/start` 新增 `examCode` —— 由另一 agent 正在补，本轮**只读源码核对、按契约对接**。若上线时这些接口缺失，所有新增下拉/统计会走「加载失败 + 重试/空态」，不会白屏，但无数据。上线后需联调一次。
2. **`subjectId` 仍是必填，与「全库随机」冲突**：`StartPracticeRequest.java:13-15` 与 `MockStartRequest.java:13-15` 均为 `@NotNull(message="科目不能为空")`。「全库随机」按任务要求不传 `subjectId`，当前后端会返回校验失败；需后端把 `subjectId` 放宽为可选（或允许 `examCode`/`year` 独立作为过滤条件）。同理，模考「纯按 examCode 不选科目组卷」也需后端放宽后才可用。
   - 前端当前保守做法：全库随机按契约不传 `subjectId`，失败时在 `setupError` 显示「题库暂无可用题目，或后端尚未开放『不限科目』抽题」；模考组卷仍保留 `subjectId` 必选（未破坏原有逻辑），`examCode` 作为**附加**筛选条件。
3. **`QuestionVO` 无 `examCode` 字段**：`QuestionVO.java` 只有 `year`（:46），没有 `examCode`。管理端「题目管理」列表与「题目总览」新增的「考试类别」列依赖后端在列表 VO 中输出 `examCode`；否则该列显示「—」。需后端在实体/VO 补 `examCode` 输出。
4. **管理端新建题目表单未补 `year`**：`QuestionSaveRequest.java` 未定义 `year` / `examCode`，按「不臆造字段」原则只做列表展示。题目年份目前由 `sql/migration-question-year.sql` 从 `source` 回填（见 `收尾_2026-11-11_B_年份与随机.md`）。若需表单录入年份，需后端先扩 DTO。
5. **INTERVIEW 题源与专题筛选的精度**：专题从 `GET /questions?examCode=INTERVIEW` 拉取后**前端本地提取**；若后端 `QuestionVO` 不返回 `examCode`，前端无法二次核验题源；若 `examCode` 参数被忽略，会拉到全库题目导致专题不纯。已做降级（失败/空时允许手动输入 `topic`），但精确按 INTERVIEW 过滤仍需后端支持该参数并在 VO 输出 `examCode`。
6. **契约文字与后端 DTO 的命名差异**：契约里写「`questionCount`」，后端实际是 `count`；时长契约写 `duration`，后端实际是 `durationMinutes`。前端一律以后端 DTO 为准（见 §3），若另一 agent 按契约文字改了 DTO 字段名，需同步前端。
7. **AI 面试依赖 Python 服务**：`/ai/interview/start` / `answer` 在 Python AI 服务不可用时返回 503，会话过期返回 404；前端显示后端错误文案，不做本地编造降级（与后端注释一致）。需 Python 服务与语料就绪后才能完整跑通。
8. **`import-stats` 表结构**：契约称「表不存在时返回空结构」，页面已按空结构渲染 `el-empty`。`byStatus` 的具体状态键未给定，页面用常见键做展示映射并保留原样显示，若后端实际键名不同，需微调 `statusName()` 的映射表。
