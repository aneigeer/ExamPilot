## 1. 目标与口径（先写清楚再派活）

### 1.1 「录进 RAG」的准确含义

不是「文件在硬盘上」，也不是「写进 `ai_chunk` 表」，而是**三级全通 + 一条实检索**：

| 级 | 判据 | 存储 |
|---|---|---|
| L1 登记 | 两目录全部文件入 `question_source`（`uk_source_path` 幂等） | MySQL |
| L2 切块 | 有文本层文件切出 `ai_chunk` 且 `status='ACTIVE'` | MySQL |
| L3 入向量 | `vector_synced=1` 且 Qdrant `exam_chunks` 集合中点数吻合 | Qdrant |
| L4 可检索 | AI 服务 8000 在线，用真实问句走 `/v1/search` 或 `/v1/ask` 能命中新灌语料（有 `chunk_id` / 来源证据） | 运行时 |

**只有 L4 通过，才能说「录进 RAG」完成。** 扫描件、岗位表、纯图片等非题目资产登记为 `SKIPPED` / `OCR_QUEUED` 属正常，不算缺口，但必须给出数量与理由。

### 1.2 「按循序完成所有周任务」的口径

按第 **1 → 10 周顺序**逐周核对：已结项周（1–6）保留原证据、不重做、不改写历史；未闭环项逐条补完并留机器证据；每周给出明确档位。

- **PARTIAL 不得写成 PASS**（协作规程 §3）。
- 系统级动作（改工作区外 `my.ini`、重启 MySQL、nginx reload）与真机验证（需手机连接）若无法在本工作区完成，如实列为「交用户执行」，并**计入未闭环**，不得算作完成。
- 第 6 周结论 **No-Go** 是既定决策，不属于「未完成」，不得为了凑「全部完成」去翻案或重跑训练。

### 1.3 明确禁止

- 不跑训练 / GPU / Ollama / 微调；不改冻结数据集。
- 不改工作区外文件；不重启 MySQL / nginx；不动系统服务。
- **不重复全量灌库**：现有 9000 条登记已幂等，重灌会破坏去重口径；只补「未解析 / INVALID / 未同步」的缺口。
- 不 force push、不改 git 历史；验证未过不提交、不推送。
- 不把「未验证」写成「通过」，不把「文档已写」写成「功能已验证」。
- 子 agent 不占 8080/8000 端口、不启停服务（本机动作统一由主 agent 执行）。

## 5. 验收判据三档

| 档 | 含义 | 处置 |
|---|---|---|
| PASS | 判据全满足、证据齐全 | 可进入下一阶段 |
| **PARTIAL** | 部分满足或证据不全 | **阻断「完成」结论**，产物不得作为正式交付 |
| FAIL | 判据不满足 | 退回执行者修复，修完重验 |

**验收者必须自己读原始文件与跑只读命令复核，不信汇报、不信注释。**

## 6. 汇总落盘口径

- 三层结论分开写：**① 数据是否全量入 RAG** / **② 周任务是否按序闭环** / **③ 项目是否可发布**。③ 受制于系统级动作与真机验证，预计仍为「不可发布」，不得因 ①② 有进展而放宽。
- 交用户执行的清单单列（S-01 改 `my.ini` + 重启 MySQL、S-02 auditor 弱口令、S-03 nginx reload、S-04 首次登录改密、真机 APK 重打包与证书）。
- 验证未过 → 不提交、不推送。
