## 5. 「T6 的 4026 PENDING」与「本轮 2200 PENDING」是否同口径

### 5.1 判定

**不同口径。** 且即便把两者统一到同一条 SQL，得到的也只是「同一总体在两个时点的快照净差」，**不得直接相减得出「已审核 1,826 道（或 1,827 道）」的结论**。

### 5.2 依据（四重差异，逐条有出处）

| # | 差异 | T6 / T3 / T5 的 4026 | 本轮 2200 |
|---|---|---|---|
| 1 | **筛选条件** | `question.origin_path IS NOT NULL`（**导入题**）。原文 `任务_2026-11-12_T3_本机执行记录.md:110`「导入题覆盖分档（`question.origin_path IS NOT NULL`）」、`:115` `PENDING 0 = 4026`；T5:286 `PENDING 0 4026 0` | **全库** `audit_status='PENDING' AND is_deleted=0`，**不加** `origin_path` 条件；主 agent §5 自己也拆成 `imported 2,199 + seed 1` |
| 2 | **时点** | 2026-11-12 22:3x（T6 §1 标题「时点 2026-11-12 22:3x」） | 2026-11-14 10:0x 之后（快照 10:07:23） |
| 3 | **语义** | 「**未进 RAG 的缺口数**」，`T6:42`「PENDING 存活导入题未进 RAG」，依据是 `ChunkExtractor.java:520` 只索引 `audit_status='APPROVED'`；T5:27「4026 题 / 0 覆盖」 | 「**当前库 PENDING 存活行数**」，不区分是否属两目录、是否有块、是否进 RAG |
| 4 | **中间流转** | 11-13 收尾执行记录:130 明写「4026 道 PENDING 题…**仍等用户 A/B，本轮未动**」；拆解记录 §1「4026 默认 A 保持现状」 | 当前同款 SQL 的 `PENDING/0` 已是 **2,199**（Q22），与「未动」的历史声明不符；期间有 11-13 18:20–22:10 的批量 UPDATE、+185 行写库、软删/重新激活等 |

### 5.3 同口径对齐后的正确表述（供裁定参考，不作结论）

统一到 T3:110 的同款 SQL 后：`PENDING/0` = **4,026（11-12）→ 2,199（11-14）**，净差 **1,827**；`APPROVED/0` = **3,836 → 5,832**，净增 **1,996**；导入题总体 **8,852 → 9,037（+185）**（§4）。
- 这个 1,827 是**两个时点的净变化量**，其间同时发生 `PENDING→APPROVED`、软删、新增 185 行、以及 11-13 的批量 UPDATE，**没有字段级流水**，不能反推「已审核 N 道」；
- 用 `4026 − 2200 = 1826` 更是把「导入题口径」与「全库口径」混减，连净差都不是（正确同口径净差是 1,827）；
- 结论：**4026 与 2200 既不同口径、也不同时点，任何相减结论都不成立**。若需解释差异，应由主 agent 补 11-12→11-14 之间的写库/审核流水或逐时点快照，交 qa-acceptance 独立裁定。
