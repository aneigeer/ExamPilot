> 执行者：主 agent（本机动作）
> 背景：用户实测「什么是Claude Code」得到篮球题答案（答非所问），并反馈「Agent 系统没了」「模拟面试没了」

## 1. 根因（三条叠加，不是单一问题）

| # | 根因 | 证据 |
|---|---|---|
| 1 | **AI 服务（8000）未启动** + `app.ai.fastapi.enabled: false` → 向量通道整条关闭，退化为 ngram 字面检索 + 抽取式硬答 | `netstat` 无 8000 监听；`application.yml:331` 原为 `false`；注释自述「enabled=false … 自动退化为 ngram 字面检索 + 抽取式生成」 |
| 2 | **候选池过小**：`search.py` 只从 Qdrant 取 `top_k` 条（默认 5）就重排，正确内容排第 20 名根本进不来 | 改前 `qrant_client.search(..., top_k=top_k)`；实测「Claude Code官方最佳实践」原始排第 20 |
| 3 | **重排只认整句命中标题**：`if query.strip() in title`，问句「什么是Claude Code」永远不触发 | `search.py` 原 `_rerank_score` |

**附加发现**：`/v1/ask` 的 `_retrieve` 完全没走 `/v1/search` 的重排，自己直接查 Qdrant，所以只重修 `search.py` 对问答无效。

## 4. 模型切换说明

- 用户指定「先只用千问3B」，已切 `qwen2.5-3b-instruct-q8_0-baseline`（Ollama 本地，3285476379 B）。
- **能力边界（如实记录）**：3B 在拿到正确材料时能给出结构化答案，但**抽象概括与抗干扰能力弱**——同一批材料里混入无关片段时容易顺着无关内容编。已通过「单文档限流 + 实体词重排」把干扰降到最低，但不能等同于 7B 或在线模型的质量。
- 回滚方式：把 `.env` 的 `LLM_MODEL` 改回 `qwen2.5-7b-instruct-baseline`，重启 AI 服务即可（备份在 `backup/收尾前快照_2026-11-11/env.bak`）。

## 5. 题库扩容的可行性结论（用户要求「题库全整进去」）

| 事实 | 证据 |
|---|---|
| `D:\题库` 共 2950 xlsx / 1028 pdf / 98 xls / 84 docx / 58 doc | `find` 统计 |
| 但 **xlsx 绝大多数是国考岗位表/报名数据，不是题目** | `D:/题库/【2】国考岗位表及分数线/…` 全是职位表 |
| 四六级、考研、国考题干**均为 PDF** | 目录清单 |
| **PDF 是扫描件，无文本层** | `pypdf` 提取 24 页四级真题，每页 **0 字符** |
| OCR 服务明确拒绝扫描 PDF | `/v1/ocr` 返回：`PDF 无文本层（扫描件），本服务不做 PDF 转图` |

**结论**：题库全量入库需要新建一条流水线——`PDF → 逐页转图（项目已有 PDFBox 3.0.7）→ /v1/ocr → 题目结构化（题干/选项/答案/解析）→ 人工校对 → 入库`。这不是当天能完成的活，且 OCR 质量决定题目正确性，必须抽检后才能批量。**本轮不宣称「题库已全量导入」。**

另：现有 634 篇面试/技术课件**已入库 578 篇**（`courseware` 表：01 面试系列 156 / 02 AI大模型 276 / 03 大厂架构 146），`ai_chunk` 中 424 段含「Claude Code」。缺口是 106 篇纯图片文档（正文在图片里）需 OCR、46 篇封面页。
