## 3. 功能改动

### 3.1 后端（Java）

- `QuestionController`：`GET /questions` 增加 `year` / `examCode` / `keyword`；新增 `GET /questions/years`、`/questions/exam-categories`、`/questions/stats`。
- `StartPracticeRequest` / `MockStartRequest`：新增 `examCode`；`subjectId` 与 `examCode` 都不传 = 全库随机；`year` 与 `examCode` 同时生效（AND）；WRONG_BOOK 模式保持不套筛选。
- `AdminDataController` + `ImportStatsService`：新增 `GET /admin/data/import-stats`（表不存在返回空结构，不 500）。
- `application.yml`：`app.ai.agent.enabled` 默认 `true`；provider 固定 ollama；`ollama-model` 固定 3B；`AiProperties` 代码默认值同步 3B，消除「yml 覆盖才一致」的历史隐患。
- 迁移：`sql/migration-question-source.sql`（新建 question_source）、`sql/migration-question-exam-code.sql`（question 增加 exam_code/paper_name/origin_path + 两个索引 + 从 source 回填 3027 条）。

### 3.2 导入流水线（Python）

- `scripts/import_question_bank.py`（1500 行）：register / parse 两阶段，幂等、可重跑、单文件失败不中断、显式事务包住「题+选项+答案+知识点」。
- `scripts/pdf_text_cache.py`：并行预抽取 PDF 文本（5 并发），696 个待解析 PDF 用 248 秒抽完。
- 2026-11-11 三处关键加固：
  1. **PDF 抽取子进程隔离**：畸形 PDF 会让 pypdf 在 C 层段错误（退出码 139/3221225477），进程内 try/except 拦不住 → 改子进程 + 结果走临时文件，单坏文件只丢自己。
  2. **禁用管道**：pypdf 对畸形 PDF 刷大量告警，管道写满 64KB 后父子互等死锁（实测每文件卡满 180 秒）→ stdout/stderr 丢弃。
  3. **答案按套号配对**：原来按 `(exam_code, year)` 分组回填，同考次第 1/2/3 套会串答案 → 改为 `(exam_code, year, 第N套)`，拿不到同套答案宁可留空，不猜。

### 3.3 前端

- 学生端 `static/student/index.html`：考试类别 + 年份下拉（接口动态加载）、「全库随机」一键入口 + 题目总量分布、模拟考试按类别/年份/题数/时长组卷、新增「模拟面试」tab。
- 管理端 `admin-web/index.html`（同步到 `static/admin/index.html`，字节级一致）：新增「题库导入」页（按状态/类别/年份统计、待 OCR 与失败清单）与题目总览筛选；题目列表增加 year、examCode 列。
- 语法校验：两处内联脚本 `node --check` 通过。

### 3.4 Agent 与模拟面试（Python）

- `interview.py`：题源改为从 INTERVIEW 知识块检索组题，支持专题；3B 判分与追问合并为一次调用（单模型下不串行多次调用）；单次请求有 LLM 调用预算与 20 秒硬超时，超时降级而不是拖死。
- **JSON 解析加固**（本次实测修复）：3B 输出常带中文引号、裸换行、尾逗号，原解析直接失败导致「评分降级」。改为四轮修复 + 字段级正则兜底；修复后同一题从 `degraded=true` 变为 `degraded=false`、得分 75/「正确」。
- Agent 工具链 7 个只读工具保持，工具调用经 Java `/internal/agent/tools/*`；`AI_AGENT_ENABLED` 默认开启。

## 6. 已知边界（不粉饰）

1. **扫描件未 OCR**：391 个文件判为扫描件进 OCR 队列。PaddleOCR 已装，但 391 个文件（多为整册真题）全量 OCR 需数小时，本轮未跑。
2. **答案覆盖率低**：导入的 7998 道真题里只有 1719 道能定位到标准答案。原因有三类：答案册是解析体例而非答案键、部分解析册用私有字体编码（抽出来是乱码）、同考次多套卷答案无法唯一对应。处理方式是**只把能判分的题置为 APPROVED**（5255 道），其余 6682 道留在待审核，不进入练习与考试，避免「答对了判错」。
3. **面试问答是抽取式**：1069 道面试题的参考答案取自原文段落，用于模拟面试与背诵，不等于人工精修的标准答案。
4. **Android 端未重打包**：`student-app` 源码未改、APK 仍是 1.9.1 旧包，新功能目前只在学生网页端与管理端可用。
5. **3B 能力边界**：拿到正确材料时能结构化作答，抽象概括弱；面试评分在材料不足时会降级为抽取式（此时响应里 `degraded=true`，前端应提示人工复核）。
6. **6 个失败/部分文件**：5 个 FAILED（2 个超大听力合集 PDF 段错误、其余见失败清单）、258 个 PARTIAL（切题不完整），未逐个人工修补。
