## 2. 派活六项

### E1 · 后端
- 【任务】只读审查 `backend/` 已写好的 Java 代码，找真实缺陷与漏洞。
- 【输入】`backend/src/main/java/`、`backend/src/main/resources/`、`backend/pom.xml`、`backend/src/test/java/`、`sql/`、`config/`、`docker-compose.yml`、`nginx.conf`、`项目规划/审计_B_产物证据_2026-11-10.md` §9、`项目规划/审计_C_缺口复查_2026-11-10.md`。
- 【产出】`代码审查_2026-11-10_E1_后端缺陷清单.md`：① 缺陷表（编号 / file:line / 类型 / 严重度 P0-P2 / 描述 / 原文片段 / 建议修法 / 是否已在上轮登记）② 按模块计数 ③ **可跑验证命令清单**（mvn 命令 + 具体测试类，标明哪些不需要数据库）④ 无法判定项。
- 【判据】每条必须 file:line + 代码原文片段；区分「确定缺陷」与「可疑但需运行验证」；不把「没写测试」当成「功能有 bug」；不编造行号；不夸大严重度。
- 【禁止】不改任何项目文件（只新建产出）；不跑构建 / 服务 / 数据库 / 端口；不扫描工作区外；不碰周计划与第 7~10 周文档；不推 Gitee。
- 【回报】≤10 行：缺陷总数、P0/P1/P2 各几条、最严重 3 条 file:line、可跑命令条数、产出绝对路径。

### E2 · 双端

## 3. 验收判据三档

| 档 | 含义 |
|---|---|
| PASS | 判据全满足且证据齐全 |
| PARTIAL | 部分满足或证据不全 → **阻断「完成」结论，不得写成 PASS** |
| FAIL | 判据不满足 → 退回执行者修复 |
