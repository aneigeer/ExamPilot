### 3.3 关键 L2 发现：**题目表 ≠ RAG 索引**

```sql
-- PAPER（真题册）所有文件 chunk_count 都是 0
SELECT parse_status, COUNT(*) files, SUM(question_count) q, SUM(chunk_count) c, SUM(chunk_count=0) c0
FROM question_source WHERE doc_kind='PAPER' GROUP BY parse_status;
-- PARTIAL 256 文件 / q=3317 / c=0 / c0=256
-- PARSED   47 文件 / q=4466 / c=0 / c0=47
-- SKIPPED  28 / OCR_QUEUED 23 / FAILED 2（均为 0）
```

原因（代码证据 `scripts/import_question_bank.py:1245-1307`）：PAPER 分支只 `insert_question(...)` 写 `question` 表，**不调用 `upsert_chunks(...)`**；只有 ANSWER/ANALYSIS/INTERVIEW_KB/VOCAB/TEMPLATE/OTHER 兜底分支才写 `ai_chunk`（`CHUNK_SOURCE_TYPE='COURSEWARE'`）。

```sql
SELECT COUNT(*) FROM ai_chunk WHERE source_type='QUESTION';          -- 3057（全部为历史种子题的块）
SELECT MIN(source_id), MAX(source_id), COUNT(DISTINCT source_id) FROM ai_chunk WHERE source_type='QUESTION';
-- 1 / 4026 / 3057 —— source_id 全部 < 1000000，即全部来自 3085 条历史种子题
SELECT COUNT(*) FROM ai_chunk WHERE source_type='QUESTION' AND source_id>=1000000;  -- 0
SELECT COUNT(*) FROM question WHERE origin_path IS NOT NULL
  AND id NOT IN (SELECT DISTINCT source_id FROM ai_chunk WHERE source_type='QUESTION'); -- 8852
```

即：**本次导入的 8852 道题，0 道有 `source_type='QUESTION'` 的 ai_chunk**；303 个 PAPER 真题册文件（47 PARSED + 256 PARTIAL）切出 **7783 道题**但 `chunk_count=0`。按 §1.1 L2 判据（有文本层文件切出 `ai_chunk` 且 ACTIVE），这些题干**未进入向量索引**。是否能由 MySQL 全文检索兜底，属 L4/T3 验证范围，本次**未验证**。

```sql
SELECT SUM(question_count) FROM question_source;                        -- 8852
SELECT SUM(chunk_count)    FROM question_source;                        -- 54321
SELECT COUNT(*) FROM ai_chunk WHERE source_type='COURSEWARE' AND source_id>=1000000; -- 55297
```

`question_source.chunk_count` 合计 54321，但 ai_chunk 里实际由导入流水线（`source_id = 1000000 + question_source.id`）写出的 COURSEWARE 块是 55297，差 **976**。逐文件核对：


### 4.2 INVALID 659 条是什么、为什么没同步

```sql

-- QUESTION / INVALID / 0 = 102
```

- **异常待复核（未确认）**：其中 **374 条**（323 已 PURGED + 51 从未同步）的父题当前是 `is_deleted=0 AND audit_status='APPROVED'`，与「来源失效」口径不一致；可能是失效时题目尚未审核通过、之后题目被批量 APPROVED 但块未重新激活。**原因未确认，处置（是否重新激活并重新向量化）交 T3 复核，本次不写成「已修复」也不写成「必须重灌」。**（审计后复检该口径为 **0**，见**附录 A-2**；引用时请重跑 SQL，勿沿用 374。）
