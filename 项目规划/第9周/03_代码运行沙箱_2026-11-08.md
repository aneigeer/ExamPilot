## 一、暴露面

### 1.1 路径与鉴权

- 控制器：`CodeRunController.java:20-24`，`@Tag(name = "21. 编程题运行")` + `@RestController` + `@RequestMapping("/run")`；唯一方法 `POST`（`CodeRunController.java:37-42`）。
- 全局上下文路径 `/api`（`application.yml:3-4`）→ 实际 URL **`POST /api/run`**。
- 鉴权规则：`/run` 未列入 `PUBLIC_ALL`（`SecurityConfig.java:104-118`）、也不在 `/ai/ask` 之类的特例（`SecurityConfig.java:202`），因此落入兜底 `.anyRequest().authenticated()`（`SecurityConfig.java:213`）。
  - 含义：**只校验"已登录"，不校验角色**；`SecurityUtils.requireUserId()`（`CodeRunController.java:39`）仅取用户 ID 写日志（`CodeRunService.java:90`），**用户 ID 不参与任何权限/配额判断**。
- 实测（无害）：未带令牌 `POST /api/run`（body 为一段正常 Java）→ **401**，说明 Security 链生效，未匿名放行。

### 1.2 是否在对外 api-docs 清单内

- `PUBLIC_ALL` 明确匿名放行 `/v3/api-docs/**`（`SecurityConfig.java:108`），`springdoc.api-docs.enabled=true`（`application.yml:80-83`）。
- 实测 `GET /api/v3/api-docs` → **200**，`paths` 共 **189** 条（= 全量 210 operation / 196 对外接口口径，见 `README.md:17`、`项目规划/第8周/01_接口与数据流_2026-11-08.md:25`），**`/run` 在册**，其 `description` 原文含"**访问级别：AUTH**""⚠️ 该功能直接在本机执行用户代码……公网部署必须换独立判题沙箱"。
- 结论：该接口**同时出现在匿名可读的对外接口文档中**，等于向任何访客公开"本系统有本机代码执行入口"。

### 1.3 注册链路把"需登录"降级为"公开"

- `POST /auth/register` 匿名可用（`SecurityConfig.java:106`），注册即 `role=STUDENT`、`status=1`、直接返回 JWT（`AuthService.java:75`、`AuthService.java:105-107`）。
- 因此 `authenticated` 并不构成有效边界：**任何能访问该站点的人都能自助注册拿到令牌，再调用 `/run`**。

### 1.4 网络可达性（本机现状）

- 实测监听地址为 `::`（PID 3608，`netstat` 口径 `LocalAddress=::, LocalPort=8080`）→ 绑定全部网卡，**同网段可直接访问**。
- 部署侧：`docker-compose.yml:45-66` 的 backend **未发布端口**，仅由 nginx 反代（`nginx-https.conf:73-82` `proxy_pass http://127.0.0.1:8080`）；本地 Windows 直跑 jar 时则是全接口直开。
- 结论：本机/局域网形态下 `/run` 可被任意终端触达；一旦该站点上公网（无论直连 8080 还是经 nginx），入口即公网可达。

### 1.5 调用方

- `student-app` 的 Retrofit 接口清单（`ApiService.java` 全量 `@GET/@POST`）**无 `/run`**；`admin-web/index.html` 与内嵌 `backend/src/main/resources/static/admin/index.html` 亦无 `/run` 调用。
- 结论：**该功能在两端均无任何客户端使用**，属纯冗余暴露面，关闭成本极低、业务影响为零。

## 五、风险级别与触发链

**P0（设计缺陷级高危），现网可利用性受数据态限制（"潜在可远程命令执行"）。**

触发链（全部无需管理员权限）：
1. 互联网用户 `POST /api/auth/register` → 得 `STUDENT` JWT（`AuthService.java:75-107`）；
2. `GET /api/questions?type=PROGRAMMING` 枚举编程题 ID（该列表匿名可读，`SecurityConfig.java:63-88`）；
3. `POST /api/run` 提交 Java 代码 → 子 JVM 以**后端进程身份**执行；
4. 可达成：读 `application.yml`/`uploads`、读 env 中 `JWT_SECRET`/`DB_PASSWORD`、访问内网 MySQL/AI 服务、`Runtime.exec` 起任意系统命令、`System.exit`/OOM 拖垮宿主、并发打满进程与内存。

放大因素：`/api/v3/api-docs` 匿名可读（相当于公示入口）；注册开放（无需审核）；无并发上限与限流（一个请求一个进程，可并行打爆）；无内存限制（子 JVM 默认堆 ≈ 物理内存 1/4）。

收敛因素：题目必须 `type=PROGRAMMING`（当前 `total=0`）；本机无 `gcc`（C 路径不可用）；Java 路径仍完全可用。

**评级**：对外可达 + 隔离不达标 + 零客户端使用 → 不应保留，按"立即关闭公网入口"处置。

## 七、结论

**功能存在、对外可达（任意登录用户）、实现为本机裸进程执行、隔离不达标**。在"无编程题"的当前数据态下暂不可直接被利用，但一旦录入任一编程题，即为"任意注册用户可在后端宿主执行任意 Java"的 P0 远程命令执行面。该功能在 App 与管理端**均无调用方**，建议按 6.1 + 6.3 立即下线并从对外文档摘除。
