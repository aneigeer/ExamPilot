## 5. 可配置化方案（**只出方案，本轮未改一行**）

> 目标：换网络环境时**不改源码、不重签（在 IP 已包含在 SAN 的前提下）、可一键注入**；与 `00_协作规程.md` §1「执行/验收分离」一致，落地须另派任务 + 独立验收。
> 本轮**未修改** `build.gradle`、`network_security_config.xml`、任何 Java 文件、证书脚本、nginx 配置；**未重打包、未重签证书**。

### 5.1 方案 A（推荐 · 最小改动 · 构建期单一配置源）

**A-1　引入单一配置源**：在 `student-app/gradle.properties`（已存在，模板值入库）或**不入库的** `student-app/local.properties`（已存在，`:1` 注释「本机路径，不入库」）新增两个键：
```
examprep.baseUrl=https://10.200.83.194/api/
examprep.lanHost=10.200.83.194
```
优先级建议：`-P` 命令行 > `local.properties` > `gradle.properties` 默认值；用 `project.findProperty("examprep.baseUrl")` 读取，保留现值作默认，**空值即构建失败**（避免静默回退到错误 IP）。

**A-2　改造 `app/build.gradle:28` / `:54`**：把两处字面量改为 `buildConfigField "String", "BASE_URL", "\"${baseUrl}\""`；`defaultConfig` 用 debug 默认（`http://10.0.2.2:8080/api/`），`release` 用 `baseUrl` 属性。同时用同一属性生成 `buildConfigField "String", "LAN_HOST"`，供代码不再靠 `replace("/api/","")` 猜主机。
- 注意 `buildConfigField` 的字符串需正确转义引号；`resValue` 与 `manifestPlaceholder` 按需配套。

**A-3　消除 `ResourceDetailActivity.java:154 / :337` 的 URL 结构耦合**：改为 `Uri.parse(BuildConfig.BASE_URL).buildUpon().clearPath()...` 或抽到 `ApiClient.siteRoot()` 统一返回站点根；**不要**再对 `"/api/"` 做字符串 `replace`。否则一旦属性值改成不带 `/api/` 后缀（如直连网关），下载/图片链接会拼成 `https://host/api//files/...` 或丢路径。

**A-4　`network_security_config.xml` 去掉 IP 绑定（关键）**：Android 框架解析 `res/xml/network-security-config` 时，`<domain>` 内容**必须是字面文本，不支持 `@string/xxx` 资源引用或 Gradle 占位符**；因此「属性注入到 `<domain>`」这条路走不通，建议二选一：
- **A-4a（推荐）**：删掉 `:24-30` 的整段 `domain-config`，保留 `base-config cleartextTrafficPermitted="false"` + `trust-anchors(@raw/server_cert, system)`。安全性**不降低**（明文仍全禁、信任锚点不变），且主机名校验仍由证书 SAN 完成 —— IP 变更时只需「重签含新 IP 的证书 + 改 `baseUrl` 属性」，**不再需要改 XML**。
- **A-4b**：按 buildType / productFlavor 拆 `sourceSets`，每个变体放一份静态 XML；缺点是每换一个网络仍要新增变体文件，不推荐。

`src/debug/res/xml/network_security_config.xml` 本就无 `<domain>`、允许明文，**无需改动**。

**A-5　证书侧参数化联动**：`scripts/生成自签证书.ps1` 的 `$san`（`:90`）已经支持 `-Ip`，建议：
1. 让脚本从**同一个** `local.properties` 读 `examprep.lanHost`（PowerShell 解析 key=value），不再靠人手敲 `-Ip`；
2. SAN 额外纳入 `IP:10.0.2.2`（模拟器视角）与常用 DNS 名，或改签发**通配符/多 IP 列表**证书，减少换网重签次数；
3. 生成后同时覆盖 `nginx/certs/server.crt`（+ `.key` / `.p12`）与 `student-app/app/src/main/res/raw/server_cert.pem`，并用 `openssl x509 -noout -ext subjectAltName` 留证；
4. 证书有效期（当前至 2029-01-31）与 `basicConstraints CA:TRUE` 属既有设定，是否调整为非 CA 叶子证书另案评估。

**A-6　配套交付物**（落地轮次做，本轮不做）：新 APK 的 SHA256 + 构建时间、`buildConfigField` 生效验证（`BuildConfig.BASE_URL` 打印/logcat）、`adb logcat` 里一次真实请求命中新主机、T2:200 要求的「真机安装后登录→刷题→AI 答疑跑通」录屏，交 `qa-acceptance` 复验 C1 转 PASS。

### 5.2 方案 B（可选增强 · 运行时可配置，建议另开一轮）

在「我的 → 设置」增加「服务器地址」输入，存 `SharedPreferences`，`ApiClient.build()` 改为按运行时值构造 Retrofit（需在切换时**重建单例**并清空 `api` / `longApi`，`ApiClient.java:24-25`）。优点：试点换网无需重打 APK；风险：
- 与 release 的「禁明文 + 信任自签锚点」策略冲突（用户填任意 http 地址会被 `cleartextTrafficPermitted="false"` 拒绝）；
- 任意主机 + 自签锚点会扩大信任面，须加域名白名单校验；
- 属产品功能改动，超出「最小可配置化」，**不建议与 D06 收口同轮做**。

### 5.3 落地顺序与不改项

```
① A-1/A-2 属性注入 → ② A-3 消除 URL 拼接耦合 → ③ A-4a 去掉 XML 域名绑定
→ ④ A-5 证书脚本联动 + 重签 → ⑤ assembleRelease 出新 APK + SHA256 留档
→ ⑥ 真机/模拟器 E2E（登录→刷题→AI 答疑 + D14 两张 UI 图）→ ⑦ qa-acceptance 复验 C1/D14
```
**本轮明确不做**：改 `build.gradle`、改 XML、改 Java、重签证书、`assembleDebug/Release`、装 APK、启停服务、写库、提交、推送。
