## 6. 环境事故（可复现条目）

### 事故 1：tokenize 阶段段错误（exit 139 / 0xC0000005）

**现象**
- 进程在 `Tokenizing train dataset` 阶段直接消失，Python 无 traceback；Git Bash 显示 `Segmentation fault`、`echo $?` 为 **139**；Windows 事件/退出码为 `0xC0000005`（访问冲突）。
- watchdog 侧表现：日志没有 `done:`，`watchdog.log` 记为 `died at step=?`，随后重启新 attempt。

**触发条件**
- HuggingFace fast tokenizer 默认 `TOKENIZERS_PARALLELISM=true`，Rust 侧多线程与 `OMP_NUM_THREADS`（默认未限）叠加；
- Windows + `transformers` 5.x + 2,156 条样本的 `dataset.map` 并行 tokenize；非确定性，重跑可能不复现。

**规避参数（已生效）**
```bash
TOKENIZERS_PARALLELISM=false OMP_NUM_THREADS=4 \
  .venv-ai/Scripts/python.exe training/train_qlora.py ...
```
`train_watchdog.sh:42` 已固定这两个环境变量。

**复现步骤（用于确认环境）**
```bash
cd "D:/大学生多考试备考知识库与题库系统"
TOKENIZERS_PARALLELISM=true OMP_NUM_THREADS=8 \
  .venv-ai/Scripts/python.exe training/train_qlora.py \
  --model C:/models/models/Qwen--Qwen2.5-3B-Instruct/snapshots/master \
  --train training/data/sft_train_behavior.jsonl --val training/data/sft_val.jsonl \
  --max-length 640 --max-steps 1 --save-steps 1000 --out d:/tmp/seg_repro
echo "exit=$?"
```
判据：命令在 tokenize 进度条中途终止、无 traceback、exit=139/0xC0000005；重复 3–5 次可提高复现概率。若设 `TOKENIZERS_PARALLELISM=false` 后同一命令稳定通过，即可确认归因。

### 事故 2：保存中途卡死，留下无 `trainer_state.json` 的残件

**现象**
- 训练进程卡在 `Saving checkpoint`，目录 `checkpoint-N` 已创建但长时间不再增长；
- 目录里可能已有 `adapter_model.safetensors`、`adapter_config.json`，但 **缺 `trainer_state.json`**；`optimizer.pt` 异常小（286,720 B，正常应 ~61 MB），且无 `scheduler.pt`/`rng_state.pth`；
- 强杀进程后，残件仍留在 run 目录。

**现存证据（本机实例）**
| 目录 | 缺失 | optimizer.pt |
|---|---|---:|
| `training/output/qwen2.5-7b-exam-lora-v3/checkpoint-10` | `trainer_state.json` | 286,720 B |
| `training/output/shortrun_c/checkpoint-4` | `trainer_state.json` | 286,720 B |
| `training/output/shortrun_f/checkpoint-10` | `trainer_state.json` | 286,720 B |

**触发条件**
- 保存过程中被 `Ctrl+C`/kill/断电/磁盘 IO 卡住（Windows 杀毒扫描大文件时更易触发）；
- `save_total_limit` 轮转删除旧目录与写入新目录并发时被打断。

**判定方法（一条命令）**
```bash
d=training/output/shortrun_c/checkpoint-4
for f in adapter_model.safetensors adapter_config.json tokenizer.json chat_template.jinja trainer_state.json; do
  [ -f "$d/$f" ] || echo "MISSING $f"
done
python -c "import json,sys;json.load(open(r'$d/trainer_state.json'))" 2>&1 | tail -1
stat -c '%s %n' "$d/optimizer.pt"
```
判据：`trainer_state.json` 缺失或 JSON 解析失败，或 `optimizer.pt < 1 MB` → 残件。`extract_train_metrics.py` 已把该判断做成 `likely_incomplete` 字段。

**处置**
1. 不要把残件用于 resume 或评测；先 `mv` 到 `quarantine/`；
2. 从**最近一个四件齐全且 trainer_state 可解析**的 checkpoint 续跑；
3. 若没有完整 checkpoint，只能从头重跑（当前正式训练 run 目录为空，符合这种情况）。

**复现步骤**
```bash
# 让保存发生在第 2 步，并在保存瞬间 kill（另开终端）
.venv-ai/Scripts/python.exe training/train_qlora.py   --model C:/models/models/Qwen--Qwen2.5-3B-Instruct/snapshots/master   --train training/data/sft_train_behavior.jsonl --val training/data/sft_val.jsonl   --max-length 640 --max-steps 4 --save-steps 2 --out d:/tmp/save_hang
# 观察 d:/tmp/save_hang/checkpoint-2 出现后立即 kill -9 <pid>
ls -la d:/tmp/save_hang/checkpoint-2   # 预期缺 trainer_state.json、optimizer.pt 很小
```
