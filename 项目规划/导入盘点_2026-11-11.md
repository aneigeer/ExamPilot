### 5.2 自动化能否跑通（具体方案，非空话）

**第 0 步：确认 AI 服务 OCR 的边界**（已知，不需再验证）
- `ai-service` 的 `/v1/ocr` **明确拒绝扫描版 PDF**（错误码 5207「PDF 无文本层，本服务不做 PDF 转图」）；
- 结论：**扫描 PDF 必须先在 Java 侧渲染成图片**再送 OCR，或走 `ocr_courseware.py` 的「docx→页面图→PaddleOCR」路径。

**第 1 步：PDF 文本抽取（A 档，纯文本）**
```bash
# 已验证可用：pypdf 单文件抽全部页文本
.venv-ai/Scripts/python.exe -c "
from pypdf import PdfReader
r=PdfReader(r'D:\题库\【1】国考真题及答案（2000-2026年）pdf\2000-2026国考行测PDF\行测-真题\2000年国家公务员考试《行测》真题.pdf')
print('\n'.join((p.extract_text() or '') for p in r.pages))
"
```
- 必须**子进程隔离**：单进程遍历遇畸形 XRef 会段错误（本次实测 exit 139），建议 `CHUNK=8` 分批 + 超时；
- 依赖：`.venv-ai` 已有 `pypdf==5.1.0`（`ai-service/requirements.txt:49`）。

**第 2 步：题目切分（新增，当前完全缺失）**
- 建议规则（对国考行测已验证文本格式）：
  - 题号：`^\s*(\d{1,3})[.、．]` 且行首无缩进过深；
  - 选项：`^\s*[A-D][.、．]` 连续 3–4 行；
  - 答案块：独立文件（`行测-答案及解析`）按 `^(\d{1,3})\.([A-D])【解析】` 切分，与题目按题号 join；
  - 分节标题：`第[一二三四五]部分` → 映射 `knowledge_point`。
- 产出去向：`question` + `question_option` + `question_answer` + `question_knowledge`，并同步写 `ai_chunk(source_type='QUESTION')`；
- 建议用「干跑 + 抽样人工核对 30 题」的方式验收后再全量。

**第 3 步：扫描件 OCR（C 档）**
```bash
# Java 侧已有 PDFBox 3.0.7，可渲染页面为 PNG（不新增依赖）
# 然后用现有 PaddleOCR 路径（cpu 15s/页，见 ocr_courseware.py docstring）
python ai-service/tools/ocr_courseware.py --list          # 列出纯图片文档
```
- **RTX 4060 + 32GB 是否现实**：现实但慢 —— 现有脚本实测 CPU **约 15s/页**；178 个扫描 PDF 若平均 8 页 ≈ 1420 页 ≈ **5.9 小时**（CPU）；换 `paddlepaddle-gpu` 版可提速 5–10 倍（需安装 GPU 版，属新增依赖，**需你批准**）。
- 注意：`ocr_courseware.py` 只处理 **docx 内嵌图片**，**不处理独立 PDF**；扫描 PDF 需先渲染成图，这一步**尚无脚本**。

**第 4 步：`.doc` 老格式（62 个）**
- 方案：`soffice --headless --convert-to docx --outdir <tmp> <file.doc>`（LibreOffice，需本机已装；**是否已装未确认**），再走 docx 管线。
