### 诚实声明两条边界

1. **①/② 无法用现有证据一刀切**：`ai-service` 日志只记 `arg_keys=` 排序后的键名，**不记模型原始输出**，

   本轮的做法是**两条都堵**（既让解析层不再丢字段，也把必填校验的错误信息写成可照抄的写法），
   而**不**在记录里断言某一条为唯一根因。
   为下一轮可归因，已在 `planner.py:194` 加 `logger.debug("[AgentPlanner] raw decision=%s", raw)`：
   把日志级别调到 DEBUG 即可看到模型逐字输出。
2. **#5 的验收描述需订正**：失败键是 `query`，不是 `page_id`（`page_id` 从未出现在 54 次调用里）。
   订正不影响「该工具 schema 与模型认知不匹配」这个结论。

### 3.3 `ai-service/app/agent/harness.py` —— **未改**，理由（可核验）

「必填校验 + 明确错误回喂、不静默用默认值」这条要求**在现有结构下已经满足**，再加一层会重复：

- 必填校验先于 Java：`tools.py:67-89`（`_validate_arguments`）→ `ToolRegistry.execute:147-151`
  `except ArgumentError → ToolResult(ok=False, summary=f"参数错误：{exc}")`，Java 零调用
  （新测试 `test_empty_arguments_fail_fast_without_touching_java` 断言 `bridge.calls == []`）。
- 明确回喂：`harness.py:376-379` 判 `PARAM_ERROR` → `:396-406` 发 `tool_result`
  → `:407-415` 写入 `observations` → 下一轮 `build_context` 进 prompt。本轮把这段 summary 从
  「questionId 必须是正整数」改成「…（必填参数：questionId；正确写法：{"questionId": 12}）」，
  回喂内容即变具体，**无需新增事件**。
- 不静默用默认值：`_search` 里 `args.get("query") or ctx.question` 的兜底在 `_validate_arguments`
  之后，空 `query` 已被拦，该兜底在合法路径上不可达；`_clamp_int` 只 clamp **可选**数值参数。

若为了「让用户也看到为什么失败」而在 `harness._agent_loop` 里额外 yield 一条 `thought`，
会改变 SSE 事件序列（Java/前端按事件类型消费，`test_agent_trace_stream.py` 有序列断言），
**收益不足、回归面偏大**，故本轮不动。

## 4. prompt / schema 改动前后对比

**A. `get_wiki_page`（对应失败 #5）**

```
改前  - get_wiki_page：按页面 ID 读取 Wiki 主题页正文与关联页（先用 search_wiki 拿到 ID）。 参数：pageId: int，必填
改后  - get_wiki_page：按页面 ID 读取 Wiki 主题页正文与关联页。只接受 pageId（整数，取自 search_wiki
      返回的 pageId）；本工具**不接受 query**，想按关键词找页面请改用 search_wiki。
      参数：pageId: int，必填，Wiki 页面 ID（正整数），取自 search_wiki 返回的 pageId
```

**B. `get_question`（对应失败 #2 #1 #3）**

```
改前  - get_question：按题目 ID 读取题干、选项与解析。 参数：questionId: int，必填
改后  - get_question：按题目 ID 读取题干、选项与解析。questionId 只能取自 search_knowledge 或
      错题本返回的题目 ID，禁止编造。 参数：questionId: int，必填，题目 ID（正整数），取自工具返回结果
```

**C. `search_knowledge` / `search_wiki`（对应失败 #4）**

```
改前  query: string，检索语句（尽量保留学生原话中的关键词）      | query: string，检索语句
改后  query: string，必填，非空检索语句（尽量保留学生原话中的关键词） | query: string，必填，非空检索语句
```

**D. SYSTEM_PROMPT 新增（规则 8，对应 #1–#5）**

```
8. 【工具参数】参数必须写在 arguments 里且是 JSON 对象；标了「必填」的参数不能省略、
   不能改名（pageId 不能写成 query）、不能编造——ID 只能取自工具返回结果。
```

**E. SYSTEM_PROMPT 新增（示例 3，对应 #2 #5）**

```
示例 3（按 ID 取详情，键名与工具参数完全一致）：
{"thought":"资料给出题目 ID 2，取题干","action":"tool","tool":"get_question","arguments":{"questionId":2}}
{"thought":"需要 Wiki 页面正文","action":"tool","tool":"get_wiki_page","arguments":{"pageId":12}}
```

**F. 参数错误文案（回喂给模型，对应 #1 #3 #4 #5）**

```
改前  参数错误：pageId 必须是正整数
改后  参数错误：pageId 必须是正整数（必填参数：pageId；正确写法：{"pageId": 12}）

改前  参数错误：query 必须是非空字符串
改后  参数错误：query 必须是非空字符串（必填参数：query；正确写法：{"query": "C语言 int 占几个字节", "topK": 5}}

改前  参数错误：questionId 必须是正整数
改后  参数错误：questionId 必须是正整数（必填参数：questionId；正确写法：{"questionId": 12}）
```

**成本核算（诚实记账，实测非估算）**

```text
tool_catalog_text()  改前 558 字符 → 改后 741 字符（+183）
SYSTEM_PROMPT        改前 1287 字符 → 改后 1784 字符（+497，约 +330 token）
```

系统提示词每轮规划都发。`AGENT_MAX_PROMPT_CHARS=8000` 只约束**用户侧** prompt，不受影响；
但本机模型窗口 4096 token（日志 14:32:03 曾出现 `request (7185 tokens) exceeds ... 4096`）。
**基线对照（复测必须一起看）**：本轮 50 条里 `LLM 规划不可用`（回退规则规划器）共 **12 次**，
构成实测为：`模型输出 JSON 解析失败` **9 次**（`Unterminated string` 3 次，列号 78/84/98；
`Expecting ':' delimiter` 3 次，列号 107/108/306；`无法定位完整对象` 3 次）+ `非法 action：` 空值 **3 次**。
复测时若该计数**超过 12**，应首先怀疑本次 +497 字符的提示词增量挤占了窗口，
处置办法是把「示例 3」压到一行或删掉 `get_wiki_page` 那句描述——这是本轮唯一的负面风险点。
