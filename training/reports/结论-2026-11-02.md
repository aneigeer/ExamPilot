# 7B 垂直微调结论（2026-11-02）

> **⚠️ 2026-11-03 更正：本文结论作废。**
> 经核验，`training/output/qwen2.5-7b-exam-lora/` 下的 adapter 是 **10:55 的冒烟产物（5 步 / 20 条样本）**，
> 全量训练（11:00–12:15，100 步）的保存没有落盘。
> 因此 `exam-prep-7b` = 基座 + 5 步增量 + Q4_0 量化，**不是 100 步模型**。
> 本文所有对比数字（+16.7pp 等）同时受「抄选项送分」判分漏洞与「训练题污染」影响，全部作废。
> 独立验收（qa-acceptance）测得的 -41pp 引用退化，同样只适用于这个 5 步产物。
> 结论：**当前没有任何一次完整训练的模型被评测过。**

## 1. 做了什么

- 基座：Qwen2.5-7B-Instruct（bf16 原始权重）
- 方法：QLoRA（r=16 / alpha=32，覆盖 q/k/v/o/gate/up/down），4bit NF4 + 梯度检查点 + paged 8bit 优化器
- 数据：项目自有题库/语料/wiki，共 4,257 条；训练取 1,600 条分层样本
- 训练：100 步 / 约 66 分钟（RTX 4060 Laptop 8GB）
- 产物：LoRA 适配器 78MB → 合并 → F16 GGUF → 自写量化器转 Q4_0 → Ollama 模型 `exam-prep-7b`（4.3GB）

## 2. 同集对比（120 条，temperature=0，Ollama 推理）

| 指标 | 基座 `qwen2.5-7b-instruct-baseline` (Q4_K_M) | 微调 `exam-prep-7b` (Q4_0) | 变化 |
|---|---|---|---|
| 单选题准确率 | 56.2% (27/48) | **72.9% (35/48)** | **+16.7pp** |
| 引用合规（有资料必标 [1]） | 70.4% (19/27) | 29.6% (8/27) | **-40.8pp** |
| 拒答纪律（以「未找到相关资料」开头） | 70.8% (17/24) | 58.3% (14/24) | -12.5pp |
| planner JSON 合法率 | 100% (12/12) | 75.0% (9/12) | -25.0pp |
| 抗注入（语料内指令不执行） | 100% (9/9) | 100% (9/9) | ±0 |
| 平均延迟 | 8.69s | 9.46s | +0.77s |

## 3. 判断

**微调确实注入了领域解题能力（+16.7pp），但同时破坏了格式纪律（引用 -40.8pp、JSON -25pp）。**

这是典型的「行为覆盖不完整」：训练数据里 `mcq` 样本不带引用、`grounded` 样本的引用只出现在固定位置，
模型学到的是「解题」而不是「按站内规范作答」。而 Agent 主链路依赖 ①引用 ②严格 JSON 协议，
这两项退化会直接让线上回答不可溯源、规划解析失败。

**结论：不上线。** 当前 `exam-prep-7b` 仅作为实验产物保留，`.env` 不做任何切换。

## 4. 若要继续，按这个顺序改

1. **统一目标格式**：所有回答类样本一律「答案 → 依据[1]」，`mcq` 也带引用；无引用的样本直接丢弃。
2. **planner 样本翻倍**：JSON 合法率必须 ≥ 基座（100%），否则 Agent 会解析失败。
3. **同量化等级比较**：本次微调是 Q4_0(4.0bpw)、基座是 Q4_K_M(4.5bpw)，对微调不利；下次两边同 Q4_0 或同 Q4_K_M。
4. **加大行为样本**：`refusal`+`injection` 至少各 800 条，`mcq` 压到 20% 以下。
5. **评测集扩容**：本次 120 条、每类 9–48 条，置信区间很宽；下一轮至少 300 条。
