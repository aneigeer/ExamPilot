# 大学生多考试备考知识库与题库系统（Enterprise AI Agent Edition）—— 完整全景大纲

> 版本：`v2.0-enterprise` | 更新日期：`2026-11-22`
> 架构定位：Android 原生学生端 + Web 学生端/管理端 + Spring Boot 3.5.3 (JDK 21) + FastAPI AI 微服务 + Qdrant 向量库 + Redis Stream 异步队列 + 现代 9 模块企业级 AI Agent 架构（支持本地 Ollama 7B 与云端 API 双模一键切换）。

## 一、系统总体架构大纲

### 1.1 五层架构拓扑
1. **多端表现层**
   - Android 原生学生端（Java + XML，36 个页面：32 Activity + 4 Fragment，支持登录前与登录后运行时切换服务器地址）
   - Web 学生端（`/api/student/index.html`，同源托管，免构建）
   - Web 管理与 AI 运维中台（`/api/admin/index.html`，Vue 3 + Element Plus 同源托管）
2. **接入与安全网关层**
   - Nginx 反向代理（80/443 TLS 入口、`/api/ai/agent/stream` SSE 流式零缓冲穿透、`/api/run` 代码执行双重硬封禁、安全响应头）
   - Spring Security + JWT 认证 + RBAC 角色隔离（`STUDENT` / `AUDITOR` / `ADMIN`）+ 可信代理子网 IP 限流分桶 + `AiQuotaService` 每日 Token/请求配额闸门
3. **Java 业务与 AI 治理中台（Spring Boot 3.5.3 / JDK 21，`:8080`）**
   - 基础业务域：考试体系、高校教学计划、资料库治理、题库与刷题、错题本、SRS 间隔重复、全真模考、双轨测评中台、数据中台
   - AI 业务域：`AiQaService`（Wiki 热层 + Hybrid RAG 冷层双引擎问答）、主观题 AI 判分、个性化学习计划、AI 模拟面试
   - Agent 治理域：`AgentStreamService`（SSE 流式状态机）、`AgentCheckpointService`（中断恢复 + HITL 人工审批）、Wiki 信任分级与自动标旧、5 层离线评测与发布门禁、`OperationLog` 合规审计、Prometheus 指标导出
   - 双模 LLM 适配层：`OpenAiCompatLlmClient` / `DashScopeLlmClient` / `ZhipuLlmClient` / `OllamaLlmClient` / `FastApiLlmClient` / `ExtractiveAnswerClient`
4. **Python AI 微服务（FastAPI，`:8000`）**
   - Agent Runtime 执行循环 + Context Engine v2（大观察落盘 Artifact + 分段读取 + 三段式压缩）
   - Router 句向量意图路由 + `SKILL.md` 渐进式技能加载 + 标准 MCP 工具服务 + 受控 Subagent 多子问题拆解
   - `bge-small-zh-v1.5`（ONNX INT8，512 维）向量化 + Qdrant 检索重排 + PaddleOCR 试卷识别
   - Redis Stream 异步消费组 Worker（`exam:jobs` / `exam:eval` / `exam:wiki`）
5. **存储与可观测基础设施**
   - MySQL 8.0（65 张表，30 份幂等迁移脚本，含 `ai_chunk` ngram 全文索引）
   - Qdrant Server（`:6333`，`exam_chunks` 97,252 条向量切片 + `status / source_type / subject_id / knowledge_id` 4 类 Payload 索引 + `wiki_pages` 索引）
   - Redis 7（`:6379`，AOF 持久化 + Stream 消费组 `expert-workers`）
   - Prometheus + Grafana + Jaeger（OTLP 4317/4318）+ 5 条 PromQL SLA 告警规则

## 二、三端业务功能大纲

1. **认证、权限与动态环境切换**

   - 登录页与「我的 → 服务器地址」动态切换后端 API 地址（切服后自动清 Token 并跳转重登）
2. **多考试体系与高校教学计划**
   - 覆盖大学课程考试、四六级（CET-4/6）、考研、国考行测、AI/计算机技术面试
   - 内置中南林业科技大学 23 个学院、信息与计算科学专业 90 门课程教学执行计划与知识点树
3. **资料库与课程课件学习**
   - 资料上传（自动验签文件头防伪造）、分页在线预览、下载计数、收藏、点赞、星级评分、评论互动、违规举报与申诉
   - 497 份课程课件（含操作系统 PPT 逐页切片与纯图片课件 OCR 切片）检索与页码精准回跳
4. **题库刷题、错题本、SRS 与全真模考**
   - 按考试品类/科目/知识点/题型/真题年份筛选刷题、作答解析、题目个人笔记、题目收藏
   - 错题本自动收录与掌握度标记、SRS 间隔重复复习调度（按遗忘曲线计算下次复习时间）
   - 全真限时模考与双轨测评（自动抽题组卷、倒计时交卷、客观题即时判分 + 主观题 AI 要点判分、薄弱知识点诊断画像）
5. **AI 智能备考五大核心场景**
   - **AI 导学问答（`POST /api/ai/ask`）**：Wiki 热层优先命中秒回 + RAG 混合检索兜底；强制 `[n]` 来源编号引用与资料/题目/课件卡片跳转；域外无关问题秒拒
   - **AI Agent 多步助教（`POST /api/ai/agent/stream`）**：SSE 流式呈现思考、工具调用、观察结果与最终回答；支持查知识库、查个人薄弱点、抽配套练习题、生成复习计划；支持断连检查点恢复与高风险操作 HITL 审批
   - **主观题 AI 判分（`POST /api/ai/grade`）**：按参考答案拆解编号要点，输出命中点、遗漏点、四档评级（`EXCELLENT / GOOD / PARTIAL / POOR`）与得分率（`completeJson` + `JsonOutputRepair` 零降级）
   - **个性化学习计划（`POST /api/ai/study-plan`）**：基于用户错题 ID 与薄弱知识点生成分日可执行计划（100% 校验真实错题 ID，零幻觉）
   - **AI 模拟面试（`/api/ai/interview/**`）**：基于 68 份真实面试语料检索改写出题、要点级评分、同题追问合并重评（防刷分）、多题复盘报告与历史记录回看

### 2.2 审核员与管理员端功能闭环（Web 管理中台）

## 三、企业级 9 模块 AI Agent 架构深度大纲

### 模块 1：Agent Runtime 执行循环
- **显式状态与预算控制**：把目标、步骤（`max_steps=6`）、工具调用次数（`max_tool_calls=4`）、Prompt 字符预算（`8000`）与完成条件建模为显式状态。
- **检查点持久化与中断恢复**：每步 `thought / tool_call / tool_result` 实时写入 `ai_agent_checkpoint`；异常断连或超时后可调用恢复接口从最后成功步继续，不丢失已完成工具结果。
- **异步任务幂等键**：`async_task` 表支持 `idempotency_key` 唯一约束，重复提交命中 `PENDING / RUNNING / SUCCESS` 直接返回原任务，防止网络重试导致重复入队与重复计算。

### 模块 2：Context Engine v2 上下文引擎
- **大观察自动落盘（Artifact Offload）**：单次工具返回超过 `600` 字符时自动落盘至 `runtime/agent_artifacts/<safe_trace_id>/<16hex>.json`（24h TTL 自动清理），Prompt 上下文内仅保留 `240` 字预览、`artifact_id` 与总长度。
- **按需分段只读（`read_artifact`）**：内置 `read_artifact(artifact_id, offset, limit)` 工具，严格校验当前 `trace_id` 归属与 16 位 hex 正则，彻底阻断跨会话读取与路径穿越（`../`）。
- **三段式结构化压缩**：历史消息超字符预算裁剪时，自动抽取并置顶保留【已确认结论】【关键证据引用（chunk/question id）】【下一步待办】三段式结构块。

### 模块 3：Hybrid RAG 混合检索层
- **双通道召回**：Qdrant 服务端 **97,252** 条 512 维向量语义召回 + MySQL `ai_chunk` ngram 全文字面召回。
- **服务端 Payload 索引加速**：服务端模式自动幂等创建 `status`、`source_type`、`subject_id`、`knowledge_id` 四类索引，97,252 全量切片下带 `status=ACTIVE` 过滤检索 **P50 = 14.36 ms**（较本地文件模式 `752.33 ms` **提速 52.4×**）。
- **五因子重排与三道反幻觉拒答闸门**：融合语义分、标题命中、用户薄弱知识点加权、时间衰减与热度；联合判定词法实词覆盖度（`min-content-coverage=0.45`）、向量语义拒答线（`semantic-reject-score=0.62`）与能力边界越界词表。

### 模块 4：LLM Wiki 知识治理层（对齐 OKF v0.3）
- **四级信任分级（`trust_tier`）**：`VERIFIED`（人工审核发布）> `AUTO_DISTILLED`（自动蒸馏草稿）> `STALE_REVIEW`（底层来源已变更待复核）> `RETIRED`（人工或规则退役）。
- **来源哈希自动标旧（`source_hash`）**：Wiki 发布时对引用的全部 `ai_chunk.content_hash` 排序计算聚合 `SHA-256`；当底层题目/资料更新或下架触发 `ChunkSyncService.invalidateSource` 时，自动将关联 Wiki 页降级为 `STALE_REVIEW`。
- **热层与全文检索双重硬拦截**：`WikiQueryService.servingAllowed` 与 SQL 全文检索同步拦截 `RETIRED`、`STALE_REVIEW` 及 `expires_at < NOW()` 的过期页面，自动回退至 RAG 冷层检索最新切片。

### 模块 5：Decision 语义路由层
- **轻量句向量路由（`/v1/route`）**：基于 `bge-small-zh` 原型句余弦相似度分类（耗时 4–20 ms，不消耗大模型调用），按意图分流 `COURSE_QA`、`WRONG_BOOK_REVIEW`、`STUDY_PLAN` 等技能并按 `source_type` 硬过滤检索范围。
- **双阈值校准与 RSI 自改进**：同时卡绝对置信度与 Top1-Top2 间隔；支持基于评测失败样本自动生成候选原型并通过四道回归闸门（训练集/留出集/域外拒答/零危险误判）。
- **零风险降级与 A/B 实测决策**：Java `AiRouteClient` 设 300 ms 硬超时，超时或关闭时 0 异常回退默认路由；基于实跑 A/B 报告保持 `app.ai.route.enabled=false` 默认关闭、按需灰度开启。

### 模块 6：Memory 与多级任务状态
- **用户学情画像（按 `userId` 严格隔离）**：融合答题正确率、难度系数、错题频次上限与 30 天半衰期指数衰减，动态计算薄弱知识点。
- **会话短期记忆与长期事实记忆（LTM）**：会话级多轮历史自动校验 `userId` 归属（跨用户访问 403）；长期记忆与执行检查点、共享 Wiki 分表分权限存储。

### 模块 7：Tools、声明式 `SKILL.md`、MCP 与 HITL 人工审批
- **声明式 `SKILL.md` 渐进式加载**：技能定义存放于 `ai-service/app/skills/<SKILL_NAME>/SKILL.md`（YAML frontmatter 声明 `name / description / allowed_tools / source_types`）；启动仅加载轻量目录摘要，路由命中后再按需注入 Markdown 正文。
- **标准 MCP 工具协议**：通过 `ai-service/app/mcp/server.py` 暴露标准 `list_tools()` 与 `call_tool()`，与 `AgentHarness` 共用同一份 `ToolRegistry` schema 与权限校验。
- **完整 HITL（Human-in-the-Loop）挂起与审批恢复闭环**：
  - 工具携带 `risk_level`（`READ / WRITE_LOW / WRITE_HIGH`）与 `requires_approval` 元数据；
  - 命中高风险未审批工具时，Python 生成一次性 `approvalToken`，发送 `approval_required` SSE 事件与 `done(waitingApproval=true)`；
  - Java 落库 `WAITING_APPROVAL` 检查点（不含任何 PII）并将 Run 置为 `WAITING_APPROVAL` 释放并发槽；
  - 用户或管理员调用 `POST /api/ai/agent/runs/{id}/approve`：经归属校验（403）、状态校验（409）、常量时间 Token 比对（409）与数据库条件更新原子幂等防重放（409）后，批准则注入 `approvedTools` 白名单恢复执行新 Run，拒绝则置为 `CANCELLED`。

### 模块 8：Verifier 机械验证与受控 Subagent
- **机械验证优先**：`AnswerPostProcessor` 正则校验并剥离越界 `[n]` 引用编号；学习计划生成器强制对照候选错题 ID 集合做 100% 真实性校验；`AbstractOpenAiCompatLlmClient.completeJson` + `JsonOutputRepair`（去围栏/截断提取/括号配平/去尾逗号 + 最多 1 次纠正重试）将主观题判分 JSON 降级率压至 **0.0%**。
- **受控 Subagent 实验路径**：开启 `AGENT_SUBAGENT_ENABLED` 时执行「问题拆解 → 逐子问题检索 → 综合汇总」，所有子问题**严格共享同一个父级 `ToolBudget` 与 `StepBudget`**（防止成本成倍爆炸）；实测复合题平均召回来源数从 `0.88` 提升至 `2.0`（**+127%**）。

### 模块 9：Tracing、5 层评测飞轮、配额与可观测性
- **全链路 Trace 与 OTel GenAI Span**：16 位小写 hex `X-Trace-Id` 贯穿 Nginx → Java MDC → Python ContextVar → MySQL `ai_agent_run`；内置 `gen_ai.chat` 与 `agent.tool` OpenTelemetry Span 埋点（严格白名单属性，零密钥/零原文泄露，未装 SDK 时自动 NoOp 降级）。
- **真实 Token 与成本核算**：解析上游 `usage`（缺失时按字符估算并标记 `estimated=true`），按 Run 累加落库 `model_name / prompt_tokens / completion_tokens / total_tokens / estimated_cost_cny`。
- **5 层离线评测门禁与数据飞轮**：覆盖 `RETRIEVAL`（214 条）、`AGENT`（120 条）、`REFUSAL`（40 条）、`GRADING`（20 条）、`STUDY_PLAN`（6 条）五层硬门槛；支持管理端将线上失败 `ai_agent_run` 一键脱敏导出为回归评测候选。
- **每日配额防刷与合规审计**：`AiQuotaService` 拦截超额请求返回 429；`OperationLogService` 记录全部高危 AI 治理操作审计日志；双端暴露 Prometheus `/metrics` 指标并配套 5 条 SLA 告警规则。
