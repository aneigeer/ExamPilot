## 3 技术亮点

1. **全题型统一模型**：题目表 type 区分 + 答案表 MySQL JSON 承载（按题型不同结构），避免大宽表；统一 JudgeService 按题型分派判分
2. **组合题父子结构**：parent_id 关联子题，创建自动生成、详情父子返回、逐子题判分
3. **防盗三件套**：PDFBox 转图分页预览（游客 3 页低清/登录整本高清）+ 因人而异水印（学号平铺）+ 短时效 HMAC 签名下载
4. **审核状态机**：含申诉出口的完整状态机（DRAFT→…→APPEALING→恢复/维持）+ 审核员自我回避（4001）
5. **四级权限**：PUBLIC/AUTH/ROLE 三级标注，SecurityConfig 集中白名单 + 方法级 @PreAuthorize，逐接口校验
6. **推荐排序 + 评分下沉**：加权 =（下载量×2 + 有效评分×min(人数,5)）/（发布天数+7），评分人数<3 不计权重
7. **编程题在线运行**：受控子进程（gcc / JDK 单文件运行），超时强杀 + 临时目录清理 + 期望输出比对
8. **App 工程化**：命令行完整构建链（Gradle 8.7 + AGP 8.5.2）、ViewBinding、图片采样压缩上传、答题卡、草稿保存、未读角标
9. **管理端零部署**：Vue3 单页应用由后端同源托管，静态页白名单 + API 角色校验分离

## 4 质量保障

- 单元测试：JudgeServiceTest 12 用例（P0 五题型判分）全部通过
- 端到端测试：8 套 Python 脚本覆盖刷题/资料/评论/水印/P0-B/P1 全链路，全部通过
- 权限测试：四级角色越权矩阵 + 匿名白名单 + 自我回避，全部符合预期

## 5 遇到的主要问题与解决

| 问题 | 解决 |
|---|---|
| 中文项目路径导致 AGP 构建失败 | 官方开关 android.overridePathCheck=true |
| 23 种题型答案结构差异大 | 答案表 JSON 字段按题型承载（大纲 13.4） |
| 游客接口全线 401 | 先定匿名白名单再联调（SecurityConfig 集中声明） |
| javac GBK 输出导致错误信息乱码 | iconv 转码后解析 |
| 匹配题用户答案误走 JSON 解析器 | 文本格式（A:1,B:3）专用解析，兼容 = 与全角冒号 |
| 跨 Activity 传对象崩溃 | 报告类 POJO implements Serializable |
| 上传 UI 入口两端缺失（自审发现） | App 图片上传页 + 管理端文档上传页双入口补齐 |

## 6 不足与展望

- **不足**：评分下沉与推荐排序为简化加权算法；编程题运行为本机沙箱（公网需独立判题机）；管理端未用 Vite+TS 构建（CDN 单页，功能等价）；性能 P95 数据需在本机正式环境回填
- **展望（P2）**：MinIO 对象存储、Redis 缓存、ECharts 可视化增强、个性化推荐、AI 辅助判分、教务系统对接
