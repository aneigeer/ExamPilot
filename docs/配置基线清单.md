## 0. 摘要：当前实际生效的是什么

### 0.1 三套 profile 的生效组合

| 能力 | 无 profile（纯默认） | `local` | `prod` |
|---|---|---|---|
| 大模型 | **Ollama 本地 7B** | Ollama 本地 7B | 同左（Q 不涉及 llm） |
| 向量通道 | **关**（`vector.enabled=false`） | **开** | 同默认=**关** |
| FastAPI 通道 | **关**（`fastapi.enabled=false`） | **开** | 同默认=**关** |
| 语义闸门 | **不生效**（依赖向量通道） | **生效** | **不生效** |
| 语义路由 | **关** | **关** | **关** |
| Agent | **关** | **关** | **关** |
| 对象存储 | **关**（纯本地盘） | **关** | **关** |
| 异步任务/蒸馏 | **关** | **关** | **关** |
| Wiki 热层 | **开** | **开** | **开** |

> **一句话**：默认是「纯离线 + 字面检索 + 抽取式兜底」；`local` 额外打开向量与语义闸门；`prod` **只改日志与 SQL 打印，不改任何 AI 行为**。

### 0.2 三条最重要的结论（都可 grep 复核）

1. **`app.ai.route.enabled` 目前是"死开关"**：`AiRouteClient` 已是 `@Component`（`AiRouteClient.java:44`）且单测齐全，但**主代码中无任何注入/调用点**（`grep -rn "AiRouteClient" backend/src/main` 只命中 `AiProperties.java:35` 的 javadoc）。把 `enabled` 改 `true` **当前不会产生任何行为变化**。
2. **`app.ai.llm.provider` 不能让 Ollama 让位给云端**：`OllamaLlmClient.available()` 只调 `super.available()`（`OllamaLlmClient.java:110-112`），**不校验 provider**；而 DashScope/Zhipu 都校验（`DashScopeLlmClient.java:38-40`、`ZhipuLlmClient.java:33-35`）。叠加 `@Order(5)` 最小 → Ollama 可达时**永远优先**。
3. **`internal-token` 为空时是 fail-closed**：`InternalTokenFilter.java:39` 判空即拒，`/internal/**` 一律 403，不是放行。

### 2.2 需要特别提醒的行为差异

1. **`prod` 继承默认的 `fastapi.enabled=false`** —— 意味着**生产若直接 `--spring.profiles.active=prod`，向量检索与语义闸门都不生效**，拒答只剩词法闸门。若生产要开向量，**必须额外显式设 `AI_SERVICE_URL` 之外再打开 `fastapi.enabled`/`vector.enabled`**（这两个键**没有环境变量占位**，只能改 yml 或加 `--app.ai.vector.enabled=true` 启动参数）。
2. **`local` 打开向量但开发机没起 AI 服务时不会误拒**：`vectorChannel.isReady()=false` → 自动跳过语义闸门，退回词法判定（`L:31-32` 注释亦说明）。
3. **`prod` 不覆盖任何 `app.ai.*`** —— 也就是说 **prod 的 AI 行为 = 默认离线行为**，与 local 差异全部集中在向量/FastAPI 两个开关上。

## 4. 已知坑（按踩坑时间排序）

### 4.1 `min-term-coverage` 代码/yml 漂移（**已修**）

| 项 | 内容 |
|---|---|
| 症状 | 代码默认 `0.25`、yml `0.5`；**未加载 yml 的 profile/单测跑在另一套闸门上** |
| 影响 | 同一份代码在不同环境拒答率不同；单测通过≠生产正确 |
| 修复 | **`fce493d`**：代码默认改为 `0.5` 与 yml 对齐 |
| 护栏 | `AiConfigConsistencyTest`（`backend/src/test/java/.../AiConfigConsistencyTest.java`）：断言 yml 必须显式声明且生效值==代码默认 |

### 4.2 `semantic-reject-score` / `min-content-coverage` 曾只在代码里（**已修**）

| 项 | 内容 |
|---|---|
| 症状 | 阈值不可见、不可审计，调参要改代码 |
| 修复 | **`fce493d`**：`application.yml` 补 `semantic-reject-score: 0.62`（Y:240）与 `min-content-coverage: 0.45`（Y:229），并注明"唯一语义防线"与"语料扩容需重标" |
| 护栏 | 同上 `AiConfigConsistencyTest`（含取值范围断言） |

### 4.3 `SERVER__PORT` 会被宽松绑定成 `server.port` 抢占端口

| 项 | 内容 |
|---|---|
| 机制 | Spring 的 relaxed binding 对环境变量做宽松匹配：`SERVER__PORT`（双下划线）会被归一到 `server.port` |
| 症状 | 明明 `Y:2` 写的是 `port: 8080`，进程却在别的端口起来（或报端口占用） |
| 排查 | `env | grep -i "SERVER"`；启动日志的 `Tomcat started on port(s)` |
| 规避 | 不要用形如 `SERVER__PORT` 的变量；要覆盖端口用 **`SERVER_PORT`**，或 `--server.port=` |

### 4.4 Spring 集成测试会加载 classpath yml，`new AiProperties()` 不会

| 项 | 内容 |
|---|---|
| 症状 | `@SpringBootTest` 里读到的是 yml 生效值；而单元测试直接 `new AiProperties()` 读到的是**代码默认值** |
| 风险 | 两者不一致时，单测"绿"但生产行为不同（4.1 的成因） |
| 规避 | 需要校验"生效值"就用 `@SpringBootTest`；只想测逻辑就用 `new`，但**不得据此断言阈值**。`AiConfigConsistencyTest` 是专门的护栏 |

### 4.5 内部令牌只配一端的症状是 401

| 项 | 内容 |
|---|---|
| 症状 | Python 调 Java `/internal/**` 返回 **401/403**，或 Java 调 Python 被拒 |
| 根因 | 两端 `AI_INTERNAL_TOKEN` 不同值，或一端未配（Java 侧 fail-closed → 403） |
| 排查 | ① Java：`InternalTokenFilter.java:37-41`；② Python：`config.py:214`、`JavaBridge` 头 `X-Internal-Token` |
| 已有记录 | **`cfd63b0`** 部署文档已写明"两端必须同值，单端配置症状为 401" |

### 4.6 【本轮新发现】`index-timeout-millis` 代码 5000 / yml 60000

| 项 | 内容 |
|---|---|
| 事实 | 代码默认 `5000`（**P:307**），yml 配 `60000`（**Y:297**） |
| 后果 | 未加载 yml 的环境（单测、`new AiProperties()`）按 5s 判超时；而 yml 注释（Y:294-296）明确说 5s 会**误判成功推送为超时** |
| 风险等级 | 中——目前 `AiConfigConsistencyTest` **未覆盖此键**，属护栏缺口 |
| 建议 | 二选一：把代码默认改为 `60000`，或把该键纳入 `AiConfigConsistencyTest`。**本轮不改代码**，仅记录 |

### 4.8 【本轮新发现】`application.yml:155` 注释与实现不符（provider 语义）

| 项 | 内容 |
|---|---|
| 注释说 | 「provider 只影响日志与展示，**实际选路由 @Order + available() 决定**」 |
| 实现是 | `DashScopeLlmClient.java:38-40` 与 `ZhipuLlmClient.java:33-35` 的 `available()` **都校验 `PROVIDER.equalsIgnoreCase(getProvider())`**；而 `OllamaLlmClient.java:110-112` **不校验** |

| 风险 | 想切云端却切不过去，且按注释排查会走错方向 |
| 建议 | 修正该注释；若要"强制云端"，需停掉 Ollama 或给 Ollama 加 provider 判定。**本轮不改** |
