## 1. 系统总览

### 1.1 产品定位

面向大学生的**多学科备考平台**：题库练习 + AI 答疑 + 知识库检索 + 智能组卷 + 面试演练。
核心差异点在「AI 必须依据知识库作答并给出来源」，不允许模型自由发挥。

### 1.2 角色与场景

| 角色 | 主要场景 | 入口 |
|---|---|---|
| 学生 | 刷题、看解析、问 AI、查知识库、模拟面试 | Android App |
| 教师/管理员 | 题库维护、知识库灌入、AI 调用监控 | 管理端网页 |
| 运维 | 服务健康、降级开关、模型切换 | 管理端 + Nginx |

### 1.3 技术栈

## 5. 微调子系统

### 5.1 为什么做

线上 AI 答疑有三个硬问题（全部来自真实 badcase）：

1. **不引用**：回答正确的知识点但不给来源，学生无法核对；
2. **该拒答时瞎编**：资料里没有的内容，模型照样编；
3. **格式不稳**：Agent 需要 JSON 协议输出，模型偶尔返回散文。

目标：让 7B 本地模型稳定做到「有据必引、无据必拒、协议必合法」，从而把在线 API 调用降下来。

### 5.2 数据构造

生成脚本：`training/build_dataset.py`（读 MySQL → 7 类样本）。

| kind | 作用 | 全量训练集 | 行为子集 |
|---|---|---|---|
| `mcq` | 纯选择题（无资料，考解题） | 1,483 | 178 |
| `grounded` | 给资料作答 + 必带 `[1]` | 925 | 209 |
| `injection` | 资料中夹带攻击指令，必须忽略 | 709 | 593 |
| `refusal` | 资料与问题无关，必须拒答 | 745 | 600 |
| `planner` | Agent 规划 JSON（tool 241 / final 250） | 804 | 491 |
| `wiki` | 知识库问答 | 43 | 43 |
| `citation` | 多来源引用 | 42 | 42 |
| **合计** | — | **4,751** | **2,156** |

> 上表为 2026-11-04 第 2 周重建后的冻结值（F2 修复版）。旧版（2,110 条，planner final 158 条含无关 chunk 与省略号）已归档在 `backup/2026-11-04/`。
> 与旧版相比：planner final 由 158 → 250（改为材料驱动的合成任务），非 planner 样本逐字未变。

**三套 system prompt 分流**（按 2,156 条行为子集三分）：

| 分组 | 条数 | system 特征 | 用途 |
|---|---|---|---|
| `mcq` | **178** | 无资料版（含「如果没有【资料】」） | 纯解题，允许模型用自身知识 |
| 回答类（grounded/refusal/injection/citation/wiki） | **1,487** | 资料约束版（「严格遵守资料」「无据答未找到相关资料」） | RAG 答疑 |
| `planner` | **491** | 规划专用（JSON 协议，`action=tool/final`） | Agent 规划 |

- 三个分组互斥且完备：178 + 1,487 + 491 = **2,156**，无遗漏；
- 审计实测：回答类内部覆盖 1,487/1,487 = 100%，对行为子集覆盖 1,487/2,156 = 69.0%；**串味 0**；
- 旧表述「其余用资料约束版」不准确——它把 planner 也归进了回答类，已按上表更正。

行为优先子集：`training/mix_behavior.py` 从全量 4,751 条中抽出 **2,156 条**（占 45.4%），其中行为类（grounded/injection/refusal/planner）占 87.8%，写入 `sft_train_behavior.jsonl`。

### 5.3 训练配置

| 项 | 值 |
|---|---|
| 基座 | Qwen2.5-7B-Instruct（safetensors，本地快照） |
| 方法 | QLoRA（4bit NF4 + LoRA） |
| LoRA | r=16，alpha=32，target 含 q/k/v/o/gate/up/down |
| 优化器 | paged_adamw_8bit，lr=3e-4，cosine |
| 批次 | batch=1 × 累积 8，max_len 512–640 |
| 硬件 | RTX 4060 Laptop **8GB**，torch 2.6.0+cu124 |
| 步数 | 计划 50 步（约 800 条样本，38% 一个 epoch） |

**硬件约束（重要）**：8GB 显存下 7B QLoRA 已接近上限。实测 max_len=640 时显存占 7.8/8.2GB，触发 Windows 共享内存回退，**步速从 60s 劣化到 195s**；max_len=512 才有余量。

### 5.4 导出链

```
LoRA adapter → merge_lora.py（CPU 合并）→ F16 GGUF（tools/llama/conv_b6000.py）
            → Q4_0 GGUF（tools/quantize_gguf.py）→ ollama create → 服务端 .env 切换
```

已知限制：
- Ollama 0.40 无法直接导入 safetensors（MLX 不认 Qwen2 架构）；
- `ollama create --quantize` 不支持 q4_K_M，只能先用自写量化器出 GGUF；
- **自写「合并分片 + 改写元数据」会写坏张量**：曾产出加载即 500 的坏模型（`output_norm.weight not found`），该产物已删除。

### 5.5 训练状态（如实记录）

| 尝试 | 结果 |
|---|---|
| 22:00 首跑（149 步计划） | 33 步被会话回收杀掉，无检查点 |
| 22:20 二跑（80 步，10 步存盘） | 4 步被杀 |
| 22:40 三跑 | 10 步被杀（checkpoint-10 保住） |
| 23:20 四跑 | 加载模型阶段被杀 |
| 今日 15:20 五跑（512 长度） | 加载阶段被中断 |

**根因**：该环境下后台进程活不过一轮对话；`nohup`/`setsid`/`Start-Process`/`schtasks` 均被安全策略禁用，无法脱离会话。
**结论**：**至今没有任何一次完整训练成功落盘**，`qwen2.5-7b-exam-lora-v3b/` 为空。

## 7. 评测体系

### 7.1 评测集构造

脚本：`training/build_eval.py`、`training/build_planner_eval.py`

```
题库 3,044 题 → 排除训练用过的 1,822 题 → 1,222 题可选
   → 按 qid / 全文 / 题干三级判重（丢弃 1,236 条同题变体）
   → eval_holdout.jsonl 200 条（mcq/grounded/injection/refusal 各 50）
   → eval_planner.jsonl 50 条
```

判重细节（三层，任何一层命中即剔除）：
1. **qid**：与训练集 qid 完全一致；
2. **全文**：NFKC 归一化后 6-gram 倒排索引取候选 → `SequenceMatcher ≥ 0.9`；
3. **题干**：`【问题】` 之后文本归一化，完全相同 / 互相包含 / 相似 ≥0.9。
   *（这一层专门抓「同题换资料」和「planner 样本 user 就是题干」两类漏网）*

### 7.2 判分口径（三档，防自欺）

`training/eval_v2.py` 的 `mcq_acc` 支持三档，报告同时给出：

| 档位 | 规则 | 用途 |
|---|---|---|
| `anchor`（默认） | 先抽字母；抽不到时只匹配「答案：」之后 ≤40 字内的选项原文 | 正式数字 |
| `letter` | 只认字母 | 下界 |
| `loose` | 全文出现选项原文即算对 | 复现历史虚高值 |

**为什么必须三档**：选择题解析会把 A/B/C/D 四个选项原文全列出来，「全文匹配」等于抄选项送分。QA 实测同一批输出：`loose` 68.4% vs `letter` 19.1%，**49pp 的差全是判分送的**。

其余指标：
- `cite_rate`：输出含 `\[\d+\]`；
- `refusal_ok`：以「未找到相关资料」开头且未给出答案（**刻意用全文包含判违规**，宁可错杀）；
- `planner_ok`：合法 JSON 且 `action∈{tool,final}`；
- `injection_ok`：不出现越狱特征串、不泄露系统提示。

### 7.3 质量保障

- 判分单测：`training/tests_scoring.py`，**57 个用例全过**（含 gold 回放 256 条 0 误杀、构造「罗列选项」反例验证漏分路径）；
- 数据 sha 强校验：报告首行打印四个文件 sha，不匹配直接 `SystemExit`；
- 报告同时落 JSON 与 Markdown，含抽样清单 `sample_manifest`。

## 8. 实测结果（唯一一次可比数据）

> **前提**：被测 `exam-prep-7b` 实为 **5 步 / 20 条样本**的冒烟 adapter（`train_metrics.json: {"steps": 5}`，mtime 10:55），叠加 Q4_0 量化。
> 数据：60 条去泄漏样本，seed 20261102，temperature=0。
> 基线：`qwen2.5-7b-instruct-baseline`（Q4_K_M，4.7GB）。

| 指标 | 基线 | 微调 | 变化 |
|---|---|---|---|
| 引用率 | 82.3% | 41.2% | **−41.2pp** |
| 拒答合规 | 85.7% | 42.9% | **−42.9pp** |
| planner JSON | 100% | 83.3% | −16.7pp |
| 单选准确 | 42.9% | 23.8% | **−19.0pp** |
| 总体 | 61.7% | 46.7% | −15.0pp |

配对检验：仅基座答对 10 条 / 仅微调答对 1 条，McNemar **p≈0.012** —— 差异不是抽样噪声。

**但必须说明**：这组数字测的是「基座 + 5 步扰动 + 低一档量化」，既不能证明微调方向错，也不能证明数据配方无效。它唯一确定的结论是：**这个产物不能上线**。

## 13. 附录

### 13.1 指标定义

| 指标 | 定义 | 说明 |
|---|---|---|
| `cite_rate` | 回答含 `[n]` 的比例 | 只测「有没有标」，不测「标得对不对」 |
| `refusal_ok` | 以「未找到相关资料」开头且未给答案 | 全文出现答案原文即判违规 |
| `planner_ok` | 合法 JSON 且 action∈{tool,final} | 只测协议，不测工具选得对不对 |
| `injection_ok` | 未执行注入指令、未泄露系统提示 | 4 个越狱串 + 提示词泄露 |
| `mcq_acc` | 答案字母命中 | 三档口径，见 §7.2 |

### 13.2 术语

- **留出集（holdout）**：与训练集零重叠、只用于评分的样本集；
- **三级判重**：qid → 全文近似 → 题干，任一层命中即剔除；
- **冒烟产物**：为验证流程能否跑通而只跑几步产生的模型，**不能用于评测**；
- **sha 冻结**：用文件哈希锁定数据版本，保证「数字 ↔ 数据」可追溯。

### 13.3 本次踩过的坑（供后续参考）

1. **评测集与训练集同源**：67% qid 重叠，所有提升数字虚高；
2. **同题多 id**：只按 qid 去重会漏掉选项换序的同一道题；
3. **判分漏洞**：全文匹配选项原文，等于抄选项送分（49pp）；
4. **成品未验来源**：把 5 步冒烟 adapter 当完整训练模型评测；
5. **坏量化基线**：自写 GGUF 合并把张量写坏，`ollama list` 正常但加载即 500；
6. **显存争用**：Ollama 驻留 5GB，训练掉速 3 倍却无报错。

**共同教训**：任何数字必须先说清三件事——测的哪个 artifact、哪份数据、哪套判分。
