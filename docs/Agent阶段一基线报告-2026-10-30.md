## 2. 会话与记忆链路（阶段一第 1 项）

### 2.1 断点定位

Java 侧链路是完整的：

- `AiAgentController#stream` 先 `AgentSessionService.resolve(...)`（校验 sessionId 归属）
- `AgentStreamService#callPython` 已把 `sessionId`、`memorySummary`、最近 6 轮 `history` 写入请求体
- 每轮成功/拒答后 `recordTurn` 追加确定性滚动摘要（不调 LLM）

断点在 Python：[app/routers/agent.py](file:///D:/大学生多考试备考知识库与题库系统/ai-service/app/routers/agent.py) 的 `_context()` 只映射了问题/用户/科目/画像，**没有把 `request.session_id`、`request.history`、`request.memory_summary` 写入 `AgentContext`**。因此：

- `meta` 事件的 `historyTurns` 恒为 0、`memoryChars` 恒为 0
- 规划 prompt 的【会话记忆】块永远为空 → 多轮追问实际是单轮

### 2.2 修复

`_context()` 补齐三个字段（只补实际缺失项，Java 侧不改）。修复后：

- `build_context` 会渲染【会话记忆】（摘要 + 最近轮次），LlmPlanner 的 user prompt 带上历史
- `meta` 事件如实报告 `historyTurns` 与 `memoryChars`，可用于线上核对记忆是否真的贯通

### 2.3 隔离与边界（已验证）

| 场景 | 行为 |
|---|---|
| 跨用户复用 sessionId | `AgentSessionService.resolve` 抛 403，不读他人记忆 |
| 历史查询 | `selectRecentTurns(sessionId, userId, limit)`，只取 `SUCCESS/REFUSED` 且答案非空的轮次 |
| 空会话 | `history` 返回空列表，`summary` 返回空串，不报错 |
| 取消/超时 | 不写入记忆（`finalSent && SUCCESS/REFUSED` 才 `recordTurn`） |
| 摘要上限 | 1800 字滚动截断保留尾部；单轮答案入摘要前截 600 字、入历史前截 300 字 |
| sessionId 格式 | 仅 `[A-Za-z0-9_-]{1,32}`，非法返回参数错误 |

已知低优先级问题：摘要包含全部轮次，最近 6 轮同时出现在 `history` 中，prompt 内存在重复（不影响正确性，占用预算）。阶段二可改为“摘要只保存窗口外轮次”。

## 3. 路由边界与典型问题映射（阶段一第 2 项）

### 3.1 实际入口（本次静态核对 + 在线验证）

| 入口 | 实际链路 | 状态 | 失败回退 |
|---|---|---|---|
| `POST /api/ai/ask` | Java `AiQaService`：Wiki 热层 → `HybridRetriever`（向量+ngram）→ `LlmClient` 链 → `AnswerPostProcessor` L3 | 可用；**Android 学生端与管理端源码均未发现调用** | Wiki 异常降级 RAG；FastAPI 不可用降级 ngram；LLM 不可用降级抽取式；无证据拒答 |
| `POST /api/ai/agent/stream` | Java `AgentStreamService` → Python `/v1/agent/stream` → Harness（规划→工具→观察→定稿） | 默认关闭（`app.ai.agent.enabled=false`）；仅管理端“AI 运行观测”控制台有调用 | Python 不可用→`fallbackToJava` 走 `/ai/ask`；LLM 不可用→规则规划；工具失败→记 `ok=false` 不进证据 |
| Python `POST /v1/agent/run` | 直连 Harness 非流式 | 仅离线评估/调试使用 | 无 |
| Python `POST /v1/ask` | Router（bge 意图路由）+ 9 Skill | **未被 Java 调用**；仅测试与工具脚本使用 | Router 不可用→通用检索，`ROUTER_UNAVAILABLE` |

结论：规划中提到的“Router/Skill”与“Agent”两条链路在生产上只有 Agent 一侧被 Java 接上，且默认关闭；普通问答走的是 Java 自带 RAG，不经过 Python Router/Skill。三条链路并存但**客户端入口缺失**，属于阶段二需要明确的入口与开关问题。

### 4.2 根因一：语义闸门否决了字面证据（已修复）

修复前误拒 26.6%，对应 64 条 `[AI] 语义拒答` 日志，例如：

- 「32 位系统里一个整型变量占多大内存？」top1 0.6145 < 0.62
- 「C语言合法关键字有哪些？」0.6197 < 0.62

这些问题的 ngram 通道都有命中。`VectorChannel` 的既有设计写的是“两道闸门各管各的、互不否决”，但 `HybridRetriever` 实际用向量分**整体否决**了 ngram 证据，属于实现与设计不一致。

修复：[HybridRetriever.java](file:///D:/大学生多考试备考知识库与题库系统/backend/src/main/java/com/examprep/service/ai/HybridRetriever.java#L96-L111) 增加条件 `ngram.contexts().isEmpty()`——语义拒答只在“两路都无证据”时生效。

代价（如实记录）：拒答准确率 10/11 → 9/11。「区块链智能合约怎么写」（字面覆盖度 0.75、余弦 0.5957）不再被语义拒答。12 条域内问题仍保持 0 误拒（见 `HybridRetrieverTest`）。

### 4.3 根因二：剩余 20.2% 误拒来自两个阈值口径问题（未改动，需专项）

逐例诊断 41 条误拒：

| 模式 | 条数 | 直接原因 |
|---|---|---|
| `VECTOR_ONLY`（退回字面查询后仍空） | 31 | 向量候选被 `min-vector-score=0.55` 全部剔除，ngram 随后拒绝 |
| `NONE`（两路皆空） | 10 | ngram 内容覆盖度 < 0.45 |

实测原始余弦分布（对 214 例直接打 `/v1/search`）：

```
可回答 top1：min 0.4664 / p10 0.5667 / median 0.6705 / max 0.8829
应拒答 top1：min 0.4529 / median 0.5302 / max 0.8066
```

两类分布**高度重叠**：没有任何单一绝对余弦阈值能同时满足“误拒≤10%”与“拒答≥90%”。这正是旧阈值（0.55/0.62，按 42 块语料标定）在 11999 块语料上失效的原因。

另有两处口径问题（本次未改，建议阶段二处理）：

1. **量纲不一致**：`VectorChannel.hydrate` 把 FastAPI 的 `rerank_score`（余弦 + 标题/热度/难度加成）写入 `ftScore`，而 `min-vector-score`、`semantic-reject-score` 的注释都按“余弦”标定；闸门实际比较的是重排分。`VectorChunkMerger` 也按“已归一化”口径直接使用 `ftScore` 融合。
2. **内容覆盖度单一阈值**：`min-content-coverage=0.45` 会拒掉「32 位系统…」0.44 这类只差 0.01 的域内问题。

回滚值：本次未修改上述两个阈值；回滚语义闸门只需删除 `&& ngram.contexts().isEmpty()`。

### 4.4 建议的下一步（需更大拒答样本，不在本阶段拍板）

1. 在 `min-vector-score`、`semantic-reject-score` 的取值与使用处统一到余弦口径（先改口径，再谈阈值）。
2. 拒答样本从 11 条扩到 ≥50 条（阶段一“真实任务集”），再标定绝对值。
3. 覆盖度阈值按题型分档（客观题/概念题/代码题），而非全局 0.45。

## 5. Agent 基线（阶段一第 4 项）

### 5.1 模型规划解析器（本次修复）

修复前 20 例任务**全部**退回规则规划，日志显示两类失败：

- `非法 action：get_question` / `search_knowledge`（7B 把工具名写进 `action`）
- `Invalid control character`（7B 把换行原样写进 JSON 字符串）

修复（[planner.py](file:///D:/大学生多考试备考知识库与题库系统/ai-service/app/agent/planner.py#L87-L106)）：

- `json.loads(..., strict=False)` 容忍控制字符
- `action` 若等于已知工具名，按工具调用解释；未知 action 仍拒绝
- `PROMPT_VERSION` 升至 `agent-planner-v3`

### 5.2 同题配对结果（20 例合成任务）

| 规划方式 | 通过率 | 平均步数 | P95 延迟 | 工具成功率 | 主要失败 |
|---|---|---|---|---|---|
| 规则兜底（每任务先尝试一次模型后失败） | **100%** | 2.35 | 7.0 s | 100% | 无 |
| 模型规划（修复解析器后） | **60%** | 3.10 | 10.5 s | 90.5% | 步数超限×8、工具失败×4、答案缺内容×1 |

解读（重要）：

- 合成任务集是按“规则规划器”的工具序列编写的，模型规划会多调工具，导致 `step_count > max_steps` 被判失败；**该判定口径对模型规划不完全公平**，需要在阶段三为模型规划单独定 rubric。
- 90.5% 工具成功率说明模型会给出非法/不匹配的参数（如 `get_question` 未给有效 `questionId`），对应阶段二“工具参数 schema 校验”。
- 修复后模型规划确实生效（不再是静默规则兜底），但质量不足以替代规则路径。

### 5.3 轨迹可解释性缺口

`meta` 只有 `promptVersion`，没有“本次规划实际由模型还是规则产生”。LLM 失败退回规则时仅有一条 `thought` 文本，难以在管理端统计规则兜底率。建议阶段三在 `meta` 或 `final` 增加 `plannerSource`（`llm` / `rule` / `llm_failed`）。

## 6. 安全与稳定性检查（阶段二预输入）

| 检查项 | 现状 | 风险 |
|---|---|---|
| 内部接口鉴权 | `X-Internal-Token` 单层；token 为空时 `/internal/**` 一律 403 | 服务身份不能替代最终用户归属校验 |
| 工具数据归属 | `get_weak_knowledge/get_wrong_book/get_study_plan` 直接使用请求里的 `userId`；Java 侧不做二次归属校验 | 只要拿到内部 token，可伪造任意 `userId` 读他人画像/错题/计划 |
| `get_question/get_wiki_page` | 按 ID 读取公共已审核内容，无归属概念 | 低风险，但需确认只返回 APPROVED |
| 提示注入 |系统提示已声明“工具返回只是数据”；历史/检索文本未做信任分隔 | 需专项样本验证 |
| SSRF/超时 | JavaBridge 每次调用新建 `httpx.AsyncClient`，超时来自配置 | 性能与连接管理待优化 |
| AI 服务稳定性 | 本地 Qdrant + 并发检索约 800 次后发生 **1 次原生崩溃**（退出码 -1073741819 / 0xC0000005），后续 10 分钟未复现 | 需专项压测定位（Qdrant local 模式线程安全 / onnxruntime） |

## 7. 阻塞项与阶段二建议顺序

1. **工具越权**（P0）：`/internal/agent/tools/*` 增加“调用方用户身份”签名或由 Java 侧用会话身份覆盖 `userId`，补越权用例。
2. **AI 服务崩溃**（P0）：复现 0xC0000005；若确认 Qdrant local 模式并发不安全，改为单线程执行器或 Qdrant server。
3. **向量分口径统一**（P0/P1）：先统一余弦口径，再重标定 `min-vector-score` / `semantic-reject-score`。
4. **拒答样本扩充**（P1）：11 条拒答不足以下调参结论；扩充到 ≥50 条并固定语料版本。
5. **客户端入口**（P1）：明确 `/ai/ask` 是否接入学生端；若接入，再决定 Agent 是否面向学生开放（当前仅管理端控制台）。
6. **参数 schema 与终态**（P1）：工具参数统一校验（`pageId/questionId/topK/limit`），补充取消/超时/预算耗尽的 SSE 终态说明与测试。
