## 问题清单（交给工程师修复，QA 不动代码）

### 问题 1（B 级 · 重要）：`@Valid` 参数校验失败时 HTTP 状态码为 200，应为 400

- 复现：`curl -s --noproxy '*' -w "\nHTTP=%{http_code}\n" -X POST http://127.0.0.1:8080/api/auth/register -H "Content-Type: application/json" -d '{"studentNo":"2022889","nickname":"QA缺密","schoolId":1,"collegeId":12}'`
- 实际输出：`{"code":400,"message":"密码不能为空","traceId":"d22c161d8f854481"}` + `HTTP=200`
- 期望：HTTP=400（与 6b/6c 的 HTTP=400 以及重复注册 HTTP=409 的约定保持一致；对 App 端而言，靠 HTTP 状态码分支的错误处理会把这个当成功响应，导致解析 body 后才报错甚至误判）
- 根因定位：`backend/src/main/java/com/examprep/common/GlobalExceptionHandler.java:38-45` 的 `handleValid(BindException)` 只 `return Result.fail(ResultCode.PARAM_ERROR, msg)`，**没有** `@ResponseStatus(HttpStatus.BAD_REQUEST)` 也没有 `resp.setStatus(400)`；对比同文件 27-35 行 `handleBiz`（BizException 落在 400-599 时同步了 HTTP 状态码，所以 409/假学校/假学院都对）
- 影响面：不止注册接口，**全后端所有走 `@Valid` 校验失败的接口**（含登录、改密等）HTTP 状态码都是 200。修复一处即可全局生效
- 建议修法：给 `handleValid` 加 `@ResponseStatus(HttpStatus.BAD_REQUEST)`（或仿照 handleBiz 注入 `HttpServletResponse` 后 `resp.setStatus(400)`）
