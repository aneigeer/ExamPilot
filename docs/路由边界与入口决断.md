## 0. 结论摘要

| 项 | 结论 |
|---|---|
| **推荐选项** | **B（加强版 B+）**：Java 保持唯一用户入口与编排权；Python Router 不再作为用户入口，但**以"检索策略顾问"身份被 Java 内部调用**，而不是仅供 Agent 使用 |
| 一句话理由 | **Java 独占鉴权、学情画像、Wiki 热层、抽取式兜底四件事，Python 独占 skill 级 `source_type` 隔离；B+ 用一跳 ~30ms 把后者借给前者，而 A 要重写生产链路、C 要丢掉唯一可用的课件隔离** |
| 不选 A | 需给 Python 补鉴权 + userId 透传，且 Java 的 Wiki/画像/兜底要么搬走要么丢失，生产链路回归风险最大 |
| 不选 C | 会丢掉 `retrieval_groups` 的 `source_type` 隔离——**这是 Java 当前唯一缺失的关键能力**（实测「进程 线程」top-5 全被课件占满） |
| Android 现状（精确表述） | `ApiService.aiAsk` / `aiCapability` **声明已就绪**（`ApiService.java:450/454`），但**全工程零调用点**——缺的是 UI 入口，不是网络层 |

## 1. 三条链路的实际形态（读代码所得）

### 1.1 对照表

| 维度 | ① Java `/api/ai/ask` | ② Python `/v1/ask`（Router+Skill） | ③ Java `/api/ai/agent/stream` → Python Harness |
|---|---|---|---|
| 代码位置 | `AiController` → `AiQaService` | `ai-service/app/routers/ask.py` | `AiAgentController` → `AgentStreamService` → `app/routers/agent.py` |
| 鉴权 | ✅ JWT（`SecurityUtils.requireUserId()`） | ❌ **无任何鉴权**（grep `token/Depends/Header` 全空） | ✅ 入口 JWT；⚠️ Python 侧无鉴权 |
| 用户身份 | ✅ 有 `userId`，用于薄弱知识点加权 | ❌ **无身份**（`ask.py` 注释明写"ask 通道没有用户身份"） | ✅ 有 `userId`（body 传递） |
| 编排形态 | 单跳：Wiki → Hybrid → 生成 | 单跳：Router(9 skill) → 检索 → 7B | **多步 ReAct**：planner 循环调 7 工具（≤max_steps/≤4 次工具） |
| 检索 | Hybrid = ngram + 向量 + 五因子重排 | 按 skill 的 `retrieval_groups` 分组检索 | 通过 `search_knowledge` 工具间接检索 |
| **`source_type` 隔离** | ❌ **缺失**（SQL 无该过滤，实测课件会挤占 top-5） | ✅ **有**（`retrieval_groups`，如 COURSEWARE_QA 只查 COURSEWARE） | ❌ 依赖 Java 同一套检索 |
| Wiki 热层 | ✅ 有（`WikiQueryService`，命中即返回） | ✅ 有（"Wiki 热层优先"，在拒答之前） | ❌ 无（工具里可 `search_wiki`） |
| 生成 | Ollama 7B（`@Order(5)`）→ 抽取式兜底 → L3 校验 | 7B → `[n]` 引用校验 | 7B 规划 + 7B 汇总，失败切 `RulePlanner` |
| 默认状态 | 开启 | 开启但**无人调用** | **`AI_AGENT_ENABLED=false`（默认关闭）** |
| 当前真实用户 | Android（声明存在，零调用点） | **无**（孤儿） | 管理端观测台 |

### 1.2 三条链路的能力互补关系（关键）

```
                 鉴权  画像  Wiki  隔离  多步工具  兜底
Java /ai/ask       ✅    ✅    ✅    ❌      ❌      ✅✅(抽取式+L3)
Python /v1/ask     ❌    ❌    ✅    ✅      ❌      ⚠️(仅引用校验)
Agent 链路         ✅    ✅    ❌    ❌      ✅      ✅(RulePlanner)
```

> **没有任何一条链路同时具备"鉴权 + 画像 + 隔离 + 多步"**。
> **所以正确动作不是三选一"留一个"，而是明确分工 + 把缺失能力定向补齐。** 这是 B+ 的出发点。

## 2. Router+Skill 是孤儿：A/B/C 取舍

### 2.1 三个选项的真实代价

#### A. Java 改成调 Python `/v1/ask`（合并）

| 项 | 影响 |
|---|---|
| 需要新增 | Python 侧鉴权（现在完全没有）、`userId` 透传与校验、学情画像在 Python 侧调用（7B 前置 → 多一跳） |
| 会丢失 | Java 的 Wiki 热层（可搬，但 Python 版与 Java 版是两套实现，需对齐）；Java 的**抽取式兜底**（`ExtractiveAnswerClient` 在 Java，Python 未实现等价物） |
| 会变薄 | Java 侧兜底从"抽取式保底"变成"Python 不可用则整条链路不可用"，除非保留 Java 原链路做 fallback（那实际是"两套并存"，比现在更复杂） |
| 延迟 | +1 跳（含 Router 21.6ms + HTTP ≈ 30~50ms），相对 5~8s 生成可接受 |
| 风险 | **生产链路回归风险最高**：`/ai/ask` 是唯一对用户开放的入口 |

#### B. 保留 Java 主链路，Python Router 只服务 Agent 内部

| 项 | 影响 |
|---|---|
| 改动量 | 最小（只需在文档/代码注释中明确"`/v1/ask` 不是用户入口"） |
| 遗留问题 | **Java 仍然没有 `source_type` 隔离** → 课件污染继续存在（实测「进程 线程」top-5 全课件） |
| Router 价值 | 仅当 Agent 开启时生效，而 **Agent 默认关闭** → 实际价值≈0 |

> **裸 B 会让 Python 侧已完成的 9 skill + Router + 隔离工作彻底闲置**，包括我刚验证过、Java 确实缺的课件隔离能力。

#### C. 退役 Python Router（删掉或标 deprecated）

| 项 | 影响 |
|---|---|
| 节省 | 一个进程组件、一份维护成本 |
| 损失 | 9 个 skill 的定义、三闸门 Router（33 例回归 90.9% 精确 / 零错误作答）、`retrieval_groups` 隔离 |
| 结论 | **不可取**。等于把"已解决"的能力重做成"未解决"的问题 |

### 2.2 推荐：B+

> **B+ = 保留 Java 为唯一用户入口与编排者；Python Router 从"问答入口"降级为"检索策略顾问"，由 Java 在内部调用；Python 侧 `/v1/ask` 标注为非用户入口（仅调试/评测/Agent 使用）。**

**调用形态（Java 内部，非用户可见）：**

```
Java /api/ai/ask
  ├─ ① JWT 取 userId（永不外传为可写参数）
  ├─ ② 调 Python POST /v1/route  {question}        ← 新增轻量端点，只返路由决策
  │      返回 {skill, source_types, sim, margin}   超时 300ms
  │      失败 → 默认 {skill: COURSE_QA, source_types: [QUESTION,KNOWLEDGE,COURSEWARE]}
  ├─ ③ Java 用 source_types 走自己的 HybridRetriever（补上隔离）
  ├─ ④ Wiki 热层（保持 Java 现有优先级）
  ├─ ⑤ 画像加权 + 生成（现有 7B / 抽取式兜底 / L3）
  └─ ⑥ 拒答与降级完全沿用 Java 现有逻辑
```

**为什么这样最优：**

| 目标 | B+ 如何满足 |
|---|---|
| 保住鉴权 | 用户只面对 Java，Python 不接受用户请求 |
| 保住画像 | `userId` 从 JWT 取，只在 Java 内部使用，**不进 Python body** |
| 补上隔离 | 用 Python 已标定好的 `skill → source_types` 映射，Java 执行过滤 |
| 保住兜底 | 抽取式 / L3 / Wiki 全部留在 Java 原处，一行不搬 |
| 复用 Router | 只借"判定"，不借"生成"，失败可退回默认 skill（**降级零成本**） |
| 延迟可控 | 一次 embed + HTTP ≈ 30~50ms，占总延迟 <1% |

**B+ 新增的最小契约（只有一个端点）：**

| 项 | 值 |
|---|---|
| 路径 | `POST /v1/route` |
| 入参 | `{question: str}`（**不带 userId**，保证无身份耦合） |
| 出参 | `{skill, source_types[], sim, margin, candidates[]}` |
| 超时 | 300ms；Java 熔断后 60s 内直接用默认 skill |
| 失败语义 | 返回默认 `COURSE_QA` + 全量 source_types（等价于今天的行为，**零退化**） |

> 注意：这**不是**把 `/v1/ask` 搬到 Java，而是把 Router 的"判定结论"暴露出来。
> `/v1/ask` 本身保留，作为评测入口和 Agent 的 skill 参考，**但明确不在用户链路上**。

## 3. 典型问题 → 入口映射表

> "目标"列是 B+ 落地后的形态；"现状"列是今天真实可用的路径。

| 问题类型 | 例子 | 现状走哪 | 目标（B+） | 说明 |
|---|---|---|---|---|
| **课程知识问答** | 「指针和数组的区别」 | Java `/ai/ask` | Java `/ai/ask` + skill=COURSE_QA | 主路径；需补 `source_types=[QUESTION,KNOWLEDGE,COURSEWARE]` 分组 |
| **题目讲解** | 「第 5 题为什么选 B」 | Java `/ai/ask`（无题目上下文）或 Agent（`get_question`） | Java `/ai/ask` + skill=EXERCISE_EXPLAIN | 需要 `questionId`；建议前端带 id，后端按 id 取题再讲 |
| **错题复习** | 「我薄弱的地方在哪」 | **Agent 链路**（`get_wrong_book`/`get_weak_knowledge`） | Agent（多步） | Java `/ai/ask` 无工具能力，短期只能靠 Agent |
| **学习计划** | 「10 天怎么安排」 | **Agent 链路**（`get_study_plan`） | Agent（多步） | 同上；Python `STUDY_PLAN` skill 无用户进度，只能给通用骨架 |
| **课件 / 面试题问答** | 「大模型面试会问什么」 | **Python `/v1/ask`**（Java 无隔离，答案会被行测题淹没） | Java `/ai/ask` + skill=COURSEWARE_QA（只查 COURSEWARE） | **B+ 最大收益点** |
| **资料推荐** | 「推荐点资料」 | Java `/ai/recommendations`（规则版） | Java `/ai/recommendations`，或 skill=RESOURCE_RECOMMEND | 规则版已够用，优先不加 AI |
| **AI 面试** | 「开始一场大模型面试」 | **Java `/ai/interview/*`**（已实装，Android 已接） | 不变 | 独立有状态链路，**不要混进 `/ai/ask`** |
| **闲聊** | 「你好」 | Python `/v1/ask`（SMALLTALK 模板，**不调 7B**） | Java 侧模板直出 | 省 5~8s |

**边界原则（三条，建议写进代码注释）：**
1. **`/ai/ask` 只做单跳问答**，不承担多步任务；多步一律走 Agent（有预算闸门与工具白名单）
2. **有状态能力（面试）不进 `/ai/ask`**，避免无状态入口被会话污染
3. **答案类信息（题目答案）只在 EXERCISE_EXPLAIN skill 内出现**，不在通用问答里主动吐答案

## 4. 失败与降级矩阵

### 4.1 按组件失效枚举

| 失效组件 | ① Java `/ai/ask` | ② Python `/v1/ask`（不再对用户） | ③ Agent |
|---|---|---|---|
| **Python AI 服务（8000）** | 向量通道降级 ngram；生成仍可用（Ollama 直连）→ **用户无感，仅语义召回变字面召回** | 整条不可用（503） | **不可用** → 建议 Java 侧回退到 `/ai/ask` 并提示"简化模式" |
| **B+ 的 `/v1/route`**（新增） | 角色判定失败 → 默认 `COURSE_QA` + 全量 source_types → **等价今天行为** | — | — |
| **7B / Ollama（11434）** | 降级抽取式（`ExtractiveAnswerClient`）→ **仍返回带引用的答案** | 降级为"仅返回检索片段 + 引用"，无综述 | planner 失败 → `RulePlanner` 兜底（现有） |
| **Qdrant** | 降级 ngram（MySQL 全文） | 同 | 同 |
| **Redis（jobs/worker）** | **不受影响**（同步链路不依赖） | 不受影响（SSE 同步） | 异步任务不可用 → 同步执行或 503 |
| **Wiki 索引** | `WikiQueryService` 异常被 catch → 直接跳过热层走 RAG（现有设计） | 同 | — |
| **MinIO** | 不影响问答（只影响上传）；上传降级本地磁盘（T10 已做） | — | — |
| **MySQL** | **整链不可用**（唯一硬依赖） | 同 | 同 |

### 4.2 用户可见文案（建议统一）

| 场景 | 用户看到 | 不应出现 |
|---|---|---|
| 7B 不可用，抽取式兜底 | 正常答案 + 角标"本地抽取模式" | "AI 服务异常" |
| 向量不可用 | 正常答案（无提示，或角标"基础检索"） | 报错 |
| 检索无命中 | "未找到相关资料。"（HTTP 200） | 空答案 / 500 |
| Python 完全不可用（Agent） | "复杂分析暂时不可用，已为你切换到简化问答" | 转圈/超时无反馈 |
| MySQL 不可用 | 统一错误页 + traceId | 堆栈 |

> **红线：问答接口永远返回 HTTP 200 + 结构化 Result**，降级信息只体现在 `generator` / `degraded` / `retrievalMode` 字段里。这一条 Java 侧已经做到，B+ 不能破坏它。

## 5. B+ 落地步骤（设计，不含代码）

| 步 | 内容 | 依赖 | 验收 |
|---|---|---|---|
| 1 | Python 新增 `POST /v1/route`（只返 skill + source_types，复用现有 Router，不带 userId） | 无 | `curl` 返回 skill；无鉴权但**入参无 userId**，故无越权面 |
| 2 | Java `FastApiClient` 加 `route()`（超时 300ms + 熔断 + 失败返默认） | 1 | 杀 Python 后 `/ai/ask` 仍 200 且行为与今天一致 |
| 3 | Java 检索加 `sourceTypes` 参数（ngram SQL + 向量 + LIKE 三入口，**null = 不过滤保证兼容**） | 2 | 「进程 线程」top-5 不含 COURSEWARE；`RetrievalServiceTest` 16 用例仍全绿 |
| 4 | `/ai/ask` 串起来：route → 按 source_types 检索 → 现有生成/兜底 | 2,3 | 8 类问题各一条 curl 正确路由且 sources 类型符合预期 |
| 5 | Python `/v1/ask` 标注"非用户入口"（docstring + README），保留给评测/Agent | 无 | 文档更新，无行为变更 |
| 6 | Android 补 UI 入口（工程师已派） | 4 | 真机可问答，无网时入口隐藏 |

> **第 3 步是我在《语义闸门与字面判据设计》之外另提的独立缺口**，与拒答判据无关，但**它是课件功能能否用的前提**（详见 `docs/Router与Skill架构设计.md` E.1.1 实测：`进程 线程`/`数据库 索引` top-5 全为 COURSEWARE）。

## 6. 风险与遗留

| # | 风险 | 应对 |
|---|---|---|
| R1 | B+ 引入"Java 依赖 Python 判路由"，Python 抖动会拖慢 `/ai/ask` | 300ms 超时 + 熔断 + 默认值；Python 挂掉等价于今天行为 |
| R2 | skill 映射与 Java 检索口径漂移（两边各改一份） | `source_types` 映射**只在 Python 一处定义**，Java 只消费 |
| R3 | Agent 默认关闭，错题/计划类问题无 AI 入口 | 答辩前确认是否开 `AI_AGENT_ENABLED=true`；否则这两类问题在 UI 上不承诺 |
| R4 | `/v1/ask` 保留但无鉴权，未来若被直连仍有风险 | 见《工具权限与提示注入基线》V1；至少绑定 127.0.0.1（`run.bat` 默认已如此） |
| R5 | 面试链路与 `/ai/ask` 边界模糊，容易被合并 | 边界原则第 2 条已明确，代码注释固化
