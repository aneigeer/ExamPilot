## 零、项目定位声明

### 0.1 性质
软件工程课程设计 / 毕业设计，完整原型，不商用、不上架。

### 0.2 目标
学生端为 Android App，管理端为 Web，后端统一 REST API。
核心闭环：
刷题 → 判分 → 错题本
上传 → 审核 → 预览 → 下载 → 举报 → 下架
游客、学生、审核员、超管四级权限可用。

### 0.3 边界
资料以模拟题、原创题、授权资料、回忆题型为主。
不接真实教务系统，课程、教师、开课班用模拟数据。
文件初期本地磁盘，后期可换 MinIO。
不追求真实高并发，使用稳定即可。
学生端做 Android App，不做 iOS，不做小程序。
管理端做 Web，不做 App。
主观题采用自评 + 参考答案 + 关键词匹配，不引入 AI 自动判分。
**App 端上传仅开放图片格式（jpg/jpeg/png/webp/gif，来源为拍照或相册）；PDF/DOCX/ZIP 等文档文件经管理端 Web 上传。视频、音频格式不开放。**

### 0.4 原则
多考试统一模型、全题型覆盖（分期开放）、审核净化、先预览后下载、无广告无娱乐、权限严格隔离、App 与管理端体验各自最优。

### 0.5 验收总标准
Android App 可安装、可用：浏览、搜索、刷题、错题本、上传、预览、下载、通知。
管理端 Web 可用：审核、举报、用户、公告、统计、日志。
游客、学生、审核员、超管四级权限可用。
**P0 五种核心题型（单选/多选/判断/填空/简答）跑通：客观题自动判分、主观题自评闭环；其余题型数据库预留、界面按批次开放。**
刷题闭环、资料闭环（上传 → 审核 → 预览 → 下载 → 举报）可跑通。
核心接口 P95 < 2 秒，上传/下载/预览可放宽到 5 秒。
App 触控目标不小于 44px，无横向滚动。
文档、源码、数据库脚本、测试报告齐全。

## 一、项目概述

### 1.1 项目名称
大学生多考试备考知识库与题库系统。

### 1.2 背景与痛点
期末资料零散，四六级、计算机二级资料混杂，真假难辨。
题库和资料分离，刷题、看笔记、下载资料来回切换。
课程、教师、学年学期不匹配，劣质资料无人审核。
手机端资料少，电脑端不方便随时刷题。
现有题库多只支持选择题，大题、应用题、作文、翻译无法练习。

### 1.3 项目目标
建立"考试类别 → 科目 → 知识点 → 题目/资料"的统一知识库。
支持校内课程、CET4、CET6、计算机二级。
**题型覆盖全部常见题型，按交互复杂度分期开放：P0 五种核心题型（单选/多选/判断/填空/简答），P0-B 开放自评类主观题（名词解释/计算/应用/作文/翻译），P1 开放复杂交互题型（匹配/排序/完形/听力/阅读大题等）。**
实现刷题、判分、错题本、资料上传、审核、预览、下载闭环。
实现游客、学生、审核员、超管四级权限。
学生端 Android App，管理端 Web。

### 1.4 用户角色
游客：浏览、搜索、低清预览前 3 页。
学生：刷题、错题本、收藏、笔记、上传、下载、评论、评分、举报。
审核员：学生权限 + 题目审核、资料审核、举报处理；不可审自己上传的。
超管：全部权限，含考试、科目、用户、公告、统计、日志。

### 1.5 核心特色
多考试统一知识树。
题库 + 资料库双核心。
全题型支持（分期开放）：客观题自动判分，主观题自评 + 参考答案。
审核、评分、举报、申诉四重净化。
先预览后下载（预览为图片，见 4.5）。
学生端 App，管理端 Web。
无广告、无娱乐、纯备考工具。

## 三、需求分析

### 3.1 核心模型
考试类别 → 科目 → 知识点 → 题目 / 资料

考试类别：校内课程、CET4、CET6、计算机二级。
科目：高数、C语言、MS Office、CET4词汇、CET6阅读等。
知识点：树形结构，如"C语言 → 函数 → 递归"。
题目：全题型（分期开放），关联知识点。
资料：课件、笔记、知识点总结、模拟卷、回忆题型、原创题，关联科目或知识点。
校内课程扩展：学院、专业、教师、学年、学期、开课班。
四六级/计算机二级：不绑学院教师，直接绑考试类别和科目。

### 3.2 题型体系（全题型，分期开放）

按判分方式分两大类：

**A. 客观题（自动判分）**
1. 单选题 ★P0
2. 多选题 ★P0
3. 判断题 ★P0
4. 填空题 ★P0
5. 匹配题（P1，连线交互）
6. 排序题（P1，拖拽交互）
7. 完形填空（P1，文章嵌空）
8. 阅读理解（P1，父子结构）
9. 听力选择题（P1，音频播放）
10. 选词填空（P1）

**B. 主观题（自评 + 参考答案）**
1. 简答题 ★P0
2. 论述题（P1）
3. 名词解释（P0-B）
4. 计算题（P0-B）
5. 应用题（P0-B）
6. 编程题（P1）
7. 案例分析题（P1）
8. 作文题（P0-B）
9. 翻译题（P0-B）
10. 改错题（P1）
11. 完形填空主观填空（P1）
12. 证明题（P1）

**C. 组合题（材料题 / 阅读大题）—— P1**
材料题、阅读理解大题、听力大题、作文题（含范文）、翻译题（含译文）。

**分期依据：**
- **P0 五种**：交互最简（点选/判断/短文本），判分链路最完整，先跑通"客观自动判分 + 简答自评"两条闭环。
- **P0-B 五种**：交互同为文本作答 + 参考答案展示 + 自评，与简答共用同一套界面组件，增量成本低。
- **P1**：匹配（连线）、排序（拖拽）、完形（嵌空）、听力（音频）、组合题（父子结构），每个都是独立交互工程，单独排期。

### 3.3 各题型字段设计
（保留 v1 全部字段定义，此处按分期引用：P0 五种题型字段先行实现，其余题型字段作为数据库预留与后续批次依据。）

单选题：题干、选项 A/B/C/D、正确答案、解析、难度、知识点、来源。
多选题：题干、选项、正确答案（多选）、解析、难度、知识点、来源。
判断题：题干、正确答案（对/错）、解析、难度、知识点、来源。
填空题：题干（含空格占位符）、答案列表（按顺序）、是否大小写敏感、解析、难度。
简答题：题干、参考答案、评分要点、解析、难度。

其余题型（匹配/排序/完形/阅读/听力/选词/论述/名词解释/计算/应用/编程/案例/作文/翻译/改错/证明/材料题）字段定义同 v1，不再重复罗列；实现时以 5.3 的 JSON 答案结构承载。

### 3.4 判分策略
客观题：后端自动判分，即时返回对错、正确答案、解析。
主观题：提交后展示参考答案、评分要点，学生自评"会 / 不会 / 模糊"。
作文题：提交后展示参考范文、评分要点，学生自评。
翻译题：提交后展示参考译文、评分要点，学生自评。
编程题：P0 只做自评，P1 可选接入简单编译运行（不做也可）。
组合题（P1）：小题按各自类型判分，整体统计正确率。

**P0 先跑通两条链路：客观题自动判分（单选/多选/判断/填空）+ 主观题自评（简答）。**

自评结果计入：错题本（自评"不会"进错题本）、知识点掌握度、刷题统计、正确率统计（主观题按自评结果折算）。

4. **资料知识库**：上传资料（选考试/科目/知识点、选类型、传文件、填简介；**App 端仅支持图片上传，文档文件走管理端 Web**）；资料类型：课件、笔记、知识点总结、模拟卷、回忆题型、原创题；资料审核（待审核、通过、驳回、下架、重新提交）；在线预览（游客前 3 页低清图，登录高清整本）；下载（记录下载、签名 URL、水印）。
5. **通知与公告**：审核结果通知；举报处理通知；公告发布与查看；通知已读/未读。
6. **后台管理**：仪表盘（用户数、题目数、资料数、待审核数、下载量）；考试类别、科目、知识点管理；题目审核、资料审核、举报处理；用户管理、角色权限管理；公告管理；操作日志（登录、审核、修改、删除）。

**P0-B：增强功能，时间够再做**
批量导入导出（Excel / JSON）；收藏题、题目笔记；收藏夹、下载历史、上传记录；评论、评分、点赞；简单统计图表；资料标签（重点必考、含答案、无答案、近年高频）；搜索排序优化；主观题评分要点结构化展示；**自评类主观题批次开放（名词解释/计算/应用/作文/翻译）**。

**P1：后置功能**

**P2：只写展望，不做**
推荐算法；Redis 缓存；MinIO 对象存储；病毒扫描；iOS 原生；统计日报表；复杂 RBAC 五表模型；AI 自动批改主观题。

### 3.7 核心业务流程
刷题（客观题）：登录 → 选考试/科目/知识点/题型 → 刷题 → 自动判分 → 错题本 → 掌握度统计。
刷题（主观题）：登录 → 选考试/科目/知识点/题型 → 答题 → 提交 → 查看参考答案和评分要点 → 自评"会/不会/模糊" → 错题本 → 掌握度统计。
上传题目/资料：选考试/科目/知识点 → 上传 → 提交审核 → 通过/驳回 → 通知上传人。
资料净化：举报 → 审核员核验 → 下架/驳回 → 通知举报人 → 可申诉。
模拟考试 P1：组卷 → 计时 → 交卷 → 判分（客观自动 + 主观自评）→ 成绩报告。

### 3.8 审核状态机
统一状态（题目与资料共用）：

```
DRAFT → PENDING → APPROVED / REJECTED
REJECTED → DRAFT（编辑后重新提交 PENDING）
APPROVED → OFFLINE（下架）
OFFLINE → APPEALING（申诉）
APPEALING → APPROVED（申诉通过，恢复公开）
APPEALING → OFFLINE（申诉驳回，维持下架）
```

规则：
题目通过后可被刷题使用。
资料通过后可预览、下载。
资料下架后，公开入口不可见，已下载用户保留历史记录。
申诉期间默认不可见，超管可恢复。
审核员不可审核自己上传的内容。

### 3.9 非功能需求

**多端兼容**
学生端：Android 原生 App（Java + XML 布局），最低 Android 8（API 26），compileSdk 34。
管理端：电脑浏览器，Chrome / Edge / Safari。
管理端手机可查看待审核并简单通过/驳回。
触控目标不小于 44px。
**App 预览：用图片分页展示（见 4.5）；整本文件下载到本地后通过 Intent 调系统阅读器打开，不作为在线预览手段。**
**App 上传：仅接受图片格式（jpg/jpeg/png/webp/gif），来源为拍照或相册，支持多选，上传前本地压缩（Android 端 Bitmap 缩放 + JPEG 质量压缩）；单张不超过 10MB。PDF/DOCX/ZIP 等文档文件经管理端 Web 上传。视频、音频格式 P0 不开放（接口预留，后续可扩展，不列入 P0 范围）。**
**说明：原生 Android 通过系统文件选择器技术上已可选取任意文件，但为控制审核成本与存储占用，P0 仍只开放图片。**
弱网、断网、加载中、空状态、错误提示完整。

**性能**
核心接口 P95 < 2 秒；上传、下载、预览可放宽到 5 秒；50 并发测试通过即可。

**安全**
JWT 鉴权、密码加密、文件白名单、大小限制、MD5 去重、防盗链。
学号脱敏，下载记录仅本人可见。

**可用性**
使用期稳定运行，数据每日备份。模块化、统一日志、统一异常处理。

**可扩展性**
后续可接教务系统、对象存储、推荐算法、AI 批改。

## 六、接口设计

### 6.1 规范
RESTful API，JSON，JWT 鉴权。
统一响应：{ code, message, data, traceId }
分页：{ page, size, total, list }

**接口访问级别（每个接口在 API 文档中必须标注，三选一）：**
- **PUBLIC**：匿名可访问（游客可用）
- **AUTH**：需登录（学生/审核员/超管均可）
- **ROLE:xxx**：需指定角色（如 ROLE:AUDITOR、ROLE:ADMIN）

### 6.2 主要接口
认证：登录（PUBLIC）、游客（PUBLIC）、登出（AUTH）、改密（AUTH）。
首页：搜索（PUBLIC）、分类（PUBLIC）、推荐（PUBLIC）、公告（PUBLIC）。
考试：考试类别（PUBLIC）、科目（PUBLIC）、知识点树（PUBLIC）。
题库：题目列表（PUBLIC）、详情（PUBLIC）、刷题提交（AUTH）、判分（AUTH）、自评（AUTH）、错题本（AUTH）、收藏题（AUTH）、笔记（AUTH）。
资料：列表（PUBLIC）、详情（PUBLIC）、预览（PUBLIC 前3页 / AUTH 整本）、下载（AUTH）、收藏（AUTH）、点赞（AUTH）、评分（AUTH）、举报（AUTH）。
上传：文件上传（AUTH，管理端 Web；App 仅图片）、提交审核（AUTH）、我的上传（AUTH）。
个人：信息（AUTH）、收藏（AUTH）、下载（AUTH）、通知（AUTH）。
管理：审核（ROLE:AUDITOR）、举报处理（ROLE:AUDITOR）、公告（ROLE:ADMIN）、考试/科目/知识点管理（ROLE:ADMIN）、用户（ROLE:ADMIN）、统计（ROLE:ADMIN）、日志（ROLE:AUDITOR 审核日志 / ROLE:ADMIN 全部）。
P1：组卷、模拟考试、成绩报告、申诉、关注、统计图表。

### 6.3 全题型接口注意
题目接口：返回字段含题型、题干、选项、材料、子题列表（P1）；组合题返回父子结构（P1）。
判分接口：客观题后端判分，返回是否正确、正确答案、解析；主观题不判对错，返回参考答案、评分要点、参考译文、参考范文；自评接口提交自评结果（会/不会/模糊）。
刷题接口：支持按题型筛选；支持只刷客观题、只刷主观题、混合刷题；**P0 仅开放五种核心题型，请求其他题型返回"该题型暂未开放"**。

### 6.4 App 端接口注意
**预览接口返回图片地址列表：游客仅前 3 页低清图，登录用户返回整本高清图。**
下载接口返回短时效签名 URL。
上传接口（App 端）**仅接受图片格式（jpg/jpeg/png/webp/gif）**，来源拍照/相册，支持多图批量；**服务端独立校验类型白名单与大小，非图片格式返回 415**。文档文件走管理端 Web 上传。
列表接口支持分页、上拉加载、下拉刷新。
通知接口返回未读数。

### 6.5 错误码
400 参数错误、401 未登录、403 无权限、404 不存在、409 重复上传、413 文件过大、415 类型不支持、429 请求过频、500 服务器错误。

**翻译题页面（P0-B）**：原文、作答区、提交后展示参考译文。

**资料详情**：头部信息、在线预览（图片分页）、下载、收藏、点赞、举报、评论区、关联推荐。

**上传页**：提示横幅、考试/科目/知识点选择、题型选择、图片上传（拍照/相册，可多选，多页试卷一次选多张并支持调整顺序与删除）、简介、提交审核。非图片格式一律提示"该格式请到电脑端上传"。

**我的**：信息卡片、统计宫格（已收藏 / 我的上传 / 下载历史）、功能菜单（含上传资料入口）。

### 7.6 交互细节
游客锁定下载/上传/收藏/评论/刷题。
手机端下拉刷新、上拉加载。
主观题作答支持草稿保存（本地用 SharedPreferences 存草稿，换设备不保留；如需云端草稿列 P1）。
表单分步或底部弹层。
**App 预览用图片分页展示；下载后的整本文件通过 Intent 调系统阅读器打开。**
**App 上传仅支持图片（拍照/相册，可多选）；上传前本地压缩（Bitmap 缩放 + JPEG 质量压缩）避免流量与超时；任何非图片文件提示"该格式请到电脑端上传"。**

## 十三、协作开发规范

### 13.1 项目结构
```
exam-prep/
  backend/          后端 Spring Boot
  admin-web/        管理端 Vue3 + Element Plus
  student-app/      学生端 Android 原生（Java + XML）
  sql/              schema.sql、data.sql
  docs/             API.md、ER 图、测试报告
  docker-compose.yml
```

### 13.2 开发顺序
1. 数据库 DDL。
2. 接口契约 API.md 或 OpenAPI（**含接口访问级别标注**）。
3. 后端骨架 + 登录。
4. 核心 CRUD。
5. **P0 五种题型题目模型 + 判分 + 自评。**
6. 核心闭环。
7. 管理端。
8. Android 学生端（Java + XML）。
9. 打包与真机调试。

### 13.3 提示词硬性规则

**后端：**
项目使用 JDK 21、Spring Boot 3.5.3、MyBatis-Plus spring-boot3-starter 3.5.7、MySQL 8、Spring Security 6、JWT（jjwt 0.12.6）。
禁止使用 javax.*，必须使用 jakarta.*。
禁止使用 WebSecurityConfigurerAdapter，使用 SecurityFilterChain。
所有代码必须兼容 Java 21。
统一响应 {code,message,data,traceId}，后端逐接口校验权限（含匿名白名单）。

**数据库：**
使用 MySQL 8 DDL，snake_case，包含主键、索引、唯一约束、外键、created_at、updated_at、is_deleted。
**题目答案表的答案内容用 JSON 字段，禁止为每种题型加列做成大宽表。**

**题目模型：**
题目表统一存储全题型，用 type 字段区分（全部枚举预留，界面按分期开放）。
组合题用 parent_id 关联子题（P1）。
客观题答案存题目选项表 is_answer；其余题型答案存题目答案表 JSON 字段。
判分服务按题型分派：客观题自动判分，主观题返回参考答案 + 自评。

**Android 学生端（Java）：**
使用 Java + XML 布局 + View 体系，架构 MVVM（ViewModel + LiveData）；网络层 Retrofit + OkHttp + Gson；图片加载 Glide；列表 RecyclerView；底部导航 BottomNavigationView；路由 Navigation Component。
**禁止使用 Jetpack Compose——Compose 仅支持 Kotlin，本项目为 Java 项目，界面一律用 XML 布局 + View 体系。**
禁止在主线程做网络或文件 IO，一律使用 ExecutorService + Handler（RxJava 可选）。
使用 ViewBinding 替代 findViewById。
底部导航 4 个：首页 / 题库 / 课程库 / 我的（BottomNavigationView）；上传资料为首页右下角 FloatingActionButton +「我的」入口。
触控目标不小于 44dp，单列布局，无横向滚动。
游客锁定下载、上传、刷题。
主观题页面需支持文本作答、参考答案展示、自评按钮。
**PDF 预览用图片分页展示（Glide 加载）；下载后的整本文件通过 Intent 调系统阅读器打开，禁止把整本 PDF 塞进应用内预览。**
**App 上传仅允许图片格式（拍照/相册，可多选，Bitmap 压缩后上传）；服务端独立校验类型白名单与大小，非图片返回 415；文档文件走管理端 Web。**
**打包与签名由 Android Studio 人工完成，模型不负责签名配置。**

**审核状态机：**
实现统一审核状态机：DRAFT → PENDING → APPROVED / REJECTED → OFFLINE → APPEALING → APPROVED / OFFLINE；REJECTED 可回 DRAFT 重新提交。
资料和题目共用，审核员不可审核自己上传的内容。
Service 层用事务。

### 13.4 最容易翻车的地方
生成过时依赖：锁定版本号。
前后端字段对不上：先定 API.md（含访问级别标注）。
权限只写前端：后端必须逐接口校验。
全题型判分逻辑分散：统一判分服务，按题型分派。
**答案表做成大宽表：必须用 JSON 字段承载各题型答案。**
组合题父子结构：先设计好 parent_id 和子题排序（P1）。
主观题自评结果统计：明确自评如何折算正确率。
**PDF 预览：后端转图片分页，禁止把整本 PDF 交给系统阅读器做在线预览（它会打开整本）。**
**游客接口 401：先定匿名白名单再联调。**
**App 文件选择：原生 Android 技术上可选任意文件，但 P0 仍只开放图片（控制审核成本与存储）；服务端必须独立校验类型白名单与大小，不能只信前端。**
打包签名：模型做不了，必须在本地 Android Studio 生成签名 APK。
使用解释不了代码：保留 Git 提交记录，每个模块自己跑通再提交。
