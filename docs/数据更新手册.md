# 数据更新手册（题库导入 / 审核 / 向量重建）

> 项目：大学生多考试备考知识库与题库系统
> 版本：2026-11-10（第 10 周新增）
> 适用：题目与资料的导入、审核上架、AI 语料切片与向量索引的重建
> **本文不含任何明文口令**；连库统一走 `--defaults-file=config/mysql-client.local.cnf`

---

## 0 数据链路总览（先建立心智模型）

```
上传/录入（题目、资料、知识点）
        ↓
   [审核：audit_status]
        ↓ 只有 APPROVED 才进语料
   ai_chunk（切片表，status = ACTIVE / INVALID）
        ↓  POST /api/admin/ai/vector/sync（或 reindex 顺带推送）
   FastAPI /v1/embed（bge-small-zh-v1.5，512 维）
        ↓
   Qdrant collection `exam_chunks`（本地嵌入式，持久化 ./data/）
        ↓
   /api/ai/ask 检索：Wiki 热层 → RAG 冷层 → LLM 生成 → 抽取式兜底
```

**两条铁律**：
1. **`audit_status != APPROVED` 的内容不进语料**。改题库后必须走审核，否则 AI 检索不到。
2. **对象题答案不入索引**（防泄题），只取主观题参考答案（`AiAdminController` `/reindex` 的接口说明原文）。

## 1 题库导入

### 1.1 首次初始化（空库）

```bash
# 按序执行，顺序不能乱
mysql --defaults-file=config/mysql-client.local.cnf < sql/schema.sql          # 建表（32 KB）
mysql --defaults-file=config/mysql-client.local.cnf < sql/data.sql            # 基础数据 + 种子账号（12 KB）
mysql --defaults-file=config/mysql-client.local.cnf < sql/migration-p0b.sql
mysql --defaults-file=config/mysql-client.local.cnf < sql/migration-p1.sql
mysql --defaults-file=config/mysql-client.local.cnf < sql/migration-p1b.sql

# 校验
mysql --defaults-file=config/mysql-client.local.cnf -N -B -e \
  "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='exam_prep';"
# 期望 56
```

> **`sql/data.sql` 含种子账号**（admin/auditor/学生演示号）。第 10 周已把历史明文口令从该文件清零，口令哈希入库、明文只在 `config/secrets.local.yml`。**不要把口令改回明文写进 data.sql。**

### 1.2 增量迁移（结构变更）

项目**无 Flyway/Liquibase、无 schema 版本号**（`information_schema` 无版本表）。26 个 `sql/*.sql` 靠人工按顺序执行。

**纪律（缺一不可）**：
1. 执行前先备份：`backup.bat`（`mysqldump --single-transaction`，实测 3 秒 / 约 24 MB）。
2. **只允许向前兼容迁移**，禁止 `DROP COLUMN` / `DROP TABLE` / 类型收窄。
3. 执行后**必须留痕**：在 `项目规划/第N周/evidence/` 写一条记录（脚本名 + 执行时间 + 执行人 + 影响表 + 影响行数）。
4. 不存在 down-migration；要退结构只能「恢复备份」，不能「反向改表」。

### 1.3 大规模题库导入（国考/操作系统等）

现成数据文件：

| 文件 | 内容 |
|---|---|
| `sql/data-guokao.sql`（5.39 MB） | 国考题目主数据 |
| `sql/migration-guokao-clean.sql`（1.30 MB） | 清洗后的迁移数据 |
| `sql/data-ai-seed.sql`（24 KB） | AI 语料种子 |
| `sql/migration-info-computing-subjects.sql` | 信息计算类科目 |
| `sql/migration-courseware.sql` | 课件 |
| `sql/migration-agent*.sql` | Agent 相关（位置/记忆/checkpoint） |
| `sql/migration-srs.sql` / `migration-wiki.sql` / `migration-study-plan.sql` / `migration-rsi.sql` / `migration-postgrad-category.sql` / `migration-perf.sql` / `migration-register.sql` | 各功能域 |

```bash
# 导入（示例：国考）
mysql --defaults-file=config/mysql-client.local.cnf exam_prep < sql/data-guokao.sql
# 导入后核对
mysql --defaults-file=config/mysql-client.local.cnf -N -B -e \
  "SELECT COUNT(*) FROM exam_prep.question; SELECT audit_status, COUNT(*) FROM exam_prep.question GROUP BY audit_status;"
```

**当前基线（2026-11-10 实测）**：
- `question` 合计 **3,085**；`audit_status='APPROVED' AND is_deleted=0` → **2,500**；`PENDING` → **583**
- `ai_chunk` 合计 **13,307**；`ACTIVE` **12,648** / `INVALID` **659**
- 用户 **14**

### 1.4 题目字段要点（建表约束，导入前必看）

`question` 表关键列（`information_schema` 实测）：`id, subject_id, type, stem, material, difficulty, source, tags, analysis, score, parent_id, sort, audit_status, created_by, created_at, updated_at, is_deleted`

- **软删**：`is_deleted`（0/1）。删题要置 1，不要 `DELETE`——`ai_chunk` 靠它判断来源是否下架。
- **审核态**：`audit_status`（`APPROVED` / `PENDING` / …）。**只有 APPROVED 进语料**。
- **组合大题**：`parent_id` 关联材料题与子题，`sort` 控制子题顺序。导入时若破坏 `parent_id` 关系，前端「组合大题」会散架。
- **图片题**：`stem` 里含图片引用时，注意 `sql/fix-quarantine-image-questions.sql` 是历史修复脚本（图片隔离问题），不要盲目重跑。

## 2 审核上架（决定能否进 AI 语料）

### 2.1 两条路径

| 路径 | 操作 |
|---|---|
| **管理端网页** | `http://<host>:8080/api/admin/index.html` → 「题目审核」→ 按题型/关键词筛选 → 通过 / 驳回（填原因）/ 下架 |
| **接口** | 需 `ROLE:AUDITOR` / `ROLE:ADMIN`，登录后带 token |

**规则**：审核员**不能审核自己上传的内容**（系统自动拦截，见 `docs/用户手册.md:111`）。

### 2.2 审核通过后必须重建索引（最容易漏的一步）

**审核通过 ≠ AI 能答到。** 必须显式触发语料重建：

```bash
# 全量重建 AI 索引（幂等，content_hash 未变则 skip）
curl -X POST http://127.0.0.1:8080/api/admin/ai/reindex \
  -H "Authorization: Bearer <AUDITOR或ADMIN的token>"
# 响应含 chunk（新增/更新数）、skipped（跳过的数）
```

`/reindex` 的正式行为（引自接口文档）：
- 从**已审核（APPROVED）**的题目 / 资料 / 知识点重新抽取语料写入 `ai_chunk`；
- **幂等**：`content_hash` 未变则跳过；
- 来源下架的块置 `status=INVALID`，**不物理删除**（保留可追溯性）；
- 若 FastAPI 通道开启，会**顺带异步推送向量**（推送失败不影响本次返回）。

## 3 向量重建（三条路径，按场景选）

### 3.1 接口一览（全部需 `ROLE:AUDITOR` / `ROLE:ADMIN`）

| 接口 | 方法 | 用途 | 关键说明 |
|---|---|---|---|
| `/api/admin/ai/reindex` | POST | 全量重建 `ai_chunk` 语料 | 幂等；顺带异步推向量 |
| `/api/admin/ai/vector/sync?limit=200` | POST | 推送 `vector_synced <> 1` 的块 | `limit` 最大 500；幂等（Python 侧按 `content_hash` 去重）；FastAPI 不可用返回 `pushed=false` 不抛异常 |
| `/api/admin/ai/vector/reconcile` | GET | **对账** MySQL ↔ Qdrant | 核心断言：MySQL 已向量化数 == Qdrant points 数；不一致时自动补推 |
| `/api/admin/ai/vector/reconcile` | POST | 对账并修复 | 同上，带修复动作 |
| `/api/admin/ai/vector/full-sync` | POST | **强制全量重推** | ⚠️ 会先把 `vector_synced` **重置为 0** 再推 |
| `/api/admin/wiki/vector/rebuild` | POST | 重建 **Wiki** 向量索引 | 与 `ai_chunk` 是两套索引，分开重建 |

### 3.2 `vector_synced` 状态位语义（对账必读）

| 值 | 常量 | 含义 |
|---:|---|---|
| **0** | `VECTOR_PENDING` | 待同步（推送失败也只留 0，等下次对账重试） |
| **1** | `VECTOR_SYNCED` | 已同步 |
| **2** | `VECTOR_FAILED` | 写入异常待重试（拒收 / 校准不通过） |
| **3** | `VECTOR_PURGED` | 向量点已从 Qdrant 移除（块已 `INVALID` 且孤儿向量清理完成），**不会再被推送** |

**当前基线核对（2026-11-10 实测，完全自洽）**：

| status | vector_synced | 行数 |
|---|---|---:|
| ACTIVE | 1 | **12,648** |
| INVALID | 0 | 102 |
| INVALID | 3 | 557 |
| **合计** | | **13,307** |

→ `GET /api/ai/capability` 返回 `chunkCount: 12648`，**恰好等于 ACTIVE 且 synced=1 的行数**，说明「只把 ACTIVE 块进索引」的设计生效，当前**无不一致**。

### 3.3 推荐操作序列（题库批量更新后）

```bash
# ① 重建语料（幂等）
curl -X POST http://127.0.0.1:8080/api/admin/ai/reindex -H "Authorization: Bearer <token>"

# ② 对账（看差了多少）
curl -s http://127.0.0.1:8080/api/admin/ai/vector/reconcile -H "Authorization: Bearer <token>"
#   关注：MySQL 已向量化数 vs Qdrant points 数

# ③ 补推（分批，避免一次推爆）
curl -X POST "http://127.0.0.1:8080/api/admin/ai/vector/sync?limit=200" -H "Authorization: Bearer <token>"
#   批次不够就多调几次，直到 reconcile 显示一致

# ④ 再对账确认一致
curl -s http://127.0.0.1:8080/api/admin/ai/vector/reconcile -H "Authorization: Bearer <token>"
```

### 3.4 ⚠️ 何时必须用 `full-sync`（而不是 `sync`）

`/vector/sync` 只推 `vector_synced <> 1` 的块。因此**当状态位「假绿」时它会漏推**：

- 换过 **embedding 模型**（`bge-small-zh-v1.5` → 其他）→ 旧向量与新模型**不可混用**，必须全量重建；
- Qdrant 数据目录被清空/损坏，但 MySQL 里 `vector_synced` 还都是 1 → 只有 `full-sync` 能修；
- 同 collection 混入其他来源的向量。

`/vector/reconcile` 在 `model_id` 不匹配时会明确提示需全量重建（接口文档原文：「**绝不允许同一 collection 混用不同模型的向量**」）。

### 3.5 孤儿向量清理

来源下架的块会被置 `status=INVALID`，其向量点需从 Qdrant 移除。当前 659 条 INVALID 中 **557 条已 `PURGED`(3)**、**102 条仍 `PENDING`(0)** → 说明清理是**异步渐进**的，不是一次到位。差异属正常，跑一次 `reconcile` 即可推进。

## 5 语料快照与一致性校验（发布前必做）

### 5.1 语料聚合哈希（可复现）

```bash
mysql --defaults-file=config/mysql-client.local.cnf -N -B -e \
  "SELECT id, content_hash FROM exam_prep.ai_chunk ORDER BY id;" \
  | tr '\t' ':' | sha256sum
```
**当前基线**：`bec213616e9717167ffdb8360b61e2871b8d9b958c8c3aff58b4a028e13de9db`

**算法**：按 `id` 升序，每行取 `<id>:<content_hash>`，`\n` 连接后对整段字节做 SHA256。
**盲区（必须知道）**：只覆盖 `id + content_hash`，**不覆盖 `content` 原文、也不覆盖向量库**。能检出「切片增删」与「文本变化」，检不出 `title`/`status`/`vector_synced` 字段改动。向量一致性靠 §3 的 `reconcile` 单独核对。

### 5.2 发布前 5 项校验

```bash
# ① 题目总量与审核态
mysql --defaults-file=config/mysql-client.local.cnf -N -B -e \
  "SELECT COUNT(*) total, SUM(audit_status='APPROVED' AND is_deleted=0) approved FROM exam_prep.question;"
#   基线：total=3085, approved=2500

# ② 切片状态自洽
mysql --defaults-file=config/mysql-client.local.cnf -N -B -e \
  "SELECT status, vector_synced, COUNT(*) FROM exam_prep.ai_chunk GROUP BY status, vector_synced;"
#   基线：ACTIVE/1=12648, INVALID/0=102, INVALID/3=557

# ③ 向量库对账
curl -s http://127.0.0.1:8080/api/admin/ai/vector/reconcile -H "Authorization: Bearer <token>"

# ④ 能力端点抽查
curl -s http://127.0.0.1:8080/api/ai/capability -H "Authorization: Bearer <token>"
#   关注 chunkCount 是否 == ACTIVE 且 synced=1 的行数

# ⑤ 实测一问
curl -s -X POST http://127.0.0.1:8080/api/ai/ask \
  -H "Authorization: Bearer <token>" -H 'Content-Type: application/json' \
  -d '{"question":"进程和线程的区别"}'
#   期望 200，sources 非空，有 traceId
```

## 6 回滚与止损

| 场景 | 处置 |
|---|---|
| 导入错数据（题目） | 置 `is_deleted=1`（**不要 DELETE**）→ `/reindex` 使对应 `ai_chunk` 置 `INVALID` → `reconcile` 清孤儿向量 |
| 迁移脚本改坏表结构 | 恢复备份（`backup.bat` 的产物，实测恢复 46 秒）；**不要写反向 DDL** |
| 向量全乱（换模型/清空 Qdrant） | `/api/admin/ai/vector/full-sync`（会重置 `vector_synced=0` 后全推） |
| 重建期间 AI 报错 | 属正常：推送是异步 + 状态位，失败只留 `vector_synced=0`，**不影响任何业务接口** |
| FastAPI 熔断中 | 等熔断窗口（60 s）过后再调 `sync`，会自动补齐，**无需全量 reindex** |

**止损优先级**：先保「刷题/资料/管理端」（与 AI 索引无关），AI 语料问题可以慢慢修。
