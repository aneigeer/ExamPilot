> 作者：软件工程师｜日期：2026-10-06

## D.0 前置：启动 Docker Desktop ★必做

**当前状态：Docker CLI 已安装（29.7.2），但守护进程未运行。**
不启动这一步，后面所有 compose 命令都会失败。

```powershell
# ① 启动 Docker Desktop
Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"

# ② 等引擎就绪（最多 2 分钟），验证
docker info
# 期望输出包含：Server Version: 29.x、OSType: linux
```

## D.2 启动 MinIO（对象存储）

```powershell
# ① 用 docker-compose 一起起（推荐）
docker compose -p examprep -f docker-compose.ai.yml up -d

# ② 或单独起
docker run -d -p 9000:9000 -p 9001:9001 --name examprep-minio `
  -e MINIO_ROOT_USER=minioadmin -e MINIO_ROOT_PASSWORD=minioadmin `
  minio/minio:RELEASE.2024-10-13T13-34-11Z server /data --console-address ":9001"

# ③ 验证
curl.exe http://localhost:9000/minio/health/live    # 期望：OK
```

**桶由 Java 侧启动时自动创建**（`auto-create-bucket: true`），无需手动 `mc mb`。

## D.3 Python 环境与 AI 服务

```powershell
cd D:\大学生多考试备考知识库与题库系统

# ① 建虚拟环境
python -m venv .venv-ai
.\.venv-ai\Scripts\Activate.ps1

# ② 装核心依赖（约 250MB）
pip install -r ai-service\requirements.txt

# ③ 装 Embedding 依赖（约 100MB，不含 PyTorch）
pip install onnxruntime==1.20.1
pip install tokenizers==0.20.3
pip install huggingface-hub==0.26.2

# ④ OCR 依赖（可选，约 500MB-1GB，不装不影响系统启动）
pip install paddlepaddle==3.3.0 -i https://www.paddlepaddle.org.cn/packages/stable/cpu/
pip install paddleocr>=3.0.0
```

> **为什么不用 PyTorch**：`sentence-transformers` 会拖入 PyTorch（800MB+），
> 而 ONNX Runtime 只需几十 MB。这是本项目最重要的依赖决策之一。

## D.4 Embedding 模型下载（约 28MB）

模型**懒加载**，首次调用 `/v1/search` 时自动下载并加载。

```powershell
# 预热（强烈建议，避免使用第一次查询超时）
cd ai-service
python -m app.tools.warmup_embedding
# 期望输出：model=bge-small-zh-v1.5 dim=512 load_ms=xxx warmed=ok
```

缓存位置：`%USERPROFILE%\.cache\huggingface\hub`

## D.7 启动后端

```powershell

  --app.storage.access-key=minioadmin `
  --app.storage.secret-key=minioadmin
```

> ⚠️ **低内存机器的构建配方**（本项目实测有效）：
> ```powershell
> $env:MAVEN_OPTS="-Xmx512m -XX:MaxMetaspaceSize=256m"
> mvn -B -DskipTests package                                    # 不要加 clean
> mvn -B test -DargLine="-Xmx384m" -Dsurefire.reuseForks=true -DforkCount=1
> ```
> **构建前必须先杀掉占用 8080 的 java 进程**，否则 jar 被占用必然 BUILD FAILURE。

## 体积与风险汇总

| 项 | 体积 | 必需？ | 不做的后果 |
|---|---|---|---|
| Docker Desktop 启动 | — | **必需** | Qdrant/MinIO 起不来 → 自动降级，**系统仍可用** |
| Qdrant | ~120 MB | 必需（向量库） | 向量通道降级到 ngram |
| MinIO | ~150 MB | 必需（对象存储） | 上传自动落本地磁盘 |
| Python 核心依赖 | ~250 MB | **必需** | FastAPI 起不来 → 同上 |
| onnxruntime + 模型 | ~90 MB | 必需（embedding） | 向量通道降级 |
| **PaddleOCR** | **~500MB-1GB** | **可选** | OCR 降级为人工录入，**其他全好** |
| 大模型 API Key | 0 | 可选 | 抽取式兜底，**接口仍 200** |

> **最坏情况：什么都不装。**
> Docker 停、FastAPI 不起、MinIO 不起、OCR 不装 →
> **系统完整退化为纯 Java 单体 AI 形态，功能不减，使用可继续。**

## 启动顺序速查（使用当天）

```
1. Docker Desktop        → docker info 确认
2. docker compose up -d   → Qdrant + MinIO
3. uvicorn app.main:app  → FastAPI :8000
4. python -m app.tools.warmup_embedding   ★ 必做，否则首次查询超时
5. java -jar ... :8080    → 后端
6. curl /api/ai/capability 确认 vectorIndexReady=true
7. 开始使用
```
